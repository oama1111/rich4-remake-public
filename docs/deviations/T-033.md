## D-BOARD-1（已消除）市價／掛牌常數改成 core 的真出口

**旧情况**：`packages/core/src/index.ts` 漏了 `places/notice-board.ts`，导致
`LISTING` / `Listing` / 四条市價公式 / `BOARD_SLOTS` / `isColumnFull` /
`ESTATE_*` / `decodeEstate` 在 client 侧一个都 import 不到，本模块曾**在本地

**现状（2026-09-15，中央补了 `export * from './places/notice-board.ts'`）**：
本模块已全部换成真 import，本地镜像**已删除**：

| 用到的 | 来源 |
|---|---|
| `LISTING` / `Listing` / `BOARD_SLOTS` / `isColumnFull` | `@rich4/core` |

单测里有一条专门的交叉核对（`marketPriceOf(...estate...) === estateListPrice(...)`），

（上限 = 市價 × 10），不是规则。

## D-BOARD-2（有意偏离）出价输入用 `dialog.ts` 的 `AmountPage`，不是原版的数字键盘窗

原版这一步是**另开一扇窗** `fcn_00453544`（VA 0x00453544）：

```asm
0045356c  push 0x15 / push panel_mkf / call read_mkf    ; Panel.mkf #21 = 数字键盘
00453586  push 0x16 / push panel_mkf / call read_mkf    ; Panel.mkf #22
004535ae  [esp] = 0x100 / 0x90 / 0x180 / 0x150          ; 开窗矩形
004535f8  mov eax, [esp+0x24] / mov [0x48ca98], eax     ; ★ 参数是**上限**
004531f6  cmp eax, edx / jle                            ; 越界夹回上限
```

即：**框的美术是 `Panel.mkf` #21/#22 的数字键盘**，参数只有一个「上限」，
初值是 0。

本模块按卡片要求复用 `dialog.ts` 的 `AmountPage`（也是股市/银行那两屏的做法），
所以**只有这一处美术与操作方式不同**：

| | 原版 | 本模块 |
|---|---|---|
| 框 | `Panel.mkf` #21/#22 数字键盘 | `dialog.ts` 的金框 + 五颗钮（−/+/最大/確定/取消） |
| 初值 | 0（全靠玩家按数字） | **市價**（股票那一类是持有股數）—— 卡片原 stub 的说法 |
| 上限 | 参数（见下） | 同左，逐条照抄 |

上限逐条（**这是原版的**）：

| 类型 | 上限 | @source |
|---|---|---|
| 股票 | 持有股數 | 0x00425f0d `push [holdings]` |
| 地產 | `(地價 + 等級 × 房價) × 物價 × 10` | 0x0042660c `shl 2 / add / add` |
| 道具 | `標價 × 100 × 物價 × 10` | 0x00426b0f |
| 卡片 | `標價 × 100 × 物價 × 10` | 0x00426f52 |

★ 股票那一类填的是**股數**而不是價錢：原版提示串是「請輸入欲賣出的張數」
（串 0x463ea0），賣價 `= round(股數 × 現價)`（VA 0x00425f1e），action 里
`price` 与 `amount` 两个字段就是这么来的。本模块照做。

## D-BOARD-5（有意偏离，仅剩「近似色」）按下高亮按原版做回了，但颜色是近似

原版在两处给鼠标反馈，本模块**都做了**，只是颜色用半透明黑近似：

| 原版在哪 | 怎么画 | @source | 本模块 |
|---|---|---|---|
| 被点的挂牌格 / SALE / EXIT | `fcn_004552e7(…, −0xc)` | 0x00427e0d / 0x00427f9e / 0x004280ee | `shade()` 叠 `rgba(0,0,0,12/32)` |
| 详情框那两颗钮（按住时压暗） | 同上 | 0x00427ac4 | 同左 |
| 卡片／道具选物窗被按下的格子 | 同上 | 0x00426e72 / 0x00426a4e | 同左 |
| SALE 弹出选单悬停到的那一格 | 同上 | 0x00427cfd | 同左 |
| 股票／地產选物窗悬停到的那一行 | 同上 | 0x00425b19 / 0x004261cb | 同左 |

**颜色是怎么定的**：`−0xc` 是把颜色换成那张 **32 级淡出表**（`0x485d68`）往回
12 张的那一档 —— 一张表 256 色 × 2 字节 = 512 字节，所以 `−0xc` = 12/32 =
**压暗 37.5%**（商店屏的 `−16` 正好是「减半」，与此互证）。本模块取
`PRESS_ALPHA = 12/32`（`board-screen.ts` 里带同一条出处）。
**偏差只在**：原版换的是**调色板索引**（对每种颜色各按 5 位分量算），
本模块是从 RGB 上叠一层半透明黑 —— 观感一致，逐像素不完全等同。

## D-BOARD-6（引擎必需，非美术偏离）换人自动收屏

原版这一屏是**模态窗口**（`Wait_0402_Message` 消息循环，VA 0x00428825），
只有 `EXIT` / 右键 / 面板窗口过程退出才关；玩家不可能在它开着的时候把回合交出去。

本引擎的整屏是**登记表里的一层覆盖**，`熱鍵`/工具列之外的路（例如「前進」鍵）
仍会打到棋盘上。所以 `tick()` 里加了一条：**当前玩家一变就收屏**。
这不是新增玩法，只是补上原版模态循环替我们挡住的那件事。

## D-BOARD-7（有意偏离）弹出选单优先吃掉点击；点选单以外先收单再按底下一层

原版 `[0x48c2ca]` 那个字节在**按下**时被无条件改写（VA 0x00427ea1 的
SALE → EXIT → 挂牌格 三路判定根本不看它现在是什么），所以「选单开着时点一格」
会既开详情框、又把选单留在屏幕上。

本模块的做法：选单开着时，**选单优先吃掉点击**（`hitSalePopup` 先判），
点不在那四格上才把选单收起来、再照同样的顺序（SALE → EXIT → 挂牌格）判定。

⚠️ 这一条不只是「好看一点」：选单那 144×96 是盖在**第 0／1 行第 5、6 格**上的，
照原版那样不看模式直接判，只要玩家在那四格里有挂牌，**选单就一格都点不动**
（按下记账改成挂牌格、抬手就变成开详情框）。所以这里是有意偏离，请中央复核。

## D-BOARD-8（已解决）时序按契约实现：`down` 记账、`up` 成立

**过程**：`main.ts` 原先把 `down` 挂在 `canvas click`、`up` 挂在 `window mouseup`，
而浏览器的顺序是 `mousedown → mouseup → click`（且 `mousedown` 不派给登记的整屏），
于是 `up` 永远先到 —— 「按下记账、抬手成立」这条时序是反的（真浏览器里点不出来：
卡片/道具选物窗选不中、详情框三颗钮无反应、EXIT 关不掉屏）。

**现状（2026-09-15，中央已按正解修掉 `main.ts`）**：

| 浏览器事件 | 打到哪 |
|---|---|
| `canvas mousedown`（button 0） | `screen.down` = `WM_LBUTTONDOWN`(0x201) |
| `window mouseup` | `screen.up` = `WM_LBUTTONUP`(0x202) |
| `canvas click` | **只吞掉，不派任何东西** |

本屏因此就是原版那两步：`down()` **只记账 + 画压下高亮**（`press` = 原版
`[0x48c2ca]` 那个字节），`up()` **只认按下记下的那一个**、完全不看抬手的坐标
（原版 `0x202` 就是这么写的）。**本模块不再有任何因时序而生的偏离。**
