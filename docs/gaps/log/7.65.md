#### (2) ★★ 由此逮到两个**真偏差**（都会改变回合数）

**偏差 A：tick 的时机记错了。** `0x418ebd` 在 `0x418f95` 就 `inc` 了游标
（`00418f95 inc esi / mov [0x49910c], esi`），`0x419039` 才用 `[0x49910c]`
⇒ 递减的是**即将行动的那位**，不是刚走完的这位。旧注释写"参数是当前玩家，就在回合边界——与此处一致"
是**读早了**。复刻原来在 `endTurn` 里递减**旧**玩家 ⇒ 每个人的计数都会晚一位玩家生效。

**偏差 B：整个「走回棋盘」的回合没实现。** 复刻原来把释放折叠成"计数直接清 0"，
于是刑满者**下一回合就能正常行动** ⇒ 比原版**少关一回合**。
而状态栏显示的 `(raw & 0x7f) + 1`（`0x40ca60`）本来就是"还会丢几个回合"的口径
（`days=3` 显示 4 天）—— 也就是说复刻自己的显示与行为当时是矛盾的。

#### (3) 修法

| 改动 | 位置 |
|---|---|
| `endTurn` 改成**先推进游标**（`nextAlivePlayer`）→ 惡人段 / `advanceGameDay` → **再**给 `next` 递减（对应原版 `0x418f95` → `0x41902e` → `0x419039`）| `state/reduce.ts` `case 'endTurn'` |
| 释放（`released`，**消失除外**）时置 `WHO_PLAYS_RETURN_TO_BOARD`（`+0x15 \|= 0x10`，即 `0x40d6be` 那一句）| 同上 |
| `startTurn` **在 `evaluateTurnStart` 之前**判该标记：命中 ⇒ 整回合跳过（`phase: 'turnEnd'`）、清标记、并把四个计数一次清光（= 走路例程 `0x40c3cf` 的折叠）| `state/reduce.ts` `case 'startTurn'` |
| `WHO_PLAYS_RETURN_TO_BOARD = 0x10` / `WHO_PLAYS_RELOCATED = 0x20` 从"语义待确认"改成有 `@source` 的具名常量 | `state/types.ts` |

**逐步核对**（3 天牢，通道 2 原版 vs 复刻，均为 4 个回合）：
`T1:3→2 → T2:2→1 → T3:1→0x80 → T4:0x80→释放（这一回合就是走回棋盘）→ T5 自由`。
`state/release-chain.test.ts` 里有一条**逐回合**数组断言把这个账钉住（`[1,1,1,1,0]`）。

**副作用（都被测试逼出来、已逐条订正）**：`endTurn` 的递减对象变了，6 个测试文件里
8 条断言写的是"递减旧玩家" —— 它们**复述的是旧实现**，不是原版真值，故全部改成
"递减新当前玩家"。`full-game.test.ts`（种子 2024 的整局）**不写死回合数**，
换实现后仍绿 —— 这条设计救了本轮。

#### (4) `0x448a7e` 也读通了（第 83 条留的未决）

它是「**走过去时中途落脚**的资格判定」：只对步行（`traffic_method & 0x83 == 3`）
且不在梦游/住宿的人有效；落在**别人已开发**的住宅地/設施上时置回合记录
`0x498ea0+idx*0x34` 的 `+0x02 = 3`、`+0x03 = 0`、`[0x46cafb] = 1`；其余情况什么都不做
（`0x448b4c test ebx,ebx / je 返回` 的 `ebx` 恒为 0 ⇒ 必返回）。

「走回棋盘」的**画面**仍未接（规则侧已接），登记为新的一项（见 §7.3 第 17 项）。
