### 7.62 ★ 第 81 条（本轮）：**结掉自己挂的「两段式释放」未决** + 物件起手移动的差分

#### (1) ★★ `[0x48baf4]` 查清了：清账条件 = **`trunc(距离 / 步长) >= 2`**

第 79 条登记「原版清账有条件、但条件里的浮点量未决」。本轮把它读通：

```asm
40c249  fild [平方和] / call 0x4582bc          ; ★ 0x4582bc = sqrt（ftst + 0x459c51）
40c252  fstp [esp+0xc]                         ; 距离（像素）
40c26d  test byte [player+0x15], 0x30 / je ... ; 被阻碍/特殊走法 → ×0.125（= /8）
40c290  al = byte [0x4749d8 + (traffic & 3)]   ; ★ 步长表 = **8 / 12 / 16 / 8**
40c29e  fdivr [esp+0xc]                        ; = 距离 / 步长 = **本趟总步数**
40c308  call 0x457dbc                          ; ★ frndint + CW 舍入位设 0x1f = **向零截断**
40c30d  fistp [0x4749dc] / [0x48baf4] = 该值 >> 1
```

⇒ 清账条件 `[0x48baf4] > 0` ⟺ **`trunc(距离/步长) ≥ 2`**。
骰子走一格约 24 px、步行步长 8 ⇒ `3`，**照常清**；只有「距离 < 2×步长」的极短走法
才会跳过（结论：复刻的「折叠成一段」在实践中等价，残留差异只在这个边界上）。
`game-loop.md` 的「释放是两段式」一节、`known-deviations.md`、
`rules/blocking.ts` 的注释都已按此更新。
