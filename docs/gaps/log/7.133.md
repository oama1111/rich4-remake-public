#### (1) ★★ 本轮的真发现：**手牌有洞时，原版 AI 漏牌**（新登记 `D-LEGACY-4`）

`0x00441262(player)` 的返回值是**非零槽的个数**，不是「最后一个有牌的槽下标」：

```asm
00441268  xor ecx,ecx                         ; ecx = 槽下标 0..14
0044126a  xor ebx,ebx                         ; ebx = 计数
00441282  cmp byte [ecx + eax + 0x499120], 0  ; eax = player*15（手牌表）
0044128a  je  0x44126e                        ; ★ 空槽 ⇒ **不计数**，但下标照走
0044128c  inc ebx
```

而 `0x41f901` 把返回值**当成下标上界**：

```asm
0041f9b7  call 0x441262(ebp)     ; eax = 非零槽个数
0041f9bf  cmp  edi, eax
0041f9c1  jge  0x41fa06          ; for (edi = 0; edi < count; edi++)
0041f9d4  mov  dl, byte [edx + 0x499120]   ; c = hand[edi] ← ★ 按下标取，**不跳过空槽**
```

⇒ **手牌中间有洞时，下标 ≥ count 的牌对这段 AI 就是隐形的。** 差分实证（A 级）：

| 手牌 | `0x441262` 返回 | 原版实际看到 | 结果 |
|---|---|---|---|
| `[7号]` | 1 | 槽 0 = 7号 | 抢到 7 ✔ |
| `[空, 7号]` | **1** | 只查槽 0 | ★ **抢不到 7**（返回 0） |
| `[4号, 空, 7号]` | **2** | 只查槽 0/1 | ★ 只看到 **4号**（更贵的 7 号被漏） |

**洞是真实存在的**：`giveCard`（`0x4412e4`）写入**第一个空槽**（`tests/test_card_give.py`
已实证：定长 15 槽、中间有洞时**进洞**），而用牌/弃牌会在中间留下洞 ⇒ 一局里完全构造得出来。

**复刻侧**：`ai/card-policy.ts` 的 `qiangduo` 遍历 `players[hated].cards`
（**紧凑数组、没有"洞"的概念**）⇒ **复刻不会漏牌**，两边这一格**行为不同**。
⇒ 已登记 **`docs/known-deviations.md` 的 `D-LEGACY-4`**（与 D-LEGACY-1/2/3 同族：
原版有潜伏缺陷、复刻收敛），并写明**残留**：
本偏离只实测了搶奪卡这一条链，同类「count 当上界」的写法在这一族里**可能还有**
（`0x41facc`／`0x41f400` 的手牌扫描），逐条复核前不要假定只有这一处。

★ 注意成因与 D-LEGACY-1/2/3 **不同**：那三条是「读未初始化栈 ⇒ 未定义」，
这条是「**定义明确但有害**」。归入同一族是因为**处置一致**（复刻保留更合理的语义并登记）。

#### (2) 语义（442 B 全程读完）

```
0x41f901():
    best = 0; me = [0x49910c]; hated = 0x40d2d3(me)
    [0x48be60] = 0x40a45c(-1)                  ; 填「可見表」0x48b8c4
    for (i = 0; i < [0x48be60]; i++) {         ; ── 第 1 趟：编「谁在哪一格」
        v = word [0x48b8c4 + i*2]
        if (!(v & 0x8000) || !(v & 0x000f)) continue   ; ★ 两道闸
        for (esi = 1, p = 0; esi < 0x10; esi <<= 1, p++)
            if ((v & esi) && p != me && player[p].alive(+0x15))
                hasPlayer[p] = 1; slotWord[p] = esi | 0x8000
    }
    if (hated != -1 && hasPlayer[hated]) {     ; ── 首选项
        for (i = 0; i < 0x441262(hated); i++) {
            c = hand[hated][i]
            if (cardType[c] < 1)          continue     ; ★ 类型 ≥ 1
            if (cardPrice[c] <= best)     continue     ; ★ 严格 >
            pick = c; best = cardPrice[c]
        }
        if (pick) { [0x48be58] = slotWord[hated]; [0x48be5c] = pick; → 1 }
    }
    for (p = 0; p < [0x499114]; p++) {         ; ── 兜底
        if (!hasPlayer[p]) continue
        for (i = 0; i < 0x441262(p); i++) {
            c = hand[p][i]
            if (cardType[c] != 2)         continue     ; ★ 兜底只要 **== 2**
            if (cardPrice[c] <= best)     continue
            [0x48be58] = slotWord[p]; [0x48be5c] = c; best = 1
        }
    }
    → best
```

⇒ 一句话：**先抢最恨的人（须在画面里）手里最贵的「类型 ≥ 1」的卡；
抢不到就抢画面里任何人手里最贵的「类型 == 2」的卡。**
两个输出：`0x48be58` = 目标（**玩家位 | `0x8000`**）、`0x48be5c` = 卡号。

★ 与复刻 `card-policy.ts` 的 `qiangduo` 对照：`f7 >= 1` / `f7 === 2` /
严格 `>` / `rivals.includes(hated)` / `visibleRivals` —— **逐条一致**，
唯一差别就是 (1) 里那条「洞」的行为。

#### (5) 本轮自己的三处写错（都被原版纠正）

1. **`[E]` 位的含义那一组**：我给了 `hostility = [0,0,0,0]`（⇒ hated = −1 ⇒ **走兜底**），
   却把卡设成**类型 1** ⇒ 兜底要求 `== 2` ⇒ 三条全挂。改成「恨那一位 ⇒ 走首选项支」。

   读完全函数才确认是「非零槽个数」。
