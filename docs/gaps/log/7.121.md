### 7.121 ★★ 第 138 条（本轮）：魔法屋 idx 6/7/8/9 进闸门（差分 22/22）—— ★ 订正一条**字段误认**

#### (1) ★★ 订正：`player + 0x11` 是 `traffic_method`，不是「状态字」

第 131 条（§7.114）把 idx 6/7/8 记成「状态 == 0/1/2」、字段写成「状态字」。
本轮差分一跑就发现**对不上**（`traffic=[0,1,2,3]` + idx7 只收到下标 1，而按旧理解应收到更多），
回头逐条读才确认：

```asm
; @source 0x00431b61（idx 7）—— 与 6/8 同构，只有比对常量不同
00431b48  mov al, byte [eax + 0x496b79]   ; ★ +0x11 = traffic_method（0 步行 / 1 機車 / 2 汽車 / 3 …）
00431b4b  and al, 3
00431b4d  cmp al, N / jne 下一位           ; 6 → N=0、7 → N=1、8 → N=2
```

`state/types.ts` 早就写着 `/** 移动方式 @source player_info +0x11 traffic_method */`
—— 本条把 PRD 侧的措辞对齐到它。（`and al,3` 是因为 `traffic_method` 理论取值 0..7，
而这三支只区分前三档。）
