### 7.51 ★ 第 70 条（本轮）：换一条线再普查 —— **企業控股重排**漏了「公佈欄买股票」

前几轮把「关押」那条线普查完了（§7.50）。本轮换成另一条有明确不变量、
且**可机械枚举**的线：**凡是持股变了，就要重排企业老板**（`0x4294d5`）。

#### (1) 口径：先数原版有几处调用，再数复刻有几处

```bash
grep -n "call    0x4294d5" rich4-spec/gen/db.txt        # 原版 3 处
grep -rn "reownCommercial(" rich4-remake/packages/core/src   # 复刻 5 处
grep -rn "holdings:" rich4-remake/.../reduce.ts         # 持股变更点 6 处
```
原版 3 处：`0x428e14`（买尾）/ `0x428eb7`（卖尾）/ **`0x42571e`（公佈欄买股票）**。
复刻的 5 处里，买/卖/命運/破产都对得上 —— **唯独公佈欄那条没有**。

#### (2) 真缺口：公佈欄买**股票**不重排企业名次

`reduce.ts` 的 `noticeBoardAction` 买分支调 `transferListing` 把股数从卖家转给买家，
然后**直接返回**（只撤掉那一格），**没有** `reownCommercial`。
原版这条路上就有：`0x0042565c` 读槽里的股票号（`word [ebx+0x4967e2]`）+ 当前玩家，
然后 `0x0042571e call 0x4294d5`。

后果：**买走别人挂牌的股票之后，"谁持股最多"变了，企业老闆却还挂在旧人名下**
（`commercialOwners` 是 `special-finance.ts` 判「銀行董事長」的依据 ⇒
连銀行董事長也会跟着错）。

**修法**：买分支按 `item.kind === LISTING.stock` 补一次 `reownCommercial(settled, item.id, 买家)`。

#### (3) 顺手把这条线**全部**核了一遍（结论：其余都对）

| 持股变更点 | 有没有重排 |
|---|---|
| 柜台买入 / 認購（`2825`→`2837`） | ✅ |
| 股票交易挂单结算（`3211`→`3217`） | ✅ |
| 命運卖股（`3633`→`3638` 的 `out.reown`） | ✅ |
| 破产清算变卖（`5284` 先写 holdings，`5282` 循环重排） | ✅ **顺序是对的**（重排读的是改完之后的持股） |
| 公佈欄买股票 | ❌ → **本轮修** |

#### (4) 回归用例（+2）

`places/notice-board-market.test.ts`：买光卖家全部持股 → 老闆换成买家（`owner`/`ranking` 都断言）；
买**非股票**（地產）→ 企业名次一个不动。

#### 诚实边界

- 「原版 3 处调用」是**静态扫描**结论；若某条路径把重排**内联**了就数不到（没发现）。
- 复刻里 `2825`/`3211`/`3633` 这几处的重排语义（尤其是 `updateCommercialOwner`
  的插位/并列规则）本轮**没有**重新差分，只核了"有没有调"。
- 客户端有没有显示 `commercialOwners`（老闆名字）本轮没看。
