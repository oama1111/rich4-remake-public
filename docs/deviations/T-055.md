# T-055　命運 5「生日收卡」的真人那一支：**分帧**问每一位

> 立项理由：`docs/known-deviations.md` 把这一条登记为「真人当寿星也走随机抽」的**近似**
> （T-053 那轮订正过：障碍不是「没有那扇窗」—— 窗已经做出来了，是**结构**问题）。
> 本文件把它接完，并把「为什么必须分帧」写清楚。

## 一、出处（`rich4_fortune.asm:541` 起，`fcn_0044c3b7`）

施加阶段（第二个实参非 0 的那一支）的循环体：

```asm
loc_0044c41f:
  cmp  ebx, [_rich4_num_players] / jge 收尾     ; 逐个座位
  cmp  ebx, [_rich4_current_player] / je 下一位 ; 跳过自己
  cmp  byte [esi + 0x496b7d], 0 / je 下一位      ; 出局 → 跳过（whoPlays == 0）
  push ebx / call _rich4_player_card_num / test eax,eax / je 下一位  ; 空手 → 跳过
  lea  ebp, [edi + 1]                            ; ★ 计数 = edi + 1
  mov  dl, byte [eax + 0x496b7d]                 ; ★ 读的是**寿星**的 whoPlays
  cmp  dl, 1 / jbe loc_0044c48b
  ; ── 寿星是电脑（whoPlays > 1）──
  push ebx / call _rich4_player_drop_random_card  ; 0x441e77 随机抽一张
  push eax / push current / call _rich4_receive_card
  jmp  loc_0044c573
loc_0044c48b:
  jne  loc_0044c575                              ; whoPlays != 1 → 跳过
  ; ── 寿星是**真人** ──
  建字体 / 画对方名字（串 0x4659c9 = 「%s 的卡片」那一类）
  push 0 / push current / push ebx / call fcn_0044192a   ; ★ 模态选牌窗，模式 0
  ; （返回值**不看**）
loc_0044c573:
  mov  edi, ebp                                  ; ★ 无论挑没挑到，计数都 +1
loc_0044c575:
  inc  ebx / jmp loc_0044c41f
; 收尾：`test edi,edi / je 什么都不说`，否则报台词（`fcn_00441d476` + `player_say`）
```

三条关键结论（都影响落码）：

1. **分支看的是寿星的 `whoPlays`，不是被收卡那一位的。**
   寿星是真人 ⇒ 每一位合格的人都弹一次窗；寿星是电脑 ⇒ 每一位都当场随机抽。
2. **选牌窗的返回值被丢掉**（`fcn_0044192a` 的 eax 没接）。所以**右键取消也算「问过一位」**，
   座位照样前进 —— 不能因为取消就停在原地重问。
3. 收尾只用 `edi`（合格人数）判断「要不要报台词」，与真收了几张无关。

模式 **0**（`push 0`）对应 `fcn_0044192a` 的第 3 个实参 ⇒ 只画**卡片欄**
（`fcn_004563f5` 的第二张框那一支被跳过），与搶奪卡的模式 1（卡片欄 + 道具欄）不同。

## 二、本引擎的落点

| 层 | 文件 | 内容 |
|---|---|---|
| 规则 | `core/src/events/fortune-effects.ts` | 寿星**非 AI** 时**一位都不收**：筛出合格座位（不是自己 / 没出局 / 有牌）原样返回 `birthdaySeats`（`amount` = 座位数，对齐 exe 的 `edi`）；寿星是电脑那一支一行未改 |
| 规则 | `core/src/rules/interaction.ts` | 新待决 `{ kind: 'birthdayCard'; seats: readonly number[] }` —— `seats[0]` 就是此刻要挑的那一位 |
| 规则 | `core/src/state/actions.ts` | 新 action `{ type: 'birthdayCard'; seat; cardId }`；`cardId = 0` = 右键取消（跳过这位） |
| 规则 | `core/src/state/reduce.ts` | `drawAndApplyFortune` 收下 `birthdaySeats` → 挂 pending + `phase: 'awaitingDecision'`；`answerBirthdayCard()` 只认队首，落码走 `applyRobCardCard`（= `consume_card` 0x441343 + `receive_card` 0x4412e4，与搶奪卡卡片路径同一个组合），最后一位答完把相位放回 `turnEnd` |
| 表现 | `client/src/steal-picker.ts` | `stealPickerScreen.tick()` 察觉这个待决并**自己开窗**（模式 `gift` ⇒ 只有卡片欄，与 exe 的 `push 0` 一致）；回调派 `birthdayCard`（取消 → `cardId: 0`）|

⚠️ **不能当场随机抽**：随机那一支是**电脑寿星**的行为（`player_drop_random_card`），
真人这一支原版根本不掷骰子 —— 选择权在玩家手上。

## 四、仍未做 / 已知近似

1. **托管的真人 / 无头驱动会「放弃」这一串收卡。** `ai/policy.ts` 的
   `decidePending` 对不认识的 pending 不表态，`awaitingDecision` 那一格于是回
   `declineDecision`（既有设计：「放弃是最后一道保险」）—— 整串座位一次跳完，
   与「一位一位右键取消」等价。**没有**给托管编一套「挑哪张」的 AI：
   原版那扇窗只服务真人，编出来就是发明行为。
2. **`amount`（原版 `edi`）在分帧这一支等于座位数**，不是最终收到几张。
   本引擎没有别处消费这个数（保险理赔只认坐牢/住院/冒貸/穿越馬路那几支），
   但表现层若拿它当「收了几张」显示会偏 —— 事件框目前不显示这个数。
3. 落点台词/表情仍是既有那一套（`lastEvent = {kind:'fortune', id:5}`），
   没有复刻 exe 收尾那句「向每人收了一張卡片」的逐字演出。
