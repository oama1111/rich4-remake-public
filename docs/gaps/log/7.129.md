#### (1) 清掉的 6 个假阳性：全部是**表现层/平台基建**，只是打分器看不见

`audit_channel2_targets.py` 的排除靠两道闸：`looks_ui and score0 == 0`。
本轮发现「地块/设施/企业」那一格 `IMPACT_REGIONS[2] = 0x48A000..0x496000`
**混着整片渲染缓冲与消息路由表**，于是这些函数被打成 5 分、`score0 != 0`，
`looks_ui` 那道闸**从来没机会生效**。

**故意换了口径**。差分驱动它们只会抓到一条**已经登记过**的偏离，产不出新证据。

★ **改动的顺序有讲究**（写进了代码注释）：必须先往 `NON_RULE_GLOBALS` 加
`0x48b8c4` 等（把它们的 `score0` 降到 0），**再**往 `VERIFIED_PRESENTATION`

（`0x4018e7` 另有 `0x48a010` 的写点，故它走的是**无条件**白名单 `VERIFIED_NOT_RULE`。）

#### (2) ★★ 前瞻 / 反瞻 `0x0040b221` / `0x0040b343` —— 差分 **58/58**

这是工作单里**唯一被复刻真正实现了却从没被驱动过**的一对（复刻侧
`ai/card-policy.ts:192` 的 `lookahead()`、`ai/tool-policy.ts:126` 的 `backtrack()`），
所以优先做它。新增 `rich4-spec/tests/test_lookahead.py`。

**从字节里读出的语义**（`0x40b221` 全 83 条指令；`0x40b343` 只差两条初值）：

```asm
0040b22e  push 0x10 / push 0 / push 0x48b8b4 / call 0x456f60  ; ★ 输出缓冲先清 16 字节
0040b23e  cmp [esp+0x30], 8 / jle 跳过                        ; ★ 只对 n>8 封顶（负数不封）
0040b24d  imul eax, [esp+0x2c], 0x68
0040b254  mov dx, word [eax+0x496b74]     ; 前瞻：cur  = node_id
0040b25f  mov ax, word [eax+0x496b76]     ; 前瞻：prev = lastNodeId
；反瞻 0x40b376/0x40b381 把这两条**对调**，其余 80 条逐条同构
0040b291  mov edi, [0x498e80]             ; ★ 节点表是**指针**，stride 0x28
0040b2b1  mov dx, word [edi+eax*2+0x18]   ; 4 个邻接槽
0040b299  mov ebp, [edi+0x24]             ; flags
0040b29e  mov ecx, 0x40000000             ; ★ 槽 slot 的封路位 = 0x40000000 >> slot
0040b2d7  test ebx,ebx : =0 ⇒ buf[i]=prev（死路，**不算岔路**）
0040b2e8  cmp ebx,1    : =1 ⇒ buf[i]=cand[0]
0040b2f2  call 0x456f2d / idiv ebx        ; ≥2 ⇒ buf[i]=cand[rand()%k]、返回值置 1
0040b311  mov eax,[esp+0x0c] / mov [esp+0x14],eax   ; ★★ prev 逐格更新（不是固定 lastNodeId）
0040b32a  mov [esp+0x0c], <buf[i]>                 ; cur ← 刚写的那一格
```

**本轮钉住的 58 条**，其中**真正有分辨力的 4 条**（写错也照样"看起来对"的那种）：

| # | 断言 | 写错时的错误表现 |
|---|---|---|
| 1 | ★★ **`n > 8` 才封顶的证明**：在紧邻的 `0x48b8c4`（可見表）放哨兵，`n=12` 跑完后哨兵**必须还在** | 若无封顶，第 9 格会踩进可见表 —— 而这在原版里是**静默的数据损坏** |
| 2 | ★★ **`prev` 逐格更新**：`1→2` 之后，2 的邻接 `[1,3]` 里 `1` 被当来路排除 ⇒ 只剩 3、**返回值 0** | 若 `prev` 固定在 `lastNodeId=0`，2 会有 2 个候选 ⇒ **摇随机数并返回 1** |
| 3 | ★★ **第二格死路写的是"更新后的 prev"**：`1→2`、2 无邻接 ⇒ `buf = [2,1]` | 固定 `prev` ⇒ 写成 `[2,0]` |
| 4 | ★ **占用位 `0x100<<idx` 不算封路**：flags 只置 `0x100` ⇒ 仍是 2 个候选、返回 1 | 若把 flags 当整字判非零 ⇒ 变成"封路"、只剩 1 个候选 |

另含：`n=0`/`n=-1`（负数不封顶 ⇒ 循环直接不成立）、4 个邻接槽的封路位**逐个**验
（bit30/29/28/27）、岔路取模 `rand % k`（含 `rand=12345` 与 `rand=9`，
**验的是取模而非位与**）、死路写 prev、两条函数**共用同一个全局缓冲**
（`0x48b8b4`，故不能同时持有两份结果）、反瞻在同一拓扑下给出**不同**结果
（证明起点/来路确实对调）。

⚠️ **不在断言范围内的**：原版这里摇的是**全局 CRT `rand()`**，复刻走
`aiRoll(state, salt, n)` 确定性替身（不推进 `rngState`）—— 这是**已登记**的
**D-004**（`known-deviations.md:629` + `gaps/02-cards.md:125` 逐点表）。
本测试只钉「`cand[rand() % k]` 这条取模规则 + `rand` 的消费时机」，
**不声称复刻的选点与原版逐位相同**。
