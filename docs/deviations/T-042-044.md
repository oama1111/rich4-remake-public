## D-MINI-2（**素材缺口，已用几何绕开**）企鵝的命中表 `Panel.mkf` **#81** 也取不到

原版的命中判定非常直接：`0x00414abe` 把鼠标位置换算成**命中表 #81 的一个字节**，
那个字节就是格号：

```asm
00414abe  mov  ecx, eax
00414ac0  shl  ecx, 2
00414ac3  add  ecx, eax
00414ac5  shl  ecx, 7                 ; ecx = y * 640
00414ac8  mov  eax, [0x48bd38]        ; = read_mkf(panel, 0x51) 的 640×480 8bpp
00414ace  add  ecx, eax
00414ad0  mov  cl, byte [ecx + ebx]   ; ★ 像素值 = 格号 0..80
00414ad3  …    idiv 9                 ; row = 值/9、col = 值%9 → fcn_0041211c
```

`Panel/0081.bin` 就是这张 640×480 的 8bpp（307200 字节），`manifest.images` 里同样没有它。
本模块改用**格坐标表 + 菱形几何**重建：

- 每格是以表里的 `(x, y)` 为中心、半宽 48 / 半高 24 的菱形；相邻格心相距 `(48, ±24)`，
  两张 96×48 的菱形严丝合缝 → 判定式 `|dx|·24 + |dy|·48 ≤ 48·24`。
- **验证**：把 #81 逐像素反查所属格，**64 个有效格的格心像素值全部等于它的格号**；
  `penguin-hit` 的测试里还钉了 15 个采样点（含几处偏心点、棋盘外、冰屋正中），
  全部与 #81 的原始像素一致（`minigame-screen.test.ts` 的「命中与命中表 #81 逐点一致」）。
- 冰屋那格（索引 40）在 #81 里像素值是 **0**（无效）→ 点上去 `penguinHitCell` 返回 `null`，
  与原版「`fcn_0041211c` 返回 0 → 什么都不做」一致。

## D-MINI-5（**有意偏离**）没有「不玩」这条路 —— 卡面那句「不玩送 null」在原版不存在

原版共用一条「不玩」出口 VA 0x00415457，进那条路的只有两种人：

```asm
0041522e  cmp byte [player + 0x15], 1   ; who_plays == 真人？
00415235  jne 0x415457                  ; 不是 → 不玩
0041523b  cmp byte [0x497159], 0        ; 设置里的小游戏开关？
00415242  je  0x415457                  ; 关了 → 不玩
```

**真人进了小游戏窗就必须玩完**，窗口过程里没有任何「放棄/跳过」的输入
（只有 `0x0f` 重画、`0x113` 定时器、`0x201/0x203` 鼠标按下、`0x401` 建窗、`0x405` 自定义消息）。

本引擎里这两条也已经在 **core** 覆盖：`enterMinigame()` 只在真人时挂 `pending`，
否则直接 `settleMinigame(state, null)`（按 50..69 抽）。所以本屏：

- **不提供**「放棄」钮（那是改良，C-FID-1）；
- 也**不会**主动送 `score: null`。

（`{ type: 'minigame', score: null }` 这条路仍然通 —— core 与通用对话框那条老路都在，
只是本屏不发起它。）

## D-MINI-6（**有意简化**）走行用整数格推，土堆按「走过即抹」实现

原版企鵝的走行是 **16.16 定点**的直线插值（`fcn_0041211c` 算步长、`fcn_00412287` 每 tick 走一步）：

- 主轴 `±0x10000`、副轴 `(drow << 16) / |dcol|`（向零取整）；
- 走到的那一格若是无效格（`word[+0] == 0`）就把**那一条轴**停住（`loc_004123aa`）；
- 每 **4** 个 tick（`test byte [0x48bcc4], 3`）重算一次朝向与插值。

本模块按**整数格**推：每 4 tick 走一格，先试对角线、被挡就退化成只走主轴、再被挡就停下。
观感与原版一致，差异只在「副轴被挡时原版会贴边走、本模块会停住」这一种边角情形。

**土堆为什么会消失**：原版每 tick 都把**上一帧的脏矩形**用底图重贴一遍
（`fcn_004562cc` @0x00412573，脏矩形存在 `0x48bd5c..0x48bd68`），
企鵝走过的地方土堆就被擦掉了。本模块用「走过该格 → `mound[i] = 0`」等价表达，
不逐像素重贴（本引擎每帧整屏重画，没有脏矩形可言）。

## D-MINI-7（**有意简化**）「接住」的包围盒按当前帧的贴图量，取不到图时用 #100 图 0 兜底

原版判「接到」是拿**当前要画的那一帧**的图记录算矩形（@0x00413743 起：
`left = x − anchorX`、`top = 0x17c − anchorY`、`right/bottom = +宽/高`），
而那一帧的图号取决于朝向与走行帧（`(朝向−1)*10 + 5 + 帧`）。

纯函数不该自己去取图，所以 `giftStep(st, mx, box, now)` 把 `box` 当参数收；
`tick` 里用 `env.sprite()` 把当前帧量出来传进去（`catchBoxOf`）。
取不到图（素材没加载好）时用 `Panel.mkf` #100 图 0 的 `66×72`、锚点 `(33,71)` 兜底。
各角色那 25 帧的宽高相差 ±20px，所以这是**兜底**而非常态。
