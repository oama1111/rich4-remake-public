### 7.11 ★ 第 28 条（本轮）：夢遊卡的**敌意增量**补上（簇 F 剩余之一）

原版在**免罪卡判定之前**就记敌意（`@source 0x004442cb`–`0x004442ea`）：

```asm
004442cb  mov  edx, [0x4990e8]   ; price_index
004442d1  mov  eax, edx
004442d3  shl  eax, 2
004442d6  add  eax, edx          ; 5×pi
004442d8  add  eax, eax          ; 10×pi
004442dc  shl  eax, 4            ; 160×pi
004442df  sub  eax, edx          ; ★ 150×pi（与陷害卡同系数）
004442ea  call 0x40df69          ; update_hostility(目标, 施卡者, 150×pi)
004442f5  call 0x4413ad          ; ← 免罪卡判定在**之后**
```

并且目标**已在冬眠**时整段跳过、**连敌意都不记**
（`@source 0x004442be cmp byte [eax+0x496b9e],0 / jne 0x44449b`）。

实现：`SLEEPWALK_HOSTILITY_FACTOR = 150`；`applySleepwalkCard` 新增 `priceIndex` 参数，
在防御卡链**之前**算出 `hostilityDeltas`（冬眠中则为空数组）；`registry.ts` 把它并进
`hostilityDeltas`（**被免罪卡挡下时照样记**）。

新增 4 例测试，其中两条专门钉住"位置"这个易错点：
**被免罪卡挡下照样记**、**被嫁祸改写后仍记在原始目标头上**；另两条是**冬眠中不记**与基本系数。

> ⚠️ **本条的诚实边界**：我只做了"**敌意**"这一半。原版 `0x004442c5 jne 0x44449b`
> 跳过的其实是**整段效果**（不施加、不查防御卡、也不记敌意），而 remake 目前仍会施加效果 ——
> 即"目标已在冬眠时夢遊卡无效"这一半**仍未做**。分开做的理由：
> 那一半会改变 `ok`/扣卡语义（原版**卡已消耗**），需要连同 `registry` 的消耗时机一起核对，
> 不适合塞进同一轮。已在续做指南里记为簇 F 的剩余项。
