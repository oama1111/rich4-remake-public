## Q-SPEECH-3　中间档的 `rand() & 1` 被改成「一律取前一句」

- **现象**：原版每个分档函数的**中间档**都掷一次硬币在相邻两句里挑
  （`call _libc_rand / and eax,1 / mov reg,[表 + 基址 + eax*4]`）：
  收入 0|1、支出 3|4、進帳 6|7、付錢 9|10、罰款 12|13。
- **取证**：`0x0044f272..0x0044f288`（收入）、`0x0044f304..0x0044f31a`（支出）、
  `0x0044f3bf..0x0044f3d9`（進帳）、`0x0044f49a..0x0044f4af`（付錢）、
  `0x0044f5d4..0x0044f5e9`（罰款）。
- **处置**：本卡的接口是**纯函数** `speechEventsFor(before, after)`（C-DET-1/2/4：
  表现层不许消费引擎 PRNG，否则回放对不上），故一律取 `eax = 0` 那一支
  —— 也就是两句话里**靠前、语气更重**的那一句（0 / 3 / 6 / 9 / 12）。
  事件 18 那道 1/2 機率（`call rand / test al,1 / je`）同样确定性取「说」。
- **影响面**：中间档永远说同一句；不改任何规则数值。
- **★ 一条由此得出的全局结论（2026-09-16 补，逐条核过 exe）**：
  这类「表现层也在消费全局 PRNG」的地方**不止台词**：
  拍卖窗口动画 4 处（`0x43b5ff`/`0x43b945`/`0x43b9d6`/`0x43baa7`，按**帧**触发）、
  台词阶梯 4 处（`0x44f354`/`0x44f42d`/`0x44f567` 的中间档 + `0x44f4ed` 的 1/2、
  `0x44f627` 的 1/3）都是。
  ⇒ **原版的全局随机序列是「规则 + 表现」共用的，且表现那一半与帧率/玩家操作有关**，
  所以**任何无头确定性引擎都不可能逐位对齐原版的全局序列** ——
  能对齐的只有**规则相关**的那部分消费（拍卖开价 `2N` 步、走位前瞻岔路 1 步、
  骰子、命運/新聞 等）。
  这一条应当写进「通道 3（全流程轨迹差分）」的适用边界：
  轨迹差分只能比**状态指纹**，不能比 PRNG 位置。

## Q-SPEECH-4　「金额」是从 `monthlyPaid` / `monthlyReceived` 的差分还原的

- **现象**：原版的金额是**调用点压栈传进来的参数**（如過路费那处
  `push ebp` @ 0x00419f65），不在任何状态字段里。本卡的接口只给
  before/after，故只能从差分反推。
- **取证**（差分确实等于那一笔）：
  - `pay_money`（VA 0x0041d2c6）**自己**把这一笔累加到 `+0x5c` / `+0x60`
    （`add dword [player*0x68 + 0x496bc4], ebx` / `…c8`），本引擎的
    `transferMoney` 是同一条（`rules/payment.ts` 的同 VA 注释）。
  - 旅館那一处的「金额」是**天数**：`0x0041a7d7 push [esp+0xd0]`，紧接着
    `0x0041a7f4 mov [player+0x32], 天数−1`（0 时挂 0x80）。故用
    `(+0x32 & 0x7f) + 1` 反推。
  - 「點」值取自卡片/道具表（`0x0041b38c` 的 `card_table[…]`、
    `0x0041b98b` 的 `tool_table[…]`），本引擎里对应的量是 `points`。
- **处置**：照上表接线。**两处已知不精确**，都只在极端局面下出现：
  1. `pay_money` 累加的是**实付额**（`paid`），原版传给发言人函数的却是
     **应收额**（`ebp`）。付款方钱不够时两者不同（差一档时说话内容会变）。
  2. 同一动作里走两笔账时，增量是**两笔之和**（本引擎里极少见）。
- **影响面**：只影响「说哪一句」，不影响任何规则数值。

### 5.1　16 / 17（同一街區獨佔 ≥ 3 塊）

**判据（逐条读自 exe，不是照猜）** —— `fcn_0044f627` @ VA `0x0044f627`，
签名 `(地名串 /*[esp+4]*/, 旗标 /*[esp+8]*/)`：

```asm
0044f636  ebx = [0x498e84]                     ; 住宅地表（map-format.md §4.2，步长 0x34）
0044f63c  add ebx, 0x34                        ; ← 循环头（jmp 0x44f63c）
0044f63f  cmp esi, [0x498e98] / jg 结束         ; num_lands，esi 从 1 起
0044f647  lea eax,[ebx+4] / push eax / push ebp
0044f64c  call 0x458370                        ; ★ strcmp(land_i + 4, 第 1 参)
0044f654  test eax,eax / jne 下一个
0044f658  al = byte [ebx + 0x19]               ; land.owner（1 基）
0044f65b  edx = [0x49910c] + 1                  ; 当前玩家
0044f662  cmp eax,edx / jne 下一个
0044f666  inc edi
0044f66a  cmp edi, 3 / jl 返回                  ; ★ 门槛 ≥ 3
0044f677  test 旗标,旗标 / je 说事件 16
0044f67b  call rand / idiv 3 / test edx,edx     ; ★ 旗标 ≠ 0 时 1/3 機率
0044f68e  jne 返回
0044f6ab  …说 [0x48088e] = 事件 17
0044f6d5  …说 [0x48088a] = 事件 16
```

- **`0x458370` 是 strcmp**（`rich4-spec/docs/systems/cards.md:1814` 已注明；
  逐字节复核：`0x458375` 取两串指针、`0x458381` 起是 4 字节一组的
  `0x80808080` 检测）。所以**「街區」= 同名地块的等价类**，
  比的是 `land + 0x04` 那个 Big5 名字串。
- **两个调用点**（`callers 0x44f627`，各只有一处）：

  | 调用点 | 第 2 参 | 同一条路上写的字段 | 出声 |
  |---|---|---|---|
  | `0x0041a13e` | `0x0041a138 push 0` | `0x0041a0de mov byte [esi+0x19], al`（**歸屬** = 玩家+1）| 16 |
  | `0x00419a31` | `0x00419a2b push 1` | `0x004199d1 inc byte [esi+0x1a]`（**等級**）| 17（1/3）|

  两条都在 `0x004198b9`（落点例程）里：`je 0x41a013` 那一支是
  **無主地**（`test ch,ch / je`，`ch = [esi+0x19]` = owner），
  故 16 = **買下一块无主地**；另一支是**自有地加蓋**（`owner == 当前+1`），
  故 17 = **加蓋**。本引擎里这两条分别由 `pending.kind === 'buyLand'` /
  `'upgradeLand'` 留下（`state/reduce.ts` 的两个 case 注释本来就引了同一批 VA）。
- **17 的一个额外条件**：`0x004199eb cmp byte [esi+0x1a], 5 / jne 0x419a2b`
  —— 加蓋**剛好到 5 級**时那一步改说事件 15，故 17 只在 `等級 ≠ 5` 时说。
- **1/3 機率**：与 Q-SPEECH-3 同一条口径，确定性取「说」。

**街區号从哪来**：`GameState` 里没有它，**但 `topo.lands[i].name` 就是那一位**
（`LandInfo.name` ← `land+0x04`，同一个地图表）。实测 8 张图的名字确实是成区的
（地图 0：`台北市` = 1..4、`桃園市` = 5..8、…；地图 3：`底特律` = 1..4 …），
所以**不需要往 core 的状态里塞一个 id**。

**处置**：`speechEventsFor(before, after, topo?)` 多了一个**可选**的 `topo`；
探测器 `detectAreaMonopoly` 只在 `topo.lands` 到位时出声（缺席 = 不出声，
其余槽位不受影响）。`main.ts` 只改一行（把模块级的 `topo` 传进去）。
**已知不精确 1 条**：原版对「買地」用的是**那一块地的名字**（调用点参数），
本实现用 `topo.lands` 里同一 id 的名字 —— 两者同源（都来自地图表），
只有在夹具把 `pending.name` 与 `topo` 改成不一致时才会不同（测试里钉住了）。

### 5.2　22 / 23（神明）

**`godInfo` 是「物件下标 + 1」，种类要查 `objects[]`** —— 这一点先坐实：

- `god_activate`（VA `0x0040ead7`）的入参 3 是**物件 1 基槽位**；
  `0x0040eb01..0x0040eb09` 把它 `dec` 成 0 基存回 `[esp+0x9c]`，
  `0x0040eb19 movzx esi, byte [eax*8 + 0x496d08]` 取的才是 **type**，
  `0x0040ec01 lea edx,[esi−1] / 0x0040ec0d jmp dword [edx*4 + 0x40ea9b]`
  按 **type** 分派（跳表 15 项，`dump 0x40ea9b 15 4`：
  `[4]=0x40ef1b`、`[5]=0x40efe4`、`[6]=0x40f083`、`[7]=0x40f155`、`[14]=0x40f2eb`）。
- 本引擎的对应量：`players[p].godInfo`（1 基）与 `objects[godInfo−1].type`
  —— 与 `rules/objects.ts` / `cards/summon.ts` 的字段说明一致。

#### 事件 22 = **附身**（種類 5/6/7/8/15 的實作第一件事就是它）

五处取串点由 **byte 级搜索** `tools/disasm.py find a2084800` 得到，全 exe

#### 事件 23 = **離身**（種類 5/6/7/8/15 才說）

`0x40e32c`（带演出动画的送神）——`callers 0x40e32c` 共 3 处：

```asm

0040e35d  je 0x40e36e                                ;   （住宿/消失/坐牢/住院）
0040e361  call 0x40e14d / jmp 0x40e661               ;   有一位非 0 → 只拆、不吭声
```

三个调用点：`0x0040eb3f`（**換神**：`god_activate` 里发现已有神明，先送走旧神）、

1. **破产不算 23**：`0x40cd87`（`_rich4_player_bankrupt`）走的是

2. `0x40e32c` 的 **`[player+0x32]` 四字节**：`inHotel / disappearing /
   inPrison / inHospital` 任一非 0 → 不说 23。
3. `player_say` 自己的两道闸（`0x44ef86 +0x37 sleepWalking` /
   `0x44ef93 +0x36 sleeping`）对 22/23 都成立。
**种类 10（惡魔）**：送神符送得走它（`canDispel` 含 10），但 `0x40e618`
那道门槛不含 10 ⇒ **不说 23** —— 测试里钉住了这一条。

## ✅ Q-SPEECH-6　同一动作派生多句时会**叠着响** —— **2026-09-16 已修**

- **现象**：一次過路费在原版要说两句（付方 9/10/11、收方 6/7/8），
  `_rich4_player_say` 是**播完才返回**（同步），两句一前一后。
- **本实现（先前）**：`SoundPlayer.play` 即发即忘（`createBufferSource().start()`），
  `playSoundFor` 照「命中的都播」处理，于是两句**同时**响。
- **处置（2026-09-16）**：**语音改成跟着显示队列走** ——
  `playSoundFor` 只把段落排进 `SpeechQueue`，**不放音**；
  `main.ts` 的 `speechTick()` 在「当前这一段换了」时放**它那一句**
  （`spokenBubble` 身份比对）。于是：
  - 同一动作派生的多句 → 一前一后（与原版同序）；
  - 语音与字幕**同步**（先前是各走各的）。
- **顺带修掉 Q-SPEECH-9 的时长问题**：`SoundPlayer` 新增纯查询
  `durationOf(archive, resource)`（毫秒，没解码好给 `null`），
  `main.ts` 起播后拿它调 `SpeechQueue.extend(voiceMs)` ——
  总时长 = 语音时长 + 1000 ms，正是原版「**等声音停 → 再
  `fcn_004544f6(0x3e8)`**」那两步（VA 0x00454520 起的循环）。
  长句不再「字先没了、声音还在」。
- 用例：`speech-bubble.test.ts` 的「撑长」一组（7 条）+ `audio.test.ts`（3 条）。

## Q-SPEECH-7　勘误：事件 15 的判据是**地块的 `+0x1a`（等级）**，不是玩家结构

- **现象**：T-051 的 `@rich4/data` `speech.ts` 把事件 15 的调用点注成
  「`player+0x1a == 5`」。
- **取证**：那一处的 `esi` 不是玩家指针 —— 同一条路上有
  `lea eax, [esi + 4]`（推**地名**串）与 `movzx ebp, word [esi + 0x1e]`
  （推房價），而 `csrc/land.h` 明写 `+0x19 owner` / `+0x1a level`。
  0x00419a0e 的原文就是
  `inc byte [esi+0x1a]` → `cmp byte [esi+0x1a], 5` → 说事件 15。
- **处置**：本卡的 `detectLevelFive` 按「`landLevel` / `facilityLevel`
  由非 5 变 5」判定。`@rich4/data` 的 `gloss` 字段是注释性的（文件头已声明），
  本卡当时没改它 —— ✅ **2026-09-16 已由汇总人订正**：
  `packages/data/src/speech.ts:162` 的 gloss 改成
  「**本塊地的等級** `land+0x1a` 由 4 升到 5 —— @0x00419a0e `inc byte [esi+0x1a]`
  / `cmp byte [esi+0x1a], 5`」，并写明 `esi` 是地块记录、不是玩家结构。

## Q-SPEECH-8　`Speaking.mkf` 改成**按需装载**（本项目的选择）

- **现象**：此前 `boot()` 只装 `Effect.mkf`，不装 `Speaking.mkf`（注释写着
  「有 57MB，先不装」），于是「接了语音却听不见」。
- **取证**：`audio.ts` 的 `addArchive` 注释本来就是「可以只装 Effect.mkf ——
  Speaking.mkf 有 57MB，**按需再装**」。
- **处置**：在 `main.ts` 的 `playSoundFor` 旁加了一个一次性后台拉取
  （`ensureSpeakingArchive()`，`speakingLoading` 去重、`sound.muted` 时连拉都不拉）。
  **静音那一条路仍然只有 `SoundPlayer` 在走**，没有另开。
- **已知代价**：档案到手之前**第一句听不到**（`SoundPlayer.play` 在档案缺席时
  安静丢弃）。换成「等装载完再播」要给 `SoundPlayer` 加排队，见 Q-SPEECH-6。
  若需求方不接受这 57MB 的按需下载，删掉 `ensureSpeakingArchive` 的调用即可，
  语音会自动退回「静默」状态。

## Q-SPEECH-11　★ 卡牌使用者台词：一条**不走状态差分**的新通道（2026-09-19 补）

- **现象**：原版每张可主动使用的卡都在函数体里说一句自己的台词
  （`player_say(出牌者, flag, 卡牌台词表[角色][卡号-1])`，26/30 张卡各一处，
  `@source 0x44210e` 等；表 VA `0x48123a`、行距 360）。
  这是**调用点参数**，不是状态跃迁 ⇒ 本卡原先那 11 个探测器**永远看不见它**，
  复刻侧因此整条缺失（用卡时一个字都不说、语音也不响）。
- **本实现**：
  1. `@rich4/data` 新增 `card-lines.ts`（360 条，`tools/gen-card-lines.py` 生成，
     `card-lines.test.ts` 与 exe 指针表逐条比对）；
  2. core 新增纯表现提示 `GameState.lastCardPlay = { player, cardId }`
     （`playCard()` 成功才写；不进指纹/存档/快照，与 `lastNpcWalks` 同类）；
  3. 客户端 `speech.ts` 的 `cardPlaySpeech(before, after)` 翻成气泡，
     在 `playSoundFor` 里**先于**状态跃迁派生的台词入队（顺序同原版）。
- **★ 订正（2026-09-19 W-50）**：本节原先写「`player_say` 的第二个实参（`flag`，各卡传 0 或 3）
  **函数体里一次都没读**（235 条指令中 `[esp+0x28]` 零命中）⇒ 无需建模」—— **两处都错**：
  1. 那个实参**确实被读**：`0x0044f050 mov edx,[esp+0x30] / inc edx`。读取点在**两次 `push`
     之后**，所以偏移从 `0x28` 变成 `0x30`；旧结论是 grep 错了偏移量。
  2. 它**就是表情号**（头像图号 = `arg2 + 1`，见 Q-SPEECH-9 第 ⑤ 步）。
     `0x80` 那一位另有用途（`0x0044ef63 test byte [esp+0x25],0x80` = 「不重设视窗卷动」），
     与表情号并存 —— 所以「各卡传 0 或 3」里的 **3 是「表情 3 + 不卷动」**，不是旗标 3。
  同一条订正也要进 `rich4-spec/docs/systems/dialogue-voice.md` §二（那边另开 PR）。
- **已知简化**：
  1. 原版 `player_say` 有「**同一句不重播**」闸门
     （`cmp ebx,[0x4762c8] / je 0x44f228`：文本指针与上一条相同就直接返回）。
     本实现只保证「同一次用卡不重复播」——连续两次说**同一句**时本引擎会响两次、
     原版只响一次。
  2. 卡牌台词表的槽 30..89（每角色另外 22 条非空槽）仍未接线。
- **影响面**：纯表现（多一句字幕 + 一段语音），不改任何规则数值；
  三道「不说话」的闸（消失/夢遊/冬眠）已照抄 `player_say` 开头。
