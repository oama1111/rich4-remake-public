### 7.15 ★ 第 33 条（本轮）：第 31 条规则的**首个落地**（夢遊卡替身支）

翻上一轮造好的标志，第一处：

```ts
// registry.ts，卡片 16 的替身分支
if (!applied.applied) return fail('noEffect', true);   // ← 加上了 true
```

依据（`@source 0x00444210`–`0x00444219` 与 `0x004444a3`）：

```asm
00444206  mov  esi, eax                 ; esi = 目标
00444208  test esi, esi / je 0x4444b8   ; 选不到目标 → 返回，不扣卡
00444210  push 0x10                     ; 16 = 夢遊卡
00444219  call 0x441343                 ; ★ remove_card —— 目标选定后立刻扣
…
004444a3  cmp  byte ptr [ebx + 0x498df4], 0   ; 替身冬眠中？
004444aa  jne  0x4444b3                 ; 只是跳过写天数，**卡早已扣掉**
```

**又一次撞上"旧测试钉死 bug"（第 6 次）**：`registry.test.ts` 里那条测试的**标题就写着
「也不扣卡（原版那条 jne）」** —— 它把偏离当成了正确行为，还引用了那条 `jne` 作依据
（而那条 `jne` 只管"写不写天数"）。已改成「不动，但**卡照样被扣掉**」，
并注明原版 `remove_card` 在它之前。

**哨兵测试按预期变红并已更新** —— 正是上一轮加它的目的：让偏离被修掉时**有人知道**。
（过程中还发现哨兵的替身少了 `place`/`nodeId`，走的是更早那条 `actorActive` 分支；
那一条是"打不出去"，本来就不该扣卡 —— 这个区分本身也验证了规则的两半都对。）

> ⚠️ **本轮（第 34 条）订正了这一条**：`fail('noEffect', true)` 的**扣卡**方向是对的，
> 但把 `ok` 报成 `false` 仍是偏离 —— 原版这条路径返回 `esi`（非 0）＝**成功**。
> 已改成 `noEffect()`（`ok: true` + 已扣卡），`consumes` 参数整个撤掉。
> 详见 **§7.16**。
