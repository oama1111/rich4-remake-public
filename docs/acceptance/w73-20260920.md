### 名字校验

| 输入 | 结果 |
|---|---|
| 空 / 只有空白 / 只有控制字符 | **拒**，红字「名字要 1~12 個字（不能只有空白）」，覆盖层不关 |
| 13 个汉字 | **拒**（同一行红字） |
| `👍` × 12（24 个 UTF-16 单元、**12 个码点**） | **放行** ⇒ 判据是码点数，不是 `.length` |
| `小明` | 放行 → 进標題畫面 |

`單機遊戲` ⇒ 覆盖层关掉，走**现有**標題畫面（`♪ midi01.mid` 起，与从前一致）。

## 3. 邀请链接 → 第二个人进来（**同名不串座**）

第二个标签页打开 `http://localhost:8787/?room=9JUX9Q`：

```
{"name":"小明","room":"9JUX9Q","hasOverlay":true}
```

⇒ 停在该停的地方（加入），房间码**已填好**（那就是邀请链接的全部作用）。

点 `加入房間` 之后（`/tmp/w73-lobby2.png`）：**两座都叫「小明」**，一个角色 1、一个角色 2，
两座都「在線」，第二座标着「（你）」。

```
房間：1人小明 2人小明
✔ 進房 9JUX9Q：我是 2 號座
```

★ 验收里这两个标签页**共用同一个 `localStorage`**，所以为了让它们扮「两个人」，
第二个标签页在连之前把 `clientId` 显式换成了另一个（见 E-31）。
这一步恰好也就是「同名两人各占一座」这条判据的现场证据。

## 5. 服务器侧：令牌、上限、回收

`hub.test.ts` 新增/改写的用例（全部在旧实现上是红的，见 §7）：

- 同名两人各占一座（名字重复允许）；
- **同 `clientId` 断线重连认回原座 —— 名字改了也认回**（显示名跟着改）；
- **不同 `clientId` 同名不认回**：另占一座，原座仍是「断线中」等他；
- 非法 `clientId` / 房间码 / 名字（含 13 字符、只有控制字符）⇒ 回 `error` **并 `close()`**；
- 名字里的控制字符被**去掉**而不是整条拒掉；12 个码点（`𠮷`×12）合法；
- **全桌无人在线满 10 分钟 ⇒ 房间被删**（差 1 ms 还在）；有人回来 ⇒ 计时清零；
- **第 51 个房间被拒**（「伺服器房間已滿」），**已有的房间照常进出**，
  回收掉一间之后立刻又能建新的。
