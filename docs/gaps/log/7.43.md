### 7.43 ★ 第 62 条（本轮）：**卖出股票**补差分（24/24），修掉一对 u16 计数器

#### (1) 差分：`tests/test_sell_stock.py` **24/24**

`_rich4_sell_stock(player, stock, amount, toPlayer)`：

| 验到的点 | 结论 |
|---|---|
| 落点 | `toPlayer != 0` → 玩家**存款**；`== 0` → `0x499080`（破产清算那支） |
| ★ 成本均价 | **只在持股变成恰好 0 时清**（`holdings != 0` 就跳过） |
| ★ 超卖 | **不夹**：持股变负数、成本不清、进账按请求量算 |
| ★ 成交量两格 | `stock+8`/`+0a` 是 **u16**，`add word` ⇒ **回绕**（65530+300 → 294） |
| ★ 宽度不一致 | 进账按**完整 amount**，计数器只吃 **`cx`**（65541 → 计数 +5、进账 65541） |
| 价格 | `float32` 后向零截断 |
| 反向确认 | `0x428d2a`（买）是 `sub word`：10 − 300 → **65246** |

#### (2) 复刻侧改动

| 改动 | 文件 |

#### (4) ★ 顺带修掉工作单自己的一个口径 bug（否则"还剩多少"一直是错的）

`audit_channel2_targets.py` 的 VA 正则原来只认 **8 位**（`0x00428E23`），
而测试里普遍写 **6 位**（`0x428E23`）⇒ **自己刚写过的测试没被算成覆盖**，
候选表里一直混着已经差分过的函数（本轮就看到 `0x428e23`/`0x41d2c6`/`0x41d89e`
明明测过却还在单子上）。同时复刻侧的被引用集合也被同一 bug 少算。

修正为 `0x[0-9a-fA-F]{5,8}` 后：
- 已测函数**确认消失**（抽了 10 个已验证 VA 逐个核对，无输出）；
- 候选数 164 → **219 个 / 94,494 字节** —— 这个上升是**修正统计**，不是新增债务
  （复刻侧引用的 VA 之前漏算了一大半）。

另外把口径写清楚了：注释里提到某 VA **不算**驱动；`patch(0x…)` 同一行**跳过**
（被打桩的是被替换掉的表现层，不是被测对象）。

#### 诚实边界

- `0x428d2a`（买）只验了**计数器那一格**；它的**認購定价**（`企業+0x24 / 10000`）与
  **加权平均成本**更新不在本轮范围，仍是读汇编结论。
- `stock+8` 与 `+0a` 是否在数值上恒等**仍未确证**（`stocks.md` §4.3 的未决项）；
  本轮只证明两者都由买卖同步增减、都是 u16。
- 「消失池」`0x499080` 全 exe 无逻辑读取这一未决项不受本轮影响。
