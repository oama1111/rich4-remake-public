### 7.112 ★ 第 129 条（本轮）：`0x40829d` 的「不写规则字段」**再审计一遍** —— 结论升级，但**不变**工作单（附一条「为什么没加白名单」）

§7.94 把 `0x40829d`（5,960 B，工作单第 1 名）判成「重画棋盘」、证据等级 B。
本轮把它的 `writes`（`gen/functions.json`）**逐条打标**，得到更细的结论：

| 写点 | 落在 | 判定 |
|---|---|---|
| `0x48a44c`、`0x48a84c`–`0x48a856`、`0x48b2ac/b0`、`0x48bac8` | 「地块/设施/企业」区 | 全是**绘制/重绘用的坐标与脏位**（§7.94 已列） |
| `0x474930/34`、`0x475114`、`0x498ea0` | 不在任何规则区 | 表现层 |
| ★ `0x496b74`、`0x496b76`、`0x496b78` | 「玩家结构」区 | **`player + 0x0c/0x0e/0x10` = 落点坐标/朝向** —— 表现字段，不是钱/地产 |
| `0x496d0e/10/14` | 「玩家结构」区 | 同族的显示坐标 |

★ 关键点：`+0x0c/0x0e/0x10` 这三处只出现在 `0x4082bc` 那条**开局落点**分支里
（实测反汇编）：

```asm
004082bc  cmp dword [0x49910c], 4           ; 当前玩家 >= 4（不存在）
004082c3  jge 0x4083a3
004082c6  test eax,eax / jne 0x4083a3       ; arg1 != 0
004082cd  test edx,edx / jne 0x4083a3       ; arg2 != 0
;   …只有这三个条件全不成立才写 player+0x0c/0x0e/0x10…
```

⇒ 正常对局（`currentPlayer < 4`、而调用方传的是当前镜头/坐标）**走不进**那条分支；
而其余写点全是绘制用的坐标数组与脏位。

#### 为什么**没有**把它加进 `VERIFIED_NOT_RULE`

试了「写集合里没有任何规则字段 ⇒ 移出工作单」这条通用判据，结果**一个都命不中**：
`IMPACT_REGIONS` 的「玩家结构」整格是 `0x496B68..0x4971A8`，把**落点/坐标/朝向**
和**现金/存款/地产**混在同一格里 ⇒ `0x40829d` 仍被判「写了玩家结构」。
要让它生效得先把玩家记录**逐字段**（`+0x0c` 落点、`+0x0e` 朝向 vs `+0x1c` 现金 …）
登记成「规则字段白名单」，那是一次会影响全部 98 个候选的打分重构。
⇒ **本轮不动工作单**（仍是 98 个 / 37,622 字节），只把这一步记为下一步的候选，
并把上面这张逐条打标表留作重构时的输入。（诚实边界：仍未逐条读完 1,557 条指令。）
