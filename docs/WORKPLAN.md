## 0. 这份计划的判断依据

1. **代码量不是瓶颈，验收证据才是。** P0/P1/P2 全勾完、5,457 项测试全绿，但计划 §11 的
   P1/P2 **出口条件一条都没有证据**（1000 局 soak、性能三条、三平台真机包）。
   没有这些就不能宣布「第一阶段完成」。
2. **真人试玩是目前产出最高的信号源。** 第一份试玩报告的 7 条问题（BGM 无鼓、走子慢 2 倍、
   魔法屋两只女巫…）**没有一条被 5,457 项测试抓到**。⇒ 把「试玩 → 修」做成流水线，比继续堆差分测试值。
3. **本项目最大的风险是「猜」。** 铁律是「搞不清就回 `rich4.exe` 取证」。小模型读汇编控制流
   容易一本正经地读错（本项目的大模型也读错过多次，见 gaps 日志里十几处「订正」）。
   ⇒ 任务按**可机械验证的程度**分级；凡需要**新解读汇编控制流**的，执行方**停手上报**，不许自行裁定。

## 2. 硬规则（违反任何一条，PR 直接关掉）

1. **仓库必须保持 private**；不新建公开仓库、不把素材/exe/反汇编贴到任何外部服务。
2. **只读目录**：`../Rich4/`、`../rich4-re/`、`assets/game/`。永不修改。
3. **不许为了变绿而改测试。** 断言与实现冲突时：先判断断言是「真值断言」（有 `@source 0x…` 依据）
   还是「复述实现」。前者 ⇒ 改实现；拿不准 ⇒ C 级上报。**删除/放宽真值断言一律 C 级。**
4. **不许猜。** 任何数值、坐标、时序、分支条件，来源只能是：① 现有代码里带 `@source` 的常量；
   ② `python3 tools/disasm.py` 查到的**立即数/数据表**（查常量可以，B 级）；③ `rich4-spec/docs/systems/*.md`。
   需要解读**跳转逻辑/调用约定/栈帧**才能得出结论 ⇒ C 级上报。截图只用来验证，不用来取证。
5. **不许「改良」。** 原版没有的 UI/提示/数值一律不加（C-FID-1/4）。
6. **门禁**：每个 PR 合并前本地必须跑过
   ```bash
   pnpm check          # typecheck + lint(--max-warnings=0) + test
   ```
   且 `pnpm test` 的汇总行必须是 **`247+ passed`、`0 skipped`**（有 `../Rich4` 等原版目录时）。
   出现 skipped = 真值测试没跑 = 环境坏了，先修环境（`RICH4_WORKSPACE`，见 `vitest.config.ts`）。
   测试总数只许增、不许减；PR 描述里贴汇总行原文。
7. **不 force-push、不改写 main 历史、不直接推 main。** 一任务一分支 `ds/<任务号>-<slug>`，开 PR。
8. **三次止损**：同一问题连续 3 次尝试仍不绿 ⇒ 停手，把现象、已试过的做法、怀疑点写进
   `escalations.md`，换下一个任务。不许靠扩大改动面硬凑。
9. **不往 `docs/gaps/README.md` 追加长日志**（已近 9,000 行）。W-20 完成后新日志写
   `docs/gaps/log/<编号>-<slug>.md`；W-20 完成前先写在 PR 描述里。
10. **CI 额度**：三平台打包（`workflow_dispatch`）macOS 按 10 倍计费。W-05 之外不许触发；W-05 内总数 ≤ 6 次。
11. 提交信息沿用现有风格：`type(scope): 做了什么 -- 关键证据/数字`，英文或中文均可，一条提交一件事。
