# T-037 魔法屋屏 —— 有意偏离与未解出的假设

> 只记与「1:1 复刻」有关、且**故意和原版不一样**、或**没解出来靠近似**的地方。
> 反汇编出处都写了 VA，复核命令：`python3 tools/disasm.py va 0xXXXXXX`。
>
> 本屏的全部出处：
> **窗口过程 `fcn_004325c2`**（= 真人那一屏，挂 100ms 定时器；
> `Wait_0402_Message(0x4325c2)`，VA 0x004338af）、
> 入口 `fcn_0043380a`（`magic_house`）——两者都在
> `rich4-re/asm/rich4_magic_house.asm`。
>
> ★ 入口一进来就按 `player + 0x15` 分流：**== 1 走真人那一屏**
> （VA 0x0043381b `cmp byte [eax+0x496b7d], 1 / jne 0x43390b`），
> 否则直接转两个转盘（VA 0x0043390b）。本引擎没有那条分流
> —— 见下面 D-MAGIC-1。
>
> ★ 本屏与其它屏最大的不同：**core 里没有对应的待决交互**
> （`state/reduce.ts` 的 `runMagicHouse()` 一转就结算完），所以这一屏是
> **回放**，不是「玩家点一个功能」。

## D-MAGIC-1（**结构性近似**）落点只能从 `before → after` 反推

原版把两个转盘的结果当场用掉了，只留下副作用；本引擎的状态里**没有**
「这次转盘转到几」这个字段。于是 `magicView(before, after, topo)` 只能：

1. 先确认 `before` 里触发者**正站在魔法屋上**（`node.specialKind == SPECIAL_KIND.MAGIC_HOUSE`）；
2. 再用本地重写的 `magicTargets`（与 core 同一套判据）枚举十二个目标条件，
   与十个（+「得一張卡片」）效果**逐一比对 `before/after`**，取证据最强的一组。

对不上的情况（例如随机抽卡那几步）**照样起播**，只是 `option = -1`、不显示落点文字。

| 症状 | 处置 |
|---|---|
| 落点靠 diff 反推，不是原版真值 | **接受**（演出效果一致） |
| `option = -1` 时只转盘、不出结果字 | **接受**，免得漏掉一次演出 |

★ 若要求更严格，得在 core 的 `runMagicHouse()` 里把 `spin` 落进状态
（例如 `state.lastMagicSpin`）—— 那是 core 的改动，不在本卡范围内。

## D-MAGIC-2（近似）落点的「动作强度」是猜的排序

`matchStrength()` 给手牌 +8、现金/存款/點券 +4、其余 +2。**没有出处** ——

强度只用于**排序**（并且 `>= 8` 时提前返回），不参与任何规则。

## D-MAGIC-4（未解出）悬停时第二张图**索引进不存在的图**

原版悬停对**同一条目**连画两张（`fcn_00456418`，VA 0x00432ca3 起 +
0x00432d0e），第二张是 `imageIndex + 1`：

```asm
; VA 0x00432cc0 / 0x00432cee
movsx edx, word [ecx*4 + 0x4756e4]   ; 该功能的中线 x（画第一张用）
lea   edx, [ecx + 0x16]              ; imageIndex = 功能号 + 22
...
call  fcn_00456418                   ; 先画 imageIndex
; VA 0x00432db6 起（清完那一格之后）再画 imageIndex + 1
```

`功能号 + 22` 最大是 **34**（包里最后一张），`+1` 就索引进 **35..45**，
而 `Panel.mkf` #18 **只有 35 张（0..34）**。也就是说原版这一处**要么**还有
第二张表、**要么**那些图是另外加载的 —— 两种都没查出来。

本模块的处置：

- 只画 `功能号 + 22`（图 22..34，全部存在）；
- 第 0 个功能（`frames == 10`）额外在两帧间循环，其余功能固定一张；
- 悬停另**描一个黄圈**（`MAGIC_HOVER`，半径 34px）表示「指到谁」——
  圈的颜色/半径**没有出处**，纯为了让「指到哪一格」在只有一张图的功能上也看得见。

## D-MAGIC-5（**已结案 2026-09-16**）音效已接上

悬停/按下/转盘结果三支各自放了音效：

```asm
; VA 0x00432e40（结果）
push 0
push ref_004757e7          ; 表 0x4757e7
call _rich4_play_sound_effect
; VA 0x00433531（悬停）  push 0 / push ref_0048231a
; VA 0x0043365c（按下）  push 1 / push ref_00482322
```

`rich4_play_sound_effect`（VA 0x004542ce）取 `[ptr]` 那**第一个字节**当音效号，
兄弟结构体已经把这个约定钉死：`[0x48231a] = 0`（`rich4.asm:50864`）、
`[0x482322] = 1`（`:50871`）、`[0x482332] = 4`（`:50885`）。
`[0x4757e7]` dump 出来是 `27 00 00 00` ⇒ **39**。

**处置（2026-09-16）**：按原版接上 —— `MAGIC_SOUND_RESULT = 0x27`（39）在转盘
停稳进 `hold` 那一刻放，`MAGIC_SOUND_HOVER = 0` 在 `move` 指到新功能时放，
`MAGIC_SOUND_PRESS = 1` 在 `down` 按下时放。原版那第 4 号（`&0x482332` @0x0043376b，
取消那一路）在本引擎这一屏没有对应动作，故不放。

> **订正记录（2026-09-16）**：本条目先前有两处错 ——
> ① 把这一处记成音效 **16**（读错表项；`push ref_004757e7` 压的是**指针**，
>    取的是 `[0x4757e7]` 那第一个 dword，dump 出来 `27 00 00 00` = **39**）；
> ② 拿「`SOUND_IDS` 里没有这一条」当不放音的理由 —— 那个表只是约十条**已具名**
>    的映射，不是 `Effect.mkf` 的全集（`assets-clean/manifest.json` 里 Effect 资源
>    是 0..114，39 就在其中），缺名不构成缺音。两处都按上面订正。
>
> 复核命令：`python3 tools/disasm.py dump 0x4757e7 4 1` → `39 0 0 0`。

## D-MAGIC-3/4/10 订正（2026-09-16，外部审查 B-2 连带）

下面三条都建立在一个**错的图号换算**上：把代码里的立即数按 `imm / 2` 当图号。
正确换算是 **`index = (imm − 0xc) / 12`** —— `read_mkf` 返回的是 SMP 文件本体，
图素表第 0 项在文件偏移 `0xc`，每项 12 字节（`(0x18−0xc)/12 = 1`、`(0x6c−0xc)/12 = 8`）。
实测尺寸当场对得上：图 6/7/9/10 都是 **142×120**（锦缎框），图 3/4/5 是
**60×35 / 60×18 / 60×21**。

- **D-MAGIC-3**：「`frames` 字段的语义」那一节里用 `imm/2` 推出的图号表作废；
  按 `(imm−0xc)/12` 读，十二个功能的图标仍是 `option + 0x16`（22..34），
  结论不变，但推理链要换。
- **D-MAGIC-4**：「悬停第二张图索引进不存在的图」—— 按正确换算，悬停第二张的
  图号是 `option + 0x17`，落在 23..35；包里 22..34 存在，35 不存在，
  故只有**最后一个功能**的第二张缺图。原条目的号段需要按此重算。
- **D-MAGIC-10**：「女巫只画一处；图 1 在渲染路径里没被画到」—— 前半句对，
  但**图 9/10 被当成「女巫头部特写」是错的**：它们是 142×120 的**悬停弹窗框**。
  先前把它们画在女巫的 (`0x11e,0xd9`) 上，等于用一只锦缎框盖住女巫 ——
  这就是外部审查看到的「女巫消失 / 两只空框」。现已改为：女巫始终画**图 2**，
  「说话」那一拍只叠一张**嘴**（图 5，60×21）在 (`0x11e,0xdc`)；
  图 9/10 只用在悬停弹窗框（与功能名同点 `magicIconAt(option)`）。
  同时补上了原先缺的**第二拍**：第一拍图 1 落 `(0x8c,0xf1)` + 图 2 落 `(0x11e,0xd9)`
  + 结果图标落 `(0x146,0x128)`；第二拍图 2 挪到 `(0xb6,0x8e)` 并压上长条结果框(8)。
  框与字**同点**（`magicIconAt(option)`），先前字固定画在五芒星中心、
  落在框外约 107 px。

## D-MAGIC-6（近似）命中几何是**角度**，原版是**逐像素掩膜**

原版把 `Panel.mkf` **#19**（307200 字节，= 640×480 每像素一字节）读进
`[0x48c394]`，鼠标一动就查（VA 0x00432b50）：

```asm
; edx = lParam = (y << 16) | x
mov  eax, edx
shl  eax, 2
add  eax, edx
shl  eax, 7          ; (x + 5y) * 128
add  eax, ecx        ; + x
mov  al, byte [[0x48c394] + eax]
```

即 `表[x + 5y]`、行距 `0x80`。表里 **1..12 = 十二个功能**、**13 = 中间那块**、
0 = 不认。把 #19 摊成 640×480 之后量出来的几何：

| 量的是什么 | 值 |
|---|---|
| 圆心 | **(320, 238)**（楔形分界线两两求交） |
| 十二条中线 | **0°/30°/…/330°**，各占 ±15° |
| 外缘 | 最长的一条到 **r = 241**，最短的到 216（**手绘**，长短不一） |
| 中间那块 | **r < 118** 起就可能是楔形，13 号最大到 136/137 |

本模块用**圆心 + ±15° + 一个外半径 241** 去近似那张手绘掩膜：

- 外缘那 216..241 的参差**丢了**（画成扇形时比原版「胖」一点，
  大概在 r 216..241 这一圈里，原版有几处是空的）；
- 118..136 之间原版同时可能给 13 也可能给楔形，本模块一律按 118 切。

★ 若要逐像素等同：把 #19 的 307200 字节也解出来当资源用
（现在它**没进** `assets-clean` 的 manifest，`classify.ts` 把它当
`imageDataSize == 0` 的非图像资源跳过了）。那需要动 `assets-pipeline`，不在本卡范围。

## D-MAGIC-7（近似）图标位置与楔形中线**不是一回事**

`MAGIC_HOUSE_OPTIONS[k]` 的 (x,y) 是原版
`_rich4_magic_house_function_info`（VA 0x00475724，每项 16 字节）的 +8/+12，
悬停时画图标、写字都用它。但把十二个点对圆心 (320,238) 求角度：

```
24.9° 33.7° 20.2° 1.0° 336.7° 321.2° 203.3° 183.0° 156.5° 147.8° 157.0° 175.4°
```

——每个都落在某个 30° 边界的**附近（差 1..10°）**，而不是中线上。
即**图标摆位与命中扇区是两套独立的数**，各自照各自的抄，别互相校验。

## D-MAGIC-8（近似）转盘演出是**我们**加的

原版这一屏**没有转盘动画**：选项是玩家自己用鼠标点的（悬停高亮），
点了就 `PostMessage(0x200, ...)` 走「按下 → 抬起」那一支，
然后 `fcn_00431caa` 派发效果、`push 0x5dc`（1500ms）后 `Post_0402_Message` 退屏。

在 core 里玩家**一次也插不上手**（两个转盘都是 `rand()`），所以本模块的
「先转两圈、慢慢停在落点上、停 1.5 秒」是一段**替代的演出**：

- 位间隔 200ms 起、每位 +45ms（`MAGIC_SPIN_MS` / `MAGIC_SPIN_SLOW`）—— 数字是
  照「原版 100ms 定时器 + 隔一次动一下」定的，**不是**原版的转盘；
- 转两圈 = 24 位；
- 停稳后 `MAGIC_HOLD_MS = 1500` 关屏 —— **这一条有出处**（VA 0x004339b3 的 `push 0x5dc`）。

★ 若需求方要求「不转、直接显示结果」，把 `magicPlaybackStart` 的
`magicSpinSteps()` 改成 0 即可，其余不用动。

## D-MAGIC-9（**已修**，但记下取证过程）抠黑表第一版是猜的，漏了女巫与图标

**症状**（中央在真浏览器复现）：屏上有好几块黑矩形 —— 女巫立绘那块最大、
左上/右上几个功能图标、还有结果框，背后都拖着黑底，把五芒星与花纹盖掉了。

**原因**：原版 `Panel` 的 SMP 图背景是黑的，**靠贴图函数抠掉**。原版有**两支**：

| 函数 | 行为 | @source |
|---|---|---|
| `fcn_004563f5` | **不透明**拷贝（`rep movsd`，无判断）→ 0x455b3a | 0x004563f5 |
| `fcn_00456418` | **抠黑**：源像素 `or ax,ax / je` 为 0 就跳过 → 0x455c52 | 0x00456418 |
| `fcn_0045643d` | 带矩形参数的拷贝 | 0x0045643d |

判定只能**逐调用点**抄，不能靠「看图上黑多不多」—— 本模块第一版那张表是按
「哪些像框」猜的，于是漏了 2/9/10/22..34。现按调用点订正：

| 图 | 原版走哪支 | 抠黑 | 出处 |
|---|---|---|---|
| 0 底图 | `fcn_004563f5` | ✗ | 0x0043256d |
| 1 女巫（水晶球） | `fcn_00456418` | ✓ | 0x00432588 |
| **2 女巫（抬手）** | **`fcn_00456418`** | **✓** | 0x0043259c |
| 3/4/5 长条框 | `fcn_0045643d`（矩形） | ✗ | 0x00432894 起 |
| 6/7 锦缎框 | `fcn_00456418` | ✓ | 0x00432cc4 / 0x00432de6 |
| 8 长条结果框 | `fcn_004563f5` | ✗ | 0x00432a85 起 |
| 9/10 女巫头特写 | `fcn_00456418` | ✓ | 0x00432ae7 |
| 22..34 功能图标 | `fcn_00456418` | ✓ | 0x00432d0e / 0x00432dd4 |

★ **图 2 必须抠黑**这条还有一处**原版自相矛盾**：铺场那支走
`fcn_00456418`（VA 0x0043259c，抠黑），但「死神召唤」回调里同一张图那个位置
又走 `fcn_004563f5`（VA 0x0043355f，不透明）。本模块**一律抠黑**
（不抠就是一块黑矩形遮住底图）。

★ 教训：**「哪些图要抠黑」不能靠看图猜，要靠调用点**。图 2 有 43% 纯黑、
边界 89% 是黑，看起来「像个不透明的大方块」，实际是张透明精灵。

## D-MAGIC-10（近似）女巫只画一处；图 1 在渲染路径里没被画到

## D-MAGIC-11（近似）绘制顺序：底图 → 字框 → 结果字 → 女巫 → 图标

原版 `fcn_00432511` 的顺序是 **底图 → 长条框 → 女巫**，而中央字框（图 6，
