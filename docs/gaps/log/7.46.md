### 7.46 ★ 第 65 条（本轮）：拆屋**漏了一整条规则** —— 原版会「全场放人」，复刻判定为"表现层"

按修正后的工作单取 `0x0040dffa`（41 字节，0 个被调函数）。它很小，但**性质严重**：
复刻把它当成了表现层，而它写的是玩家字段。

#### (1) 差分：`tests/test_mutate_release.py` **7/7**

```asm
0040dffc  for edx in 0 .. [0x499114]-1:
0040e007      if whoPlays[edx] == 0: continue        ; 出局者跳过
0040e010      if [player+0x32] == 0: continue        ; 本来没被关
0040e019      [player+0x32] = 0x80                   ; 置「释放挂起」
```
★ 它是**一刀切**：**无参数、不查设施表** —— 拆掉任意一处旅馆/医院，
**全场所有**被关押的在场玩家一起被放出来。`0x80` 与其它阻塞计数器共用
「释放挂起」位（`rules/blocking.ts` 的 `RELEASE_PENDING`）。

**六个调用点**（原版自扫，全在 `mutate_land`/`mutate_facility` 里）：
`0x40ac33`（設施 mode 0 拆到 0 级）、`0x40ac4d`（設施 mode 1）、`0x40ac6c`（設施 mode 2）、
`0x40ae0d`（住宅 mode 0 拆到 0 级）、`0x40ae58`（住宅 mode 1 与 mode 2 共用）。

#### (2) 复刻侧：此前注释写反了

`cards/monster.ts` 与 `cards/land-cards.ts` 的注释都写着
「`0x40dffa` 是表现层的设施重建/刷新，core 无可落副作用」—— **错的**：
它写的是玩家字段 `+0x32`（复刻映射成 `blocking.inHotel`），是规则状态。

改动（全部落地，不是"记个待办"）：

| 文件 | 改动 |
|---|---|
| `rules/blocking.ts` | 新增 `releaseConfinedPlayers(players)`（差分语义 + 调用点注释） |
| `cards/monster.ts` | `MutateResult`/`FacilityMutateResult` 加 `releasesConfined`；六条返回按 mode 门控（mode 0 **只在归零时**、mode 1 无条件、mode 2 改了才放）；两个卡 handler 透传；旧注释订正 |
| `cards/land-cards.ts` | 两个設施 handler 透传 + 旧注释订正 |
| `cards/registry.ts` | 4 处卡效果（怪獸地/怪獸設/惡魔設/拆除設）→ `releaseConfinedPlayers` |
| `events/news-effects.ts` | 6 处（颱風 / 地震同名全拆 / raze 单挑，各含地與設施）→ 汇总后落到 `players` |
| `state/reduce.ts` | `fireMissile` 的直调 mutate 处按同样门控放人 |

> ⚠️ 一个容易做错的顺序问题：原版放人发生在**改记录那一刻**（`mutate` 内部），
> 而飛彈那支稍后还有「送医 3 天」。复刻按同序：**先放人、再送医** ——
> 若反过来，刚被放出来的人会立刻又被塞进医院，行为完全不同。

#### 诚实边界

- 差分只单调 `0x40dffa`；**六处门控**是从 `mutate_land`/`mutate_facility` 的
  反汇编读出来的（A 级），没有跑整条 mutate 调用链。
- `player+0x32` 的**字段语义仍未定**（PRD 记「忙碌/阻塞计数器」、`disasm.py` 记
  `days_in_hotel`、复刻映射成 `blocking.inHotel`）。本轮证明的是**行为**，
  没解决"它到底代表什么"。
- `0x40a4e1` 的作用域只有静态观察（写地图数组），**没有差分**。
