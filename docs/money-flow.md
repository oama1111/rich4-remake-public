# 钱的流向

大富翁 4 里的钱**不是只有一条路**。目前已确认三条，各有各的规则，
互相之间不能套用。

## 1. `pay_money`（VA 0x0041d2c6）—— 卡片与事件结算

实现：`packages/core/src/rules/payment.ts`

- 两级级联：一个口袋不够就把负数搬进另一个
- 两个口袋都空 → **削减实付额**（收款方只收到实付部分）并触发破产
- flags bit0 = 收款进现金，bit2 = 付款先扣存款
- 参与方编号：玩家下标 / `>100` 企业（下标 1 基）/ `-1` 公库

全 exe **只有 4 处**调用：

| 调用点 | 形式 | 用途 |
|---|---|---|
| 0x00442479 | `pay_money(cur, seller, price, 0)` | 购地卡 |
| 0x0040ec99 | `pay_money(i, cur, amt, 1)` | 其他玩家各付当前玩家 |
| 0x0040efd9 | `pay_money(cur, i, amt, 0)` | 当前玩家各付其他玩家 |
| 0x0040f076 | `pay_money(cur, -1, amt, 0)` | 付给公库 |

后三处同属一个事件结算函数，先 `call 0x440706(n)` 按编号取金额，
再遍历在场玩家（`[0x499114]` = 人数，跳过出局与自己）。

## 2. 落点消费 —— 就地 `cmp` + `sub`

实现：`packages/core/src/rules/purchase.ts`

买地、盖房、买设施**不走 pay_money**：

```asm
cmp ebp, dword [player + 0x1c]     ; 只与**现金**比较
jg  放弃                            ; 钱不够直接放弃
sub dword [player + 0x1c], ebp     ; 直接扣现金
```

五处消费点（0x004199c5 / 0x0041a132 / 0x0041a29f / 0x0041a34d / 0x0041a984）
结构完全一致，**都没有存款级联，也都不会触发破产**。

> 钱在银行里就是买不了地，必须先取出来。这是与 `pay_money` 的根本差别。

消费前还有一道 `call 0x0040fa61(player)` 的附身检查：
`god_info` 为 7（小衰神）、8（大衰神）、15（死神）时**禁止消费**。

## 3. 过路费 —— ★ **尚未定位**

这是目前最大的空白。已排除的可能与所用方法记录如下，**不要重复**：

### 已排除

- **不走 `pay_money`**：全部 4 处调用点如上，无一是收租。
- **不在落点结算函数（0x419750..0x41b100）里**：
  该区间内对 `cash`(+0x1c) 的写入只有 5 处 `sub`，全部以
  `[0x49910c]`（当前玩家）为目标，**没有任何一处给别人加钱**；
  对 `money_in_bank`(+0x20) 的引用全是 `add edx, [...]` 形式的**读取**
  （在算总资产），没有写入。
- **`calculate_land_toll`（真实入口 0x00419744，非 rich4-re 所记的 0x419750）
  只有一个调用者**：0x00417913，而那是**文本格式化**函数
  （`sprintf` 0x452793 / `strcpy` 0x457110），只用于显示地块信息面板。
- **0x0044fabc 不是收租**：它 `cmp ah, 0x23` 解析 `'#'`，是台词/对话框
  的文本显示函数（`#NNNN` 前缀是原版真实的格式码，不是注释）。
- **0x00428d55 一带不是收租**：那是**股票买入**
  （`[0x4971a0]` 持股数、`[0x4971a4]` float 均价，
  `新均价 = (旧股数×旧均价 + 本次成本) / 新股数`）。
  顺带直接证实了 rich4-re 错误 #6：`player_stock_info` 第二个字段
  确为 float 均价。

### 下一步建议

1. `python3 tools/disasm.py xref hostility` —— 收租必然抬高对地主的敌意，
   从敌意写入点反推收租函数。
2. 从移动/停步流程入手：找 `days_stopping`、`node_id` 的写入点所在函数，
   收租应在落点判定的**更早**阶段。
3. 注意收租的金额可能经由 `money_in_bank` 入账（`pay_money` 的默认行为
   就是收款进存款），所以别只盯着 `cash`。

> ⚠️ 线性反汇编在本 exe 上**会失步**（代码段夹杂数据），
> 曾因此漏掉 `pay_money` 自己对 cash 的写入。
> 一律用 `tools/disasm.py xref <字段名|地址>`，它按字节搜常量再逐点对齐。
