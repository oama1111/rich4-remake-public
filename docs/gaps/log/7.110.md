### 7.110 ★★ 第 127 条（本轮）：神明對過路費 `0x41d709` **进闸门**（差分 35/35）—— 签名订正 + 两个「patch 不生效」的坑

#### (1) 签名：第二参**不是**租金，是「要填进 `%s` 的文本」

`gods.md` §6b 早已订正过，但本轮用 `edx` 逐指令追踪**再次核实**，并把测试口径
改成正确签名：
**`0x41d709(付款方玩家下标, &填 %s 的文本, 原始租金)` → 返回调整后的租金（`eax`）**。

```asm
; @source 0x0041d709   （反汇编实测，非抄 remake）
0041d709  push ebx / push esi / sub esp,0x80
0041d711  mov edx, [esp+0x90]        ; arg2 = %s 的**文本**
0041d718  mov esi, [esp+0x94]        ; arg3 = **原始租金**
0041d71f  mov ebx, esi
0041d721  imul eax, [esp+0x8c], 0x68 ; arg1 = 付款方
0041d729  mov al, [eax+0x496ba7]     ; +0x3f = god_info
0041d72f  dec al / cmp al,5 / ja 0x41d79e
0041d73a  jmp dword [eax*4+0x41d6f1]
```

#### (2) 三条**机器次序**事实（由返回值直接实测，不靠读汇编）

| god | 分支 | toll=1000 | toll=999 | 结论 |
|---|---|---|---|---|
| 1 小財神 | `sar ebx,1` | 500 | **499** | 算术右移、向下取整 |
| 2 大財神 | `xor ebx,esi` | 0 | — | 归零（**不是** `mov ebx,0`，故 `ebx==esi` 的判据仍成立） |
| 3/4 福神 | 与「不改变」**同一地址** | 1000 | — | 对过路费无影响、也不弹提示 |
| 5 小窮神 | `sar ebx,1` **再** `add ebx,esi` | 1500 | **1498** | ★ 是 `toll + ⌊toll/2⌋`，**不是** `×1.5` 的浮点近似 |
| 6 大窮神 | `lea ebx,[esi+esi]` | 2000 | **1998** | 整数加倍；`toll=1e9 ⇒ 2e9` 不溢出 |

`god_info ∉ 1..6`（0、7、8、12、32、255）一律原样返回且**一次 `sprintf` 都不调**；
判据取址实测为 `player*0x68 + 0x496ba7`（用 `player=2` 反证不串位）。

#### (3) ★★ 两个「`patch()` 看起来生效、执行却是旧码」的坑（都记进测试注释）

1. **`__init__` 里打桩会被第一次 `reset()` 抹掉。** `patch(va,…)` 会把**命中段**
   的当前内容重拍进快照；但在 `__init__` 里第一次 `patch` 时该段尚未改过，
   重拍的仍是原始内容 ⇒ 紧接着 `call()` 开头的 `reset()` 把补丁还原。
   表现极具误导性：`read()` 明明读到补丁字节，执行却是原版代码。
   ⇒ **打桩一律写进 `setup()`**（`reset()` 之后、压栈之前执行）。
2. **同一实例里打过补丁后，先前翻译过的基本块仍跑旧码。** 实测：
   `patch(0x41D7B4, jmp)` 之后字节读出来是新值，执行却仍走旧分支，
   连 `UC_HOOK_CODE` 都只在**块首**触发、根本不报 `0x41D7B4`；
   `ctl_remove_cache`（`patch()` 内部已按段调用）在本 Unicorn 版本上不足以失效它。
   ⇒ **每个用例新建一个 `Emu()`**（实测一次构造 ≈ 23 ms，用例数十个，总开销可忽略）。
   ★ 这条也解释了此前若干「注入了却读到 0 / 改了却不变」的假象。

#### (4) 停址取「跳表汇合点」`0x41d79e`，绕开无法建模的表现层

`0x41d79e` 之后是 `0x41d7ac` 的 `sprintf("%d")` 和 `0x41d7c1` 的显示调用
（`0x440cac` → `0x44f9d8` → `0x44fa8f` 的 `call dword cs:[0x46228c]`）——
一整套 **Win32 文本渲染**：thunk 目标是未映射的 `0x624ce`，且 `0x44f9d8`
是变参格式化、栈清理与 C 约定不对应，替身桩会把栈搞歪（实测 `ret 0/4/…/0x1c`
七档全试、无一能平）。
而本函数的**唯一语义出口是 `0x41d7c9  mov eax,ebx`** ⇒ 用 `eval_block`
停在 `0x41d79e`（`ebx` 即最终金额），完全绕开该段。这是「如实跳过表现层、
不写假断言」的又一例（同 §7.107 的 `0x450f04`、§7.108 的状态 5 绘制链）。
