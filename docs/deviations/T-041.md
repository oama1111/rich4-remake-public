## D-MONTHLY-1（**结构性近似**）结算屏那一列的 x —— 表读不出，改用頒獎屏那张同构表

**原版**：

```asm
; loc_00439cd7 的循环，ebx = 玩家下标
movsx esi, word [edi + esi*2 + ref_00475918]   ; 0x00439cf7
; edi = 在场人数 × 8，esi = 玩家下标
```

按 `movsx` 的**操作数长度取比例**（4 倍），`edi + esi*2` 实际是
`在场人数×24 + 玩家下标×6` 字节 —— 也就是说这张表**每项只有 3 个 short**
（不是頒獎屏那边的 4 个），步长 6 字节。

★ 反推出来的 4 人局列首是 `{100, 240, 380, 60}`（每列步长 **120**），
与頒獎屏那张 `{60, 180, 300, 420}` 是**同一张 4 列网格换个起点** ——
实测 `0x475918` 的头 12 字节确实是 `14 00 00 00 0e 00 00 00 60 00 00 00`
（img20 @ x=96+4），"x 字段" 与推出来的公式**差 4**（`x = 60 + player*120`）。
值本身没人读得到，这里只记「公式对得上」这件事。

**问题**：`0x475918` 这一段在 exe 里读出来的不是坐标 —— 那 96 字节是
`4 大 富 翁 4 大 富 翁 …`（Big5 串，见 `rich4.asm` 的 `0x475918` 附近），
**不是一张 word 表**。也就是说该地址在加载后被**运行时覆写过**
（很可能就是那张 12 项的 x 表），静态反汇编里看不到真值。

**处置**：本模块改用**同一张 4 列网格**的另一支 —— 頒獎屏 `loc_0043849e`
的 `0x475918`（读出来是 `{60,180,300,420}`、1..4 人一步 **120**）。
两支在 4 人局里列间距完全一致，故版式不会漂。

| 症状 | 处置 |
|---|---|
| 结算屏列首 x 不是原版真值 | **接受**（`{60,180,300,420}`，与頒獎屏同网格）|
| 若将来能从存档/运行时 dump 到那张表 | 只需改 `MONTHLY_SEAT_X` 一处 |

## D-MONTHLY-2（**未解出**）頒獎屏 4 列头像是「叠在竖栏上」还是「各占一栏」

原版 `loc_0043849e`（VA 0x0043849e..0x00438518）那一段，先按**槽 0..3**
画 4 张窄板（图 11..14），再按**同一批槽 0..3** 画 4 张竖栏（图 15..18），
最后按**同一批槽 0..3** 画 4 张头像：

```asm
帧   = [0x475960 + 槽*24 + 槽*2]
图像 = 3×角色 + 47 + 帧
x    = {60,180,300,420}[槽]
y    = 0x14a − h[帧] + y[帧]           ; 0x14a = 330
```

四列 x 跨度 60..420、每张头像 42..66 宽，**互不重叠**；
但 y 都在 294 附近（三帧的 `height/y` 都是 `(72,36)`）。
把这一组常量喂进原版的 12 个头像图逐个核过，**四张确实会互相盖住**。

**处置**：照抄原版，不做改良。若日后拿到一张原版頒獎屏截图，
第一件要核的就是这 4 个头像的 y。

## D-MONTHLY-3（**有意补写**）`存款：` / `利息：` 两个标签

原版这一屏**不重画**这两个标签 —— 串 `0x464e56`（`存款：`）与
`0x464e90`（`利息：`）在结算是作为**参数**传给 `fcn_0044ec30` 的，
也就是「气泡 + 里面那行字」是一整块被贴上去的。

本模块**把两个标签自己写上去**（落点与串一致：气泡局部 `(0x2e, 0x84)` 与
`(0x2e, 0xe6)`），理由：资源 25 里那张「存款」气泡的下半是一片空白
（`assets-clean/Panel/0025_001.png` 逐张核过），不补写就是四个空行。

| 症状 | 处置 |
|---|---|
| 标签是客户端画的、不是图里的 | **接受**（位置与串一致）|

## D-MONTHLY-4（**订正**）頒獎屏状态 1 贴的那一小块 —— 是**裁切拷贝**，不是缩放

**先前（包括旧注释与一张草图）记的是**「把区域 `(24,70)-(261,480)` 缩放着
贴图 0」。

**复核后订正**：`loc_00437fff` 走的是 `fcn_0045643d`（VA 0x0045643d，转调
`draw_image_in_rect_ex`），参数序是
`(dst, src, x, y, x_move, y_move, init_copy_width, init_copy_height, use_draw_area)`：

```asm
push 0x19a   ; x_move
push 0xba    ; y_move
push 0x46    ; init_copy_width  = 70
push 0x18    ; init_copy_height = 24
push 0x46    ; y  = 70
push 0x18    ; x  = 24
```

即「把图 1 落在 `(70,24)` 处那块 **70×24** 原样盖到 `(24,70)`」——
`x_move`/`y_move` 才是后两个数，先前把它们当成目的地尺寸，**读反了**。

本模块按订正后的读法实现（`drawMonthlyScreen` 里那段 9 参 `drawImage`），
并用一张合成图目视核过：结算屏 + 四列竖栏（图 15..18）合起来就是一张
「四道光柱」的頒獎台，与 `Panel#25` 的图对得上。

## D-MONTHLY-5（**未接**）音效

原版这一屏有四处音效：

| 时机 | 原版调用 | @source |
|---|---|---|
| 进頒獎屏前 | `fcn_004549cf(9)` | 0x00439ecc |
| 頒獎屏每一步 | `play_sound_effect(0x475b17)` —— 表里第 0 项 = **0** | 0x004383c3 |
| 獲獎者 FLIC 前 | `fcn_00454304(帧)` | 0x00438fxx |
| 收尾 | `play_sound_effect(0x475b27)` —— 表里第 0 项 = **0** | 0x00438a78 尾 |

`fcn_004549cf(9)` 是 **BGM**（`rich4_media_music.asm:354`），本引擎的

本引擎的 `playEffect(0)` 没有已核过的语义。

**处置**：**一个音都不放** —— 按 T-037 立的规矩「宁可不响也不乱响」。

## D-MONTHLY-7（**有意不做**）「无人获奖」时的 `別灰心，再加油喔！`

原版在 `[0x48c42f] == 0xff` 时走状态 15（`loc_00438a31`）：
`fcn_0044ec30(图 0x30, 0xbe, 0x0a, 0, 0x14, 0x101010, 0)` 画一个**对话框**，
再 `fcn_0044ecb6` 放字符串 `別灰心，再加油喔！`（串 `0x464e26`）。

本模块**保留了那句串作为常量**（`MONTHLY_NO_AWARD`），但**没有画那个对话框**
—— 那个 `fcn_0044ec30` 用的是**图号 0x30 = 48**，而资源 25 里 48 是
「沙隆巴斯头像的帧 1」（66×72），显然不是它想要的那张；
说明 `fcn_0044ec30` 的第一个参数走的是**另一套资源**，不是 `[0x48c41c]`。
没有核清之前不照抄，故本模块在无人获奖时只把后四条详情按 `$0` / `0天` 画。

## 与卡片 `files` 一栏的差异

卡片写的是 `packages/core/src/state/reduce.ts`（「若 core 没有摘要，先加
`state.lastMonthly`」）。**实际不需要**：摘要全部可以从 `before → after`
的 diff 取到 ——

- 现金 / 存款 / 贷款 / 角色：取 `after`（`settleMonthlyBank` 已落地）；
- 利息：`after.moneyInBank − before.moneyInBank`，
  与规则侧 `applyMonthlyInterest`（`rules/monthly.ts`）同源；
- 本月收入 / 支出：直接取 `after.monthlyPaid` / `after.monthlyReceived`
  （原版在收尾才清零，`loc_00439ec6`，演出期间一直读得到）。

故**没有新建 `core/state/monthly-cue.ts`、也没有动 `core/index.ts`**
（这正是任务书允许的「优先在自己的 client 文件里用 diff」那一条）。
