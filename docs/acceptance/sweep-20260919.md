# 全屏幕扫描截图集（W-12）—— 2026-09-19

> 工具：[`tools/sweep-screens.js`](../tools/sweep-screens.js)（在页面里跑）+ [`tools/sweep-screens.sh`](../tools/sweep-screens.sh)（驱动、收集 console error、生成缩略图墙）。
> 产物：`.qa-tmp/sweep/`（**不入库**，`.gitignore` 已排除）+ 一页 `index.html` 缩略图墙。

## 1. 怎么跑（可复现）

```bash
pnpm dev                       # 另开一个终端；Vite 一般落 5173
bash tools/sweep-screens.sh    # 8 张地图 × 20 屏，约 6 分钟
open .qa-tmp/sweep/index.html  # 缩略图墙（按地图分组，打不开的屏标 ✗）
```

驱动对**每一扇浮窗都重新载入一次页面**再打开它 —— 不这么做会把上一扇（尤其魔法屋
那种没有 pending 的演出屏）当成下一扇截下来（实测踩过：第一版的「樂透」截出来是魔法屋）。

## 2. 实测结果（2026-09-19）

| 指标 | 值 |
|---|---|
| 截图张数 | **160** = 20 屏 × 8 张地图 |
| 钉住成功 | **160 / 160** |
| 打不开（`no-recipe` / `open-failed`） | **0** |
| 有 console error 的屏 | **0**（`browse console --errors` 对每一屏逐屏采集） |

20 屏 = 11 个 `main.ts` 的 `Screen`（`title / setup / options / saveload / lobby / aiSettings /
intro / assets / inventory / stock / game`）+ 9 个用现有出口打开得到的整屏：
`help`（工具列 #1）、`bigMap`（熱鍵 M）、`magic`（`__rich4.magicHouse()`）、
`lottery` / `minigame` / `eventBox` / `shop` / `bank` / `bail`（`__rich4.warp()` 到对应落点再 `settle`）。

逐屏状态与错误原文在 `.qa-tmp/sweep/summary.tsv` / `console.log`；缩略图墙按地图分组。

## 3. ⚠️ 覆盖缺口（**如实列出，没有拿别的屏顶替**）

`packages/client/src/screens.ts` 登记的 16 屏里，本轮**只截到 6 屏**
（`magic` / `eventBox` / `lottery` / `minigame` / `help` / `bigMap`）。
下面 10 屏**没有截到**，因为要构造它们的**中间态**，而现有 `__rich4` 出口
（`goto` / `toolbar` / `warp`+`settle` / `magicHouse`）都造不出来：

| 屏 | 它要的中间态 |
|---|---|
| `auction` | 一拍一拍进行中的竞拍（`pending.kind === 'auction'`，且 `screen.settling` 演出） |
| `shares` | 每月 15 日「上市公司分红」那一拍（`presenting`） |
| `monthly` | 月结 / 颁奖那一拍（`playback !== null`） |
| `lotteryDraw` | 樂透開獎演出（`active !== null`，随日期跨到开奖日） |
| `godSlot` | 神明附身那一刻的老虎机窗 |
| `wheel` | 旅館／購物中心的转盘（落在設施 type 1/2 上） |
| `research` | 落在**自己的研究所**上（`pending.kind === 'research'`） |
| `facilityPicker` | 在等级 0 的設施加蓋时点出「選設施類別」浮窗 |
| `stealPicker` | 搶奪卡拾取到人之后弹出的选择浮窗 |
| `board` | 棋盘那层子窗口 `ui.open`（要真的点开某一颗工具列钮走到那一步） |

这些屏**不是没实现**（都有单测与卡片），是**本工具缺构造它们的手段**。
两条可选路（留给下一轮，按需做）：
1. 给 `__rich4` 加一个 **DEV-only 的「直达某屏」出口**（像 `magicHouse()` 那样，一屏一个），
   本工具就能补满 16 × 8；
2. 或者把扫描改成「跟着一局长跑、哪一屏出现就抓一张」（像 `soak-browser.js` 那样驱动），
   代价是每张地图要跑很久、且抓到哪张带随机性。

★ 第 1 条要动产品代码（`main.ts` 的调试出口），**本任务按「不改产品代码」处理**，
只截现有出口能到的那 20 屏 —— 这也是为什么本节要把缺口一条条列出来。

## 4. 结论

- **能截的 20 屏 × 8 图全截到了，0 个未处理异常**（W-12 的验收口径）；
- `screens.ts` 里另外 10 屏**未截**，原因与补齐办法见 §3 —— 需要首席/需求方决定是否加调试出口；
