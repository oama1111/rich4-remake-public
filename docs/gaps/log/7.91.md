#### (2) ★★★ 黑卡尾部：「double 压栈、被调方只读低 32 位」—— **不是 0，是巨大的垃圾值**

PRD 早写了这条类型不匹配，但复刻侧一直据此认为「恒为 0 ⇒ 不落敌意」。本轮**真跑 `0x40df69`**
（不打桩）把它钉死了：

| 组合（旧价 100 → 99.7） | 写进关系值的数 |
|---|---|
| 持股 **10** | **1717986918** |
| 持股 3 | **−687194767**（负 ⇒ 关系值为 0 时被 `0x40df83` 提前返回，看不到）|
| 持股 100 | 0（恰好）|
| 价差取整数档（10.0）| 0 |
| 持股 0 | 整支跳过 |
| 循环上界 | `[0x499114]`（人数），不排除 `who_plays == 0` |

★ 关键细节：价差必须是 **`fround(旧价) − fround(现价)`**（两个价都存在状态里、是 float32），
再 `fstp dword` 舍一次 —— 直接拿两个 JS double 相减再 fround 会得到**另一个** delta
（100−99.7 的 double 差是 0.30000000000000004 ⇒ fround 成 0.30000001192092896，
而原版是 0.3000030517578125）。

**复刻侧已改**（`cards/swap-and-stock.ts` 的 `blackCardHostilityDeltas()` +
registry 的 24/25 分支把 `holdings` 接进 ctx）：照原样取 double 低 32 位（`Float64Array` → `Int32Array`）。
6 条单元用例 + 1 条 reduce 级集成用例钉住（数值全部取自上面那张表）。

#### (3) ★★★ 连带查出：**全引擎的卡片敌意被应用了两次**（真 bug，阻断级）

做黑卡的集成用例时发现实际写入值是模型的 **2 倍**：`cards/registry.ts` 尾部已经
`players = applyHostilityDeltas(players, hostilityDeltas)` 落过一次，而
`state/reduce.ts` 的 `playCard()` 又按 `r.hostilityDeltas` 落了第二次。

⇒ **梦遊卡、冬眠卡、陷害卡、查稅卡、黑卡**的敌意全部翻倍（敌意影响 AI 的「最敵對玩家」
判定与「敌意上升解除同盟」）。已修：`playCard` 直接用 `r.players`，并在
`use-card.test.ts` 加了一条回归用例（「只落一次」）。

> 为什么以前没暴露：卡片的单元测试都是**直接调 registry 的 `applyXxxCard`**（看 `deltas` 字段），
> 而 reduce 级的用例只断言现金/地产 —— 没有任何一条断言「走完整 `reduce` 之后关系值是多少」。
