那个扫描只用了 1000/1500/…/8000 这些**整齐**地价（都能被 5 整除），机制上是错的：

#### (4) ★★★ 顺带钉死一个**全局性**的浮点复刻要点：x87 的默认精度是 **double**

「double 压栈被当 int 读」那一族的低 32 位**取决于那个 double 的位型**，而原版算它的次序是
`fild A` → `(等级+2)/5` → `fmulp`，**每一步都舍成 double** —— 因为 x87 默认精度控制字是
`0x027F`（PC = 10b = **53 位**），不是 64 位扩展精度。

⇒ **照 asm 的次序在 JS double 里逐步算** 就与逐位相同；反过来"聪明地"合成一次除法会差 1 ulp：

| 写法 | 地价 3、等级 0 | 地价 1001、等级 2 |
|---|---|---|
| 逐步舍入（原版 = 本实现）| **858993460** | **+1717986919** |
| 精确乘积 ÷ 5 | 858993459 | +1717986918 |

复刻侧 `rules/auction.ts`（拍賣卡）与 `cards/buy-land.ts`（購地卡）都已按逐步舍入改正，
黑卡那条（`持股×价差÷200`）本来就是「一次除法」且与 x87 等价（乘法那步精确，不产生额外舍入）。
