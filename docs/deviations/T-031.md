## D-T031-1（**差在 core**）分红金额：原版**截断**、`companyDividends()` 四舍五入

**原版**（VA 0x0042bc89..0x0042bc9f，每个玩家那一格）：

```asm
0042bc90  fild  dword [eax + 0x28]        ; 该公司累积盈餘
0042bc93  fmul  dword [esp + ebx*4 + 0x80]; × 这一格的持股比例（单精度）
0042bc9a  call  0x457dbc                  ; ★ 取整
0042bc9f  fistp dword [esp + 0xa0]
```

`0x457dbc` 不是四舍五入 —— 它把 FPU 控制字的高字节写成 `0x1f`
（RC 两位 = 11b = **向零取整**）再 `frndint`：

```asm
00457dc5  mov  byte [esp + 1], 0x1f
00457dcd  frndint
```

**本引擎**：core 的 `companyDividends()`（`places/company.ts`）用
`Math.round(Math.fround(funds * ratio))` —— 是四舍五入。屏上的
`dividendText()` 再 `Math.trunc` 一次**不管用**，因为 core 交出来的已经是整数。

| 症状 | 处置 |
|---|---|
| 乘积小数 = .5 时，本引擎进账/显示比原版**多 1 元** | **未改**（差在 `@rich4/core`，不在 `packages/client`；本卡只动 client）|
| 屏上显示 | 照 core 的整数画（`dividendText`），不自作主张再还原 |

★ 要彻底修，改 `core/places/company.ts::companyDividends` 的 `Math.round` →
向零取整，并把 `packages/core/src/places/company.test.ts` 里对应的期望一起改。

## D-T031-3（**订正**）起播判据只有「日期跨到 15 日」——**不加**「确实发了红利」的闸

**原版**（VA 0x0041d080..0x0041d094）：

```asm
0041d080  mov  eax, dword [0x497160]   ; 今天（低字节 = 「日」）
0041d085  and  eax, 0xff
0041d08a  cmp  eax, 0xf                ; 15 日
0041d08d  jne  0x41d099
0041d08f  call 0x42ba97                ; ★ 本屏
0041d094  call 0x431712                ; 樂透開獎
```

`0x42ba97` 从进门一路到 `Wait_0402_Message`（VA 0x0042be43）之间**没有一个提前
返回**（整段只有 VA 0x0042becf 那一个 `ret`）：12 家盈餘全是 0、没人持股时，
原版**照样**把这张表贴出来（表上全是 0）。

⇒ 本模块的 `dividendDayCrossed(before, after)` 只认两件事：
① `after.day === DIVIDEND_DAY`；② `after.totalDays > before.totalDays`
（`advanceGameDay` 里 `inc dword [0x4990e4]` @source VA 0x0041cfab；「一輪一天」
见 VA 0x00418f93..0x0041902e）。**第二条是必要的**：`event()` 会被任何 action
叫到，同一个 15 日里的别的 action 不该重播。

★ 任务书里提到的「`companyFunds` 有减少 / 玩家现金有增加」那类闸**没有加**
—— 那是原版没有的东西（`C-FID-1/4` 不许改良）。任务书同时要求「判据自己取证」，
证据就是上面这段汇编。

## D-T031-4（**已修正**）本屏与樂透開獎屏谁先演

原版是**先分红屏、后開獎**（VA 0x0041d08f 在 0x0041d094 之前），而两屏都在
同一个 action 里触发（都是 `after.day === 15 && totalDays` 变了）。

**两处都已修好**：

1. **登记序**：`client/screens.ts` 里 `sharesScreen` 挪到 `lotteryDrawScreen`
   **前面**（`active()` 为真的第一屏接管整屏 ⇒ 顺序与原版一致）。
2. **每帧 tick 的范围**（中央在 `main.ts` 里根治，2026-09-15）：
   ```ts
   const overlay = activeUiScreen();
   if (overlay !== null) overlay.tick?.(uiEnv());
   ```
   —— **只有接管整屏的那一屏收 `tick`**。每一屏的「起播」都走 `event()`
   （`main.ts` 在 state 变化时统一派），`tick` 只推进**自己正在播的那一段**。
   ⇒ 分红屏占屏那 3 秒里，開獎屏**不会再**在背后偷跑；本屏收掉后開獎从头演。

★ 本模块 `tick` 里的「不在对局里就不推进、也不空转」与「真正上屏那一帧才起算
计时」（`shownAt`）留作保险，不再依赖 tick 的派发范围。

## D-T031-5（**有意不做**）键盘关不掉这一屏

原版窗口过程 `fcn_0042b3eb` 的消息分派里只有 `0x202`/`0x205`（抬手）、
`0x401`、`0xf`（WM_PAINT）、`0x113`（WM_TIMER），**没有 `0x100`（WM_KEYDOWN）**
—— 键盘落到 VA 0x0042b580 的 DefWindowProc。所以本屏**不实现 `hotkey`**。

| 症状 | 处置 |
|---|---|
| 演出期间按熱鍵会透到 `main.ts` 的通用熱鍵那一路 | **接受**（与 T-041 月結屏同一处理：那屏的窗口过程有 `0x101`，本引擎同样没接）|

## D-T031-6（**有意忽略**）自动收屏不看「程序在前台」

原版 WM_TIMER 那一支（VA 0x0042b4db）先过一道
`cmp byte [0x46cb01], 0 / je`。`0x46cb01` 是 **WM_ACTIVATEAPP** 的「本程序在
前台」标志（写它的地方 VA 0x00401a93 `mov byte [0x46cb01], 1` /
VA 0x00401aab `mov byte [0x46cb01], dl`，读的是 WM_ACTIVATEAPP 的 wParam）。
⇒ 窗口不在前台时**不计时**。

网页版没有「程序是否前台」这个概念，`SHARES_AUTO_CLOSE_MS = 3 × 1000`
**不设**这条闸。

## D-T031-7（**已按 exe 修正**）版面：一家公司**一行**、一位玩家**一列**

2026-09-15 逐声核过 `fcn_0042ba97` 的每一个 `push` 后重排。先把参数序定死：
`fcn_0044fabc` 是 `(chunk, str, x, y, flag)`，cdecl 逆序入栈 ⇒ 汇编里的
`push` 次序是 **flag, y, x, str**。用三处已知量交叉验证：
① 标题 `push 2; push 0x19; push 0x128` + 7 个 28px 大字 = 居中合理，反过来
（x=0x19）会跑出左边框；
② `本月盈餘`（串 `0x464103`）`push 2; push 0x58; push 0x21e` = 正中于 (542, 88)
—— 正好在表头那一带、盈餘那一列的上方；
③ 玩家名那一圈 `push 2; push 0x58; push edi`，`edi` 从 0xa0 起每列 +0x62
—— 纵向固定、横向递增，确定「第 3 个 push 是 x、第 4 个是 y」。

| 项 | 改前 | **exe 真值（现已照此实现）** | @source |
|---|---|---|---|
| 行 / 列 | 「一家公司一列」，行距 `0x62` | ★ **一家公司一行，行距 `0x18 = 24`**；玩家才是一列，列距 `0x62 = 98` | 行距 VA 0x0042bd2d `lea edi,[esi+0x18]` / 0x0042bd30 `mov [esp+0xa8],edi`；列距 VA 0x0042bbad / 0x0042bcea / 0x0042be3d `add edi,0x62` |
| `人名` 表头 | (0x52, 0x12) flag 6 | **(0x68, 0x52)** flag 6 | VA 0x0042bb28 `push 6 / 0x52 / 0x68` |
| `公司` 表头 | (0x5e, 0x12) flag 5 | **(0x12, 0x5e)** flag 5 | VA 0x0042bb44 `push 5 / 0x5e / 0x12` |
| `本月盈餘` 表头 | **没画** | **(0x21e, 0x58)** flag 2 | VA 0x0042bbb3 `push 2 / 0x58 / 0x21e`；串 0x464103 |
| 「自留股數」列 | `SHARES_COL.value = 0x47`（自定）| **原版没有这一列**，已删 | 整段无 `push 0x47`、也没读 `commercial+0x30` |
| 各玩家**每格分红** | `playerColumnX(p)` = 0xa0+0x62p | **(0xc6 + 0x62p)** flag 6 | VA 0x0042bc70 `mov edi,0xc6` / 0x0042bcea `add edi,0x62` |
| 各玩家**合计** | (0x23c, 0x74 + 0x18p) | **(0xc6 + 0x62p, 0x194)** flag 6 | VA 0x0042bdef..0x0042be35 `push 6 / 0x194` |
| 字号颜色 | 表身白字、有企业时青字 `0xf0f0` | **12 号与 16 号都是近黑 `0x101010`**（标题才是白 `0xf0f0f0`）| VA 0x0042bb20 `create_font(0xc,0x101010,0,2,1)` / VA 0x0042bb6d `create_font(0x10,0x101010,0,2,1)` / VA 0x0042baec 标题 |
| 零值 | 跳过不画（改良）| **`0` 也画** —— `format_int` 对 0 给 `"0"` | VA 0x0042bcb3 / 0x0042bd00 / 0x0042be17 `call 0x452793`；VA 0x00457d10 是 do-while，除一次写一位 |
| 每行的「盈餘合计」| 各玩家分红之和 | **`company[+0x28]` 本身** | VA 0x0042bcf7 `mov ebx,[eax+0x28]` |

对得上、没动的几处：标题 (0x128,0x19) flag 2；公司名 (0x3e, rowY) flag 2
@VA 0x0042bda1；盈餘合计的列 (0x23c, rowY) flag 6 @VA 0x0042bd12；玩家名
(0xa0 + 0x62p, 0x58) flag 2 @VA 0x0042bb77；行首 y = 0x74 @VA 0x0042bbfa。

几何用例已按上表同步重写（`shares-screen.test.ts` 的「几何」与「画出来」两组），
并补了两条：`0` 被画出来、公司名/各玩家数额/合计各自的落点。

## 与卡片 `source` 一栏的差异（本次订正的实际动作）

卡片 `docs/tasks/cards.yaml` 的 T-031 写着 `source: "Panel.mkf #76；pending{buyShares}"`、
`output: "dispatch(buyShares{shares})"`、算法「买股份走 AmountPage」。**与 exe 不符**：

- `Panel.mkf` #76 那一屏的入口是 **VA 0x0041d08f**（每月 15 日的分红演出）；
- `buyShares` 那条路**没有整屏** —— 訊息框 + 填数窗
  （VA 0x0041d24d / 0x0041d25b / 0x0041d281），题面与 AmountPage 在
  `interactions.ts` 的 `case 'buyShares'`。

本次改动（2026-09-15 收尾，三轮）：

1. `shares-screen.ts` 的 `active()` 改成 `env.screen === 'game' && presenting`；
   新增 `dividendDayCrossed()` + `event()` 起播（判据见 `D-T031-3`）；
2. **删掉** `pending{buyShares}` 那条接管路径与为它写的填数页
   （`sharesAmountUi` / `hitSharesPage` / `toDialogSpace` 那套 / `amountDialog` /
   `openAmount` / `closeAmount` / `onPageHit` / `pageHitOf` / `press` /
   `SharesUiState`）；
3. 收屏照原版：`up`（`0x202`/`0x205` 抬手）+ 到点自动收屏
   （`SHARES_AUTO_CLOSE_MS`）；
4. **版面按 exe 重做**（见 `D-T031-7`）：行/列搞反、两个角落表头、缺 `本月盈餘`、
   自加的「自留股數」列、玩家数额/合计的落点、字色、零值、盈餘合计的取数；
5. `screens.ts` 里把 `sharesScreen` 挪到 `lotteryDrawScreen` 前面（见 `D-T031-4`）；
6. **删掉**原版没有的「董事长那一格蓝底」与它带的一串数据
   （见 `D-T031-8`）。

卡片 T-031 的 `notes` 已按需求方要求改成与实现一致；`title` / `source` / `input` /
`output` / `algorithm` / `tests` 几栏**仍是旧读法**，待需求方一并订正（已在 `notes`
