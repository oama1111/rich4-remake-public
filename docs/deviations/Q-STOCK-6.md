## 〇、需求方报的现象与根因

> 「股市模块除了那几个蓝色的股票以外，其他股票点击查看【上市公司】资讯跳出的弹窗是错误的」
> （「蓝色的股票」= 股名是青色 / `listed` 的那几支）

原实现（`stock-detail.ts` 的 `stockDetailFrom`）**无条件**按「有上市公司」那套版式摊卡：

```ts
const comm = stock.commercialIndex;              // ★ 0 = 这支股票没有上市公司
const funds = state.companyFunds[comm] ?? 0;     // ← 企业表是 1 基的，读了第 0 格
const profit = state.companyProfit[comm] ?? 0;
const owner = state.commercialOwners[comm]?.owner ?? 0;
...
icon: commType === null ? 0 : iconImageOf(...)   // ← 图 0 = 资源 75 的 640×480 整屏页
```

于是未上市的股票会：① 打出企业表第 0 格的垃圾数字；② 在 (50,107) 贴一张
**640×480 的整屏页**（资源 75 的图 0 是行情页），把整张卡盖掉 —— 这就是看到的「弹窗错误」。

### 4.1 Q-STOCK-6-a　底椭圆：**画**，而且就画在扇下面 —— **已落地**

- **条件**：`0 < r < 1` 那一支**无条件**画（分叉之后第一条绘制指令，没有任何判断）。
- **矩形**：`Ellipse(dc,414,343,591,401)` —— 就是 `box`。扇的 bounding box 是
  `(414,336,591,394)` = `topBox`：**同尺寸、只差 7px 纵向平移**（502.5,372 对 502.5,365）。
- **层次**：在两次 `Pie` **之前**、在黑笔选中之后 → 被两段扇盖住，只在下缘露出
  **处处正好 7px 厚**的一条月牙（就是那个「厚度」）。上一轮「只在下缘露 ~7px、无法目视核对」
  的前半句对，后半句不成立 —— 7px 的月牙在 640×480 的卡上是看得见的，而且见 4.2 还会变黑。
- **落码**：`drawPie` 的 `ellipsePath(box); fillStroke(rest)`（`rest` = `#0000d0` = `0xd00000`）。
- **顺带补的描边**：原版这一步的笔是黑 1px（VA 见 4.0 第 0 行），`Ellipse` 与 `Pie`
  **都会描边**，所以两个椭圆各有一圈黑线、两段扇的路径自带两条黑半径。本引擎原来
  只描了外框一次 ⇒ 月牙的内边界没有黑线，新加的蓝月牙会和蓝色的「其余」扇连成一片。
  本轮把「填 + 描」绑在一起（`fillStroke`），三支一致。
- **观测差别**：`0 < r < 1` 的饼在下缘多出 7px 厚的一条深蓝月牙（原来没有）；
  盘内多出两条黑半径线与那圈内黑边（原来只有最外那圈）。
  两侧那两道 7px 端帽竖线原来就画了，没动。

### 4.2 Q-STOCK-6-b　`FloodFill(dc,589,374,0)`：**能读出来，已落地**

上一轮说「GDI 语义静态读不出」——其实种子像素的颜色完全由本函数前面几步决定，可以读：

- **填哪块**：`FloodFill(hdc,x,y,color)` 从种子起、在**与种子同色**的连通区里填 `color`，
  碰到异色像素就停。种子 (589,374) 与两椭圆的关系：
  `((589−502.5)/88.5)² + ((374−372)/29)² = 0.960 < 1` → 在**底椭圆 `box` 内**；
  `((589−502.5)/88.5)² + ((374−365)/29)² = 1.052 > 1` → 在**扇那张 `topBox` 外**
  ⇒ 种子正好落在 4.1 那条月牙上（月牙在 x=589 处的竖直厚度 = 371.1…378.1，种子 y=374 在其中）。
- **边界**：月牙的两条边都是黑（`Ellipse` @0x0042a542 与两次 `Pie` 的黑描边），
  所以填出来的就是**这条月牙**；`0xd00000` 底盘是它唯一的底色 ⇒ 种子色 = 深蓝。
- **为什么还要 `xend < 589`**：第 8 步那道 7px 竖线画在 `x = xend`，而月牙在任意 x 处
  正好从 `topBox` 下弧到 `box` 下弧 = 7px 高 ⇒ **竖线正好把月牙切穿成左右两半**。
  种子在最右端，所以真正被涂黑的是**竖线右边那一截**；闸 `xend < 589` 就是保证种子
  在竖线右边（`xend ≥ 589` 时种子落在竖线上或左边，原版干脆跳过）。
  竖线的存在条件（第 8 步 `yend ≥ 365` ⟺ `r ≥ 0.25`）在 FloodFill 这两道闸
  （`r > 0.25`）成立时**必定成立**，除了 `r > 0.75` 那一段 —— 那时端点跑到上班、
  没有竖线，整条月牙连通 ⇒ **整条一起变黑**。
- **颜色 0 是什么**：本屏所有颜色都是显式 `COLORREF`（`0xd00000` / `0xd0` / `0xffffff`），
  这里传 `0` 就是**纯黑**，不是什么透明（GDI 也没有「透明填充」）。
- **落码**：`drawPie` 的 ④ —— `crescentPath(0, capped ? acos((xend−502)/88) : π)` 后填 `#000000`，
  其中 `capped = pieEnd(ratio).y >= 365`（= 有没有那道竖线，和 exe 同一条件）。
  月牙本身用两个「半椭圆弧」拼（`box ∖ topBox`），不需要 DC 上的位图内容。
- **观测差别**：`ratio` 落在 **(0.274, 0.75]** 时，月牙从端点竖线到最右那一截由深蓝变黑
  （`ratio=0.5` 时正好是右半边）；`ratio > 0.75` 时整条月牙变黑；`ratio ≤ 0.274` 仍是深蓝。
- **1px 级说明**：GDI 的 flood 是像素级判定，落码按「`x ≥ xend` 的月牙」解析地填；
  与真 GDI 在边界那 1px 上可能差一格。种子色与连通区结论本身是确定的。

### 4.4 Q-STOCK-6-d　均价全空：原版打的是 **`-nan`**（不是 0）—— 已落地

- **算出来是 NaN**：週/月均价都是 `fild 计数`（@0x0042a194 / @0x0042a245）后
  `fdivr 求和`（@0x0042a19b / @0x0042a24c）；计数 0 时是 `0/0` → x87
  **QNaN indefinite**（`0xFFC00000`，**符号位为 1**），
  `fst dword`（单精度）→ `fstp qword`（双精度 `0xFFF8000000000000`）。
- **那个串是什么（这才是本轮取到的证）**：`_libc_sprintf`(0x457110) → 0x458db5 →
  0x45ae76（格式化引擎）→ `%f` 走 0x45b8a3 → 0x45b554 → **`call dword [0x4895a8]`**。
  `[0x4895a8]` 的初值是 **0x45c4fb**（一份桩：`push 1 / push 0x46c958`，
  串 0x46c958 = `"Floating-point support not loaded"`），
  被 FP 支持初始化入口 **0x459ce1** 改成 **0x45c3b2**（0x459cec `mov [0x4895a8],edx`、
  0x459cf2 `mov [0x4895ac],ebx`；0x459ce1 这个地址挂在 0x4898d8 那组初始化表里）。
- **真 `_cvt` 0x45c3b2**：`fld qword` / `fstp xword` 成 80 位 → 0x45d4b6。
  0x45d4b6 先提符号（0x0045d4f9 `test byte [ebp-0x3f],0x80` → `[esi+0x14] = −1`），
  再 `call 0x45eec4` 分类，然后 `jmp dword [eax*4 + 0x45d4a2]`：
  - 指数 0x7fff 且尾数 ≠ `0x8000000000000000` → **2** → **0x45d55d 写 `'n','a','n'`**（长度 3）
  - 指数 0x7fff 且尾数 == `0x8000000000000000` → 3 → 0x45d57b 写 `'i','n','f'`
  - 0x0045c48b 起：符号为负就在**串首**补 `0x2d` = `'-'`（0x45b61e 开头的 0x45b632 已把下标清 0）。
- ⇒ `sprintf("%.1f" | "%.2f" | "%.0f", 0/0)` = **`-nan`**（全小写、带负号）。精度不影响
  （NaN 那一支直接写死 3 个字符）。全 exe 里 `#INF` / `#IND` / `NaN` / `nan` 这些字面量
  **0 命中**（所以 `-1.#IND` 那套是 MSVC 的，不是这一版的）。
- **落码**：`recentAverage` 在 `n === 0` 时返回 `NaN`（不再收口成 0），
  数值格走新的 `fixedOrNan(v, dec)` → `'-nan'`；单测钉住。
- **观测差别**：只有「历史一格都没写过」时（开局第一天那一支）週/月均价两格
  由原来的 `0.00` / `0.0` 变成 `-nan` —— 与原版一致。真实对局里其余时候看不出。

### 4.5 顺带修掉：`r == 0` / `r ≥ 1` 两支的**颜色原来记反了**

- 取证见 4.0 尾巴：`r == 0` → `push 0xd00000`（**深蓝**）；`r ≥ 1` → `push 0xd0`（**深红**）。
  与「自己那一份 = 深红」自洽：一份都没有时整块是别人的颜色，全归自己时整块是自己的颜色。
- 本引擎原来 `ratio === 0` 画 `mine`（红）、`else` 画 `rest`（蓝），**正好相反**；
  且 `0 < r < 1` 那支的两段扇颜色是对的（自己那份红、其余蓝）—— 因为上一轮把
  COLORREF 当成 `#rrggbb` 读、名称与颜色一起错，扇那一支两处错正好抵消，退化两支没有抵消。
- **落码**：`drawPie` 两支对调；单测钉住「r==0 两个椭圆都是 `rest`、r≥1 都是 `mine`」。
- **观测差别**：玩家**没有**某支股票时，那张卡上的饼由整块深红变回原版的整块深蓝；
  持股 ≥ 10000 时由深蓝变回深红。
