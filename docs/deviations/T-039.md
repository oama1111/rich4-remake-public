# T-039 旅館 / 購物中心轉盤 —— 有意偏離與未解出的假設

> 只记与「1:1 复刻」有关、且**故意和原版不一样**、或**没解出来靠近似**的地方。
> 反汇编出处都写了 VA，复核命令：`python3 tools/disasm.py va 0xXXXXXX`。
>
> 本屏的全部出处（两个函数都在 `rich4-re/asm/rich4.asm`）：
> **窗口过程 `fcn_0043f7c6`**（VA 0x0043f7c6，真人与 AI 共用同一支）、

> 由 0x0041a458（旅館 `push 1`）/ 0x0041a4b4（購物中心 `push 2`）两处 `call` 调起）。

>   **回放演出**，与 `magic-screen.ts` 同一套路。

> ★ 素材**认到了**（不是占位）：四个转盘 = `Panel.mkf` 资源 `(转盘 & 3) + 0x44`
>   = 68/69/70/71（VA 0x0044093a），每个资源 14 张图：

>   逐张目视核过：图 2 的「1」在正上方、图 5 的「4」在正上方，与
>   `WHEEL_TABLE[1]`（旅館：槽 2 → 1、槽 5 → 4、槽 7 → 3、槽 10 → 2）对得上。
>   对话气泡 = `Data.mkf` 资源 **517（0x205）图 6**（271×199，锚点 (127,92)）。

## D-WHEEL-1（取證，非近似）起點槽從 `before.rngState` 反推

原版 `[0x48c50c] = rand() % 12`（VA 0x0043f7da），而这个随机数**没有进 state**。
本引擎不去改 core（`reduce.ts` 是禁改文件），改成**重放随机数**：

```ts
const rng = new WatcomRng(before.rngState);
const start = rng.next() % WHEEL_SLOTS;   // ← 与 core 的 settleFacility 第一次 rand() 同一个
const stop = firstFilledSlot(wheel, start); // ← 与 core 的 spinWheel() 同一条走法
```

成立的前提是「这条路上唯一的随机数消耗就是转盘那一次」。逐条核过
`settleFacility()`（VA 0x0041a370 起）：`level`→`type`→`tollExemption` 三段
**都不取随机数**，第一次 `rng.next()` 就是 `spinWheel()`。
单测（`wheel-screen.test.ts`）把这条钉住：**反推出来的点数 == core 真的住的天数 /
真的收的那笔费 ÷ 单价**，而且 `WHEEL_TABLE[wheel][firstFilledSlot(...)]`
对四个盘 × 十二个起点全部等于 `spinWheel()`。

| 症状 | 处置 |
|---|---|
| 原版真人那一路按一下就停、格数取决于点击时机 | **接受**（D-003：结果由 core 定），起点一律按「第一次 `rand()`」推 |
| 若将来 `settle` 在转盘之前新增了随机数消耗 | 起点会偏一格 → **必须在 core 里落一个 `lastWheel`**（本卡不做） |

## D-WHEEL-2（**已銷案 2026-09-16**）整屏画在**纯黑**上，原版是画在棋盘上

原版的转盘**没有自己的底图**：它只把屏幕 (0,40)-(440,480) 那块存进离屏
（`fcn_00451e7e`，VA 0x00440988），然后在**棋盘之上**画圆盘/天使/气泡，
退出时把那块贴回去。也就是说游玩时**棋盘一直看得见**。

本引擎的契约（`ui-screen.ts`）是「`active()` 为真的第一屏**接管整屏**、
棋盘与侧栏一概不画」，而 `UiScreenEnv` 里**没有**棋盘那张画布 ——
本模块拿不到它，于是屏上是黑底 + 四个部件。

| 症状 | 处置 |
|---|---|
| 底下的棋盘没了 | **接受**（契约限制）；要修得给 `UiScreenEnv` 加一个「画棋盘」的出口，那是契约改动，不在本卡范围 |

## ✅ D-WHEEL-3（**前提被推翻** · 2026-09-16）「動畫過程」**管不到**这一屏

先前写：「原版这一屏受 RICH4.CFG offset 1 `animation` 管辖，本引擎够不到」。
**逐字节核 exe 后不成立**：转盘的入口 `fcn_0044090e`（VA 0x0044090e）与窗口过程
`fcn_0043f7c6`（VA 0x0043f7c6）**一处都没读** `[0x497159]`：

```
python3 tools/disasm.py va 0x0043f7c6 900 | grep 497159   # 无输出
grep -n 497159 rich4-re/asm/*.asm | grep -c rich4.asm     # 只有 16883 / 17107（銀行月結算屏）
```

状态机 `ebx`（1 = 快转 → 2 = 减速 → …）的推进只受两个判据影响：

- `wheel-screen.ts` 的 `wheelFrameSequence(start, stop, animate = false)` 那一支
  （一帧直接落点）在原版里**没有对应调用点** —— 它是本引擎自带的出口，
  留着备用，**不要**拿 `env.animation` 去接它（那会凭空造出原版没有的行为）。
- 全 exe 的 `[0x497159]` 读点清单、以及真正受管辖的屏，
  另见 **`docs/deviations/Q-ANIM-1.md`**。

## D-WHEEL-4（近似）这一趟转几格是**我们**定的

原版转多少格**取决于点击时机**（真人：快转段一直转到松手；AI：快转 0x28 帧
之后自动进减速段），所以不可复现（D-003）。本引擎固定：

- **4 圈 + 起点到落点的距离**（`WHEEL_REVOLUTIONS`，VA 量级见下）；
- 减速段**贴在尾巴上**：最后 `3 × (5−1) = 12` 格逐档变慢（延迟 2,3,4,5，每档 3 格，
  @source 0x0043f9c7 起），保证「最后几格一定是最慢那一档」；
- 快转段一格 **36ms**（@source 0x0043faab `cmp esi, 0x24 / jb`，这是原版每帧的下限），
  减速段最多 5 倍 = 180ms；
- 停稳后再等 **0x28 = 40 帧 ≈ 1.44s** 关屏（@source 0x0043fa19）。

原版自动那一路是 40 帧快转（≡ 3⅓ 圈）+ 减速 12 格 + 等非空格，
本引擎的 4 圈多落在同一个量级（整段 ≈ 3s + 1.44s）。
`stop === start` 时仍走满一圈（倍数就是起点那格，不能站着不动）。

## D-WHEEL-5（**已接 2026-09-16**）一个音都不放

原版是**循环**音效：进场 `_rich4_play_sound_effect(1, &info)`（VA 0x0043f80d，
`info` = `0x475d4c`，第一格 dword = **52 = 0x34**），落地那一下
`fcn_004542e9(&info)`（VA 0x0043fa0a），退屏前释放（VA 0x00440a85）。

本模块不放，两条理由：

1. `UiScreenEnv.playEffect(id)` 只有**一次性**出口，没有「停」——照原版播一个
   循环音就会一直响到采样结束；
2. `ARCHIVES`（`client/assets.ts`）里**根本没有** `Effect.mkf`，`sound.play()` 取不到包。

★ 建议：中央接音效时，先确认 `Effect.mkf` 的 52 号是什么、再决定是否加循环出口。

## D-WHEEL-6（近似）真人点一下 = **直接进减速段**

原版（@source 0x0043fa66 起）在 `WM_LBUTTONUP`(0x202) / `WM_RBUTTONUP`(0x205) /
`WM_KEYDOWN`(0x101) 时，若当前玩家 `whoPlays == 1`（真人）且 `+0x37`（梦遊）为 0，
就把状态机 **1→2**（快转段结束、开始减速）或 **5→6**（停好之后提早关屏）。

本引擎的落点已由 core 定死，所以「按一下」= **把步数直接跳到减速段起点**，
照样停在同一个落点上；停好之后再点一下就提早关屏（这一条与原版一致）。
AI 与梦遊中的玩家点了不算（`wheelClickable`，照原版的 `whoPlays` / `+0x37` 判据）。

## ★ 修订（2026-09-16）：D-WHEEL-2 銷案、D-WHEEL-5 已接、D-WHEEL-4 复核

> 只改**状态**，前面几节的取证过程与 VA 原样保留。

### D-WHEEL-2 → **銷案**

「契約不許改，故只剩黑底」这条**已经不成立**：`UiScreen` 早就有
`windowed?: boolean`（`ui-screen.ts:83`，大地圖彈窗就是这一支，见
`big-map-screen.ts:222`）。原版那一屏本来就是把 (0,40)-(440,480) 存进离屏
（`fcn_00451e7e`，VA 0x00440988）后**画在棋盘之上**，退出时贴回去 —— 那正是
`windowed` 的语义。修法只有**一行**：

```ts
export const wheelScreen: UiScreen = {
  id: 'wheel',
  windowed: true,   // ★ 新增
  ...
};
```

`main.ts` 见到 `windowed === true` 会先照常画一整帧棋盘（`drawGameStage()`）再叠
本屏，于是**棋盘与右侧栏全程可见**，与原版一致。那塊矩形 `LAYOUT.board` =
`(0,40)-(440,480)`，圆盘 (220,320)、天使 (265,230)、气泡 (220,140) 全在它里面，
所以浮窗不会把棋盘画到不该画的地方。单测：`wheel-screen.test.ts` 断言
`wheelScreen.windowed === true`。

### D-WHEEL-5 → **已接**

先前的两条理由都是**过时/半过时**的：

1. `ARCHIVES`（`client/assets.ts:17`）里**有** `Effect.mkf`，`main.ts` 的
   `SoundPlayer.addArchive` 真的装了它；
2. `SoundPlayer.stop(archive, resource)` 早就有了（`audio.ts:136`），
   `play()` 还会自动停掉同一路的上一个 voice（`audio.ts:86`）。
   真正缺的只是**循环标志**。

**已补的出口**（契约改动）：

| 出口 | 语义 |
|---|---|
| `playEffect(id: number, loop?: boolean)` | `loop = true` → `AudioBufferSourceNode.loop = true`（原版 `flags = 1` = `DSBPLAY_LOOPING`）|
| `stopEffect(id: number)` | 停掉那一路（原版 `fcn_004542e9` = `IDirectSoundBuffer::Stop`）|

**本屏的调用点**（VA 全部复核过）：

| 时机 | 调用 | @source |
|---|---|---|
| 起播 | `playEffect(52, true)` | 0x0043f80d `_rich4_play_sound_effect(flags=1, &0x475d4c)`；`ebx` 在函数头就是 1、`[0x475d4c] = 52` |
| 落地 | `stopEffect(52)` | 0x0043fa0a `fcn_004542e9(&0x475d4c)` |
| 落地 | `playEffect(1)` | 0x0043f8a0 `_rich4_play_sound_effect(0, ref_00482322)`；`[0x482322] = 1` |
| 退屏 | `stopEffect` 已由落地那一拍收掉 | 0x00440a85 `fcn_00454240`（释放 buffer，浏览器里不需要）|

★ **为什么必须循环**：`assets-clean/Effect/0052.wav` 只有 **2086 B ≈ 0.089 s**，
一次性播出就只是一声「嗒」；原版靠 `DSBPLAY_LOOPING` 把它拉满整趟。

### D-WHEEL-4 → **复核：仍是近似，且不许改**

这一条**没有变**：原版真人那一路的格数**取決於点击时机**（快转段一直转到松手），
不可复现（D-003）。本引擎的 `wheelSpinSteps()` 固定走 **4 圈 + 起点到落点的距离**
（`WHEEL_REVOLUTIONS = 4`），减速段贴在尾巴那 12 格上 —— 这是**注册在案的近似**，
**不是**原版真值，也**不要**按「原版总格数」去改。结论一句话：

> 原版总格数 = 点击时机决定；本引擎 = 最早合法落点 + 固定 4 圈。
> 两者只保证「停在同一个落点」与「先快后慢」这两点一致。

### 仍然没解出的 #2 → **已解**

`fcn_004542e9` 就是 `IDirectSoundBuffer::Stop`（不是「换一段音」）：
它接的正是 `_rich4_play_sound_effect` 用的同一个 sound-info 指针（`0x475d4c`），
而且同一个函数在移动音效那边也是「停当前那一路」的用法
（`docs/deviations/Q-SOUND-1.md` §4 / VA 0x0040d8dc）。
