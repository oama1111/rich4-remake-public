## 0. 两个 UI 档位 vs 两个规则全局

开局屏两条下拉各自只存**档位下标**，到开局那一刻才换算成**规则全局**：

| 屏上的东西 | 档位（UI） | 值表 | 开局写入的规则全局 |
|---|---|---|---|
| 遊戲時間 | `[0x46cb4c]` 0..5 | `0x46cbe8` = `0/730/365/182/91/30` **天** | `[0x49911c]` |
| 勝利條件 | `[0x46cb50]` 0..5 | `0x46cc00` = `0/100/50/10/5/3`（**倍率**） | `[0x499108] = 倍率 × [0x49908c]`（開局資金） |

两张值表 dump（`tools/disasm.py dump 0x46cbe8 12 4` / `0x46cc00`）：

```
0x46cbe8:  0  730  365  182   91   30
0x46cc00:  0  100   50   10    5    3
```

**0 = 無限**（两条都是；见下方 §2 的 `fcn_0041d89e` 开头那两条 `test`/`je`）。

### 标签

两条下拉的**标签是同一批字符串**（两张表里的指针值完全相同）：

```
0x46cbb8（土地權限） = [0x463112, 0x463119, 0x46311e, 0x463123, 0x46312a, 0x463131]
0x46cbd0（遊戲時間） = [0x463112, 0x463119, 0x46311e, 0x463123, 0x46312a, 0x463131]
                      無限期   二年     一年     六個月   三個月   一個月
```

所以遊戲時間下拉显示的就是 `無限期/二年/一年/六個月/三個月/一個月`，
但**含义是天数**（730/365/182/91/30）。勝利條件那一栏不查表：
浮窗逐行算 `开局资金表[s.money] × 0x46cc00[i]`，0 显示 `無限`
（`rich4_new_game.asm:1047-1058`，`imul eax, dword [ebx*4 + 0x46cc00]`；
`%d` 串 @ `0x46316e`、`無限` 串 @ `0x463171`）。

### 开局写入（`rich4_new_game.asm` 的 `loc_00407319`，VA 已核）

```asm
0040737d  mov eax, [0x46cb4c]
00407382  mov eax, [eax*4 + 0x46cbe8]     ; 天数
00407389  mov [0x49911c], eax
0040738e  mov eax, [0x46cb50]
00407393  mov edx, [0x49908c]             ; _rich4_game_initial_fund
00407399  mov eax, [eax*4 + 0x46cc00]     ; 倍率
004073a0  imul eax, edx                   ; ★ 整数乘，与开局资金同一档
004073a3  mov [0x499108], eax
```

★ **倍率乘的是本局真正选中的开局资金**（`[0x49908c]`），不是默认 30 万。

### 下拉的「记住上次选择」

`loc_00406f3f`（`rich4_new_game.asm:3844`）在**非首次**进这一屏时，
拿 `[0x49911c]` / `[0x499108]` **反查**下标写回 `[0x46cb4c]` / `[0x46cb50]`：

* 天数：直接逐项比 `0x46cbe8`；
* 金额：**先 `[0x499108] ÷ [0x49908c]` 再逐项比 `0x46cc00`**（有符号 `idiv`）。

首次进入（`[esp+0x24] == 0` 那条）把 `0x46cb3c..0x46cb58` 整块清零 ——
即两条下拉的默认档位都是 **0 = 無限**。

## 1. 到点之后发生什么：**当场结束，不是标记继续**

唯一调用点是**每日推进** `fcn_0041cf67`（VA 0x0041cf67）：

```asm
0041cfab  inc  dword [0x4990e4]      ; 總天數 +1
0041cfb1  call 0x41d89e              ; ★ 勝負判定
0041cfb6  cmp  eax, 1
0041cfb9  je   0x41d1a5              ; ★ 达成 → 整个日推进函数当场 return
0041cfbf  call 0x423acf              ; 物价指数（达成时被跳过）
0041cfc4  call 0x428475              ; 股市收盘等
   ...                                ; 停牌计数、樂透開獎、月結、地契到期 —— 全部跳过
```

即：**到点那天不再走行情 / 开奖 / 月结 / 地契到期，也不更新物价指数**，
对局直接进入终局。判定只在**日推进**这一处跑（**不是**每个玩家回合），
所以「今天总资产刚好达标」要等到下一天翻页才结算。

## 2. 胜负怎么判（`fcn_0041d89e` @ VA 0x0041d89e）

```asm
0041d8a3  if ([0x49911c] == 0 && [0x499108] == 0) return 0;   ; 两条都無限 → 完全不判
          ; 在 [who_plays & 3] != 0（未出局）的人里取总资产最高者 → esi=下标, edi=资产
0041d8e9  if (edi == 0) goto 看金额;                 ; ★ 全员资产 0 时，天数条件不生效
0041d8f1  if ([0x49911c] == 0) goto 看金额;          ; 天数为 0 = 無限
0041d8fa  if ([0x49911c] <= [0x4990e4]) goto 结束;   ; ★ jle：已过天数 >= 目标天数
0041d8ff  if ([0x499108] == 0) return 0;             ; 金额为 0 = 無限
0041d908  if (edi >= [0x499108]) goto 结束;          ; 总资产最高者达标
0041d915  ... 结束路径
```

要点：

1. **赢家 = 总资产最高者**（`_rich4_calculate_player_wealth`，即在世者里的首富），
   与是哪条条件触发**无关**；平手取先出现的（`jge` 跳过替换，同 `pickRichest`）。
2. 天数的比较是 `limit <= 已过天数`，而 `[0x4990e4]` 在调用前刚 `inc` 过
   （开局置 0）⇒ 「730 天」= **第 730 次日推进那天结束**。
3. `edi == 0`（全场首富资产为 0）时**天数条件整个跳过**，只有金额条件还能触发。
   这是原版的边角，按原样复刻。
4. 两条条件的先后：**先看天数，天数没到再看金额**；结果是 or 关系。

### 结束时的收尾（同一函数 0x0041d915 起）

* `[0x49910c] = esi`（当前玩家 = 赢家）；
* 单人类局：赢家是真人 → 其余人的 `[0x4990f4 + 角色号] = 2`、`0x46caf8 = 2`；
  赢家是电脑 → `[0x49910c] = 0`、`0x46caf8 = fcn_00407842(1)`；
* 多人类局：赢家是真人 → `3`，否则 → `1`。

`[0x46caf8]` 就是终局码（`rich4_main.asm:444-458` 读它并按 `[0x401b8c]` 跳转）：
`1` → 回主菜单，`2`/`3` → 先播頒獎/名次屏 `fcn_004075c1`，`4` → 读档屏。
`fcn_00407842` 是个**模态对话框**，返回值 1 或 4（4 = 玩家选了读档）——
「单人类局里电脑赢」这一支因此可能落到读档屏。**这是 UI 流程，本引擎未复刻**
（本引擎该情形给 1）。

## 3. 与「其他人破产」这条既有结束条件的关系

**两条路各自独立、谁先到谁算**：

* 破产结束：`rich4_player_bankrupt.asm:276-307`，在**付款当场**判，
  条件是「剩余在场人数」；终局时**跳过清算与拍卖**。
* 时间/金额结束：只在**日推进**判，终局时**跳过当天的行情/开奖/月结**。

两者写的是同一个 `[0x46caf8]`，主循环只有一条终局分支。本引擎两者都落到
`phase = 'gameOver'`。

## 4. 落码（rich4-remake，2026-09-16 落地）

* `rules/setup.ts`：`GAME_TIME_DAYS`（0x46cbe8）、`VICTORY_FACTORS`（0x46cc00）、
  `winConditionsOf(fundIndex, timeIndex, victoryIndex)`（复刻 0x0040737d..0x004073a3）。
* `rules/victory.ts`（新文件）：`checkVictory()` —— §2 那张判定的纯函数版；
  `victoryEndCode()`（§2 收尾的终局码）；`clearLosers()`（0x0041d951 那个
  「除赢家以外 `who_plays = 0`」的循环 —— **只清这一个字节**，钱与地产留着）。
* `GameState` 新增两个字段（只做加法）：
  * `winConditions: { targetDays, targetWealth }` —— 开局写一次；
  * `victory: { winner, reason, wealth, code } | null` —— 只有「按条件结束」那条路写它。
    `code` **在清 `who_plays` 之前**算好存下来（清完就数不出本局有几名真人了）。
* `rules/new-game.ts`：`newGame({ …, winConditions })`，缺省 `NO_WIN_CONDITIONS`
  （= 与接线前逐字节一致）。
* `state/reduce.ts` 的 `advanceGameDay`：`totalDays + 1` → **判定** → 才算物价指数。
  命中就 `phase = 'gameOver'` + `currentPlayer = 赢家` + `clearLosers()`，
  当天其余步骤（行情/開獎/月結/地契到期）全跳过（§1 的顺序）。`endTurn` 见到
  `gameOver` 直接收工，不再把 phase 覆盖回 `'turnStart'`。
  `gameOverCode()` 有 `victory` 时直接返回 `victory.code`。
* `loaders/savegame.ts`：新格式存档天然带上两个新字段（`migrate` 给旧档补默认值）；
  原版存档导入按 §5.2 的偏移**已回填**（2026-09-16）：`save.ts` 读
  `0x2682` / `0x2686`，`totalDays` 读 `0x2692`，`gaps['winConditions']` 已摘掉。
* `client`：开局屏点 `OK` 时 `winConditionsOf(setup.money, setup.time, setup.victory)`
  传给 `newGame`（另一条未动的缺口：`updatePriceIndex` 仍硬编码 30 万，见 known-deviations ④）。
* 回归测试：`packages/core/src/state/win-conditions.test.ts`（15 条：到点那天 /
  倍率达标 / 两条都 0 行为不变 / 破产结束仍有效 / 终局码 / `who_plays` 收尾）
  ＋ `packages/core/src/rules/setup.test.ts`（档位 → 天数/金额 的换算 4 条）。
* 未复刻：`fcn_00407842` 那个「要读档吗」模态框（终局码 4 那条 UI 支线）；
  頒獎/名次屏 `fcn_004075c1` 与原版的胜利台词（`_rich4_player_say`）也没做
  （REQ-12.15），所以达标后引擎只停在 `phase='gameOver'`，**不弹任何屏**。

### 5.3 `fcn_004075c1`（頒獎/名次屏）的取证与**为什么现在做不了**

2026-09-16 把这一支读完了（`rich4_new_game.asm:4381-4609`）。它**不是一屏动画**，
而是**同一支函数兼两用**，靠「画满 4 名没有」分流：

```asm
004075c1  [0x4990f0 + winner] = 1          ; 名次表：按**枚坐标**打标（winner = [0x4991b8]）
          jump = load_mkf("jump.mkf")      ; [0x48a3b0]
          bg   = read_mkf(jump, [0x4991b6]*4 + [0x4991b8])   ; ★ 关/页 两个下标
          rank = read_mkf(jump, 8)         ; [0x48a3b8] 名次贴片总表（+0x84 起是子表）
          ; 找赢家 = 第一个 who_plays != 0 的人（clearLosers 之后就是唯一那个）
          portrait = read_mkf(Panel.mkf, 0x64 + 赢家角色号)   ; [0x48a3bc]
          banner   = read_mkf(Panel.mkf, 0x5d)                ; [0x48a38c]
          esi = ([0x4991b6] != 0) ? 0x14 : 0xf                ; ★ 行距随关数变
          for (ebx = 0; ebx < 4; ebx++)
            if ([0x4990f0 + ebx] != 0) 画这一名的两块贴片（两次 fcn_004562a5）
00407726  if (edi < 4) {                   ; ★ 名次没满 4 ⇒ **这一关还没结束**
            memcpy 背景 → 屏幕
            播 fcn_004549cf(0x8006)
            Wait_0402_Message(fcn_004060e9)  ; 等「按一下继续」的窗口过程
            ; 回去继续下一关
          } else {                       ; ★ 满 4 ⇒ 整局结束
            sprintf("%s" 之类的串) → fcn_00451677(0x46cadc, 串, 0)
            [0x46caf9] = 1
          }
```

**为什么现在做不了（技术理由，不是「工作量大」）**：

1. 它依赖原版的**多关流程**：`[0x4991b6]`（关/局序号）与 `[0x4991b8]`（名次页），
   两者一起选背景图，还决定行距 `0xf` / `0x14`。本引擎是**单关**（`gameStage`
   恒 0，见 `events/fortune.ts` 的 `ctx.gameStage = 0`），没有这两个全局量，
   也没有「一关结束 → 名次屏 → 下一关」的循环可挂。
2. 它的「名次表」是 `[0x4990f0 + 玩家]` 这张**只有 0/1 的标记表**
   （`clearLosers` 清成 0、这里给赢家写 1）。本引擎的 `clearLosers()` 只清
   `who_plays`，没有这张表 —— 名次的信息在 `victory` 里（只有赢家），
   要画完整名次得**另算一遍资产排名**（`wealthOf` 有，但原版这一屏用的是
   关内名次，不是总资产名次）。
3. 名次贴片在 `jump.mkf` 资源 8 的 `+0x84` 子表里，行距/列位来自上面那两个
   全局量；`Panel.mkf` 的 `0x64+角色` 与 `0x5d` 都已能解出，但**没有实机截图
   对齐**，落点全是推算。

⇒ **登记为「需要先有原版多关流程才能复刻」的表现层缺口**，而不是一个能直接照抄的
屏幕。真要做，最小可信的替代是：终局时上一屏「四名玩家按总资产排名 + 赢家头像 +
一句胜利台词」，并把「这不是原版那一屏」写进 UI 文档 —— **那属于新增界面
（C-FID-1 不许改良），故不做**。

## 5. 独立复核（Q18 卡，2026-09-15）—— 结论一致，另补四条事实

复核方式：**不看本文**，从 `rich4.exe` 重新线性反汇编
`fcn_0041cf67` / `fcn_0041d89e`（`tools/disasm.py va`），并用仓库现成的
`loaders/save.ts` 解析器把 `Rich4/Save0.dat` 与 `Rich4/SAVE1.DAT` 读出来。

### 5.1 逐指令核对（无订正）

| 本文的说法 | 复核到的指令 | VA |
|---|---|---|
| 两条都为 0 → 直接返回 0 | `cmp [0x49911c],0 / jne` + `cmp [0x499108],0 / jne` + `xor eax,eax / ret` | 0x0041d8a3..0x0041d8b8 |
| 在世者里取首富 | `cmp byte [eax+0x496b7d],0 / je` 过滤；`cmp edi,eax / jge` 严格大于才换 | 0x0041d8c1..0x0041d8e6 |
| 首富资产 0 → 跳过天数条件 | `test edi,edi / je 0x0041d8ff` | 0x0041d8e9 |
| 已过天数 ≥ 目标天数 → 结束 | `cmp edx,[0x4990e4] / jle 0x0041d915`（edx = `[0x49911c]`） | 0x0041d8fa |
| 金额条件 | `test ebx,ebx / je 返回0` + `cmp edi,ebx / jl 返回0` | 0x0041d8ff..0x0041d915 |
| 只在日推进判，且**先 inc 天数** | `inc dword [0x4990e4]` → `call 0x41d89e` → `cmp eax,1 / je 返回` → `call 0x423acf`(物价) → `call 0x428475`(行情) | 0x0041cfab..0x0041cfc4 |
| 达成则跳过当天其余步骤 | `je near loc_0041d1a5`（= 该函数的收尾 `pop/ret`），后面的停牌计数/樂透/月結全在外 | 0x0041cfb9 |

`tools/disasm.py callers 0x0041d89e` 也证实**全程序只有 0x0041cfb1 一个调用点**；
`callers 0x0041cf67` 只有 0x0041902e（回合推进里"越过了最后一名玩家"那一支）。

### 5.2 补：两个全局**在存档里的偏移**（接线/读档要用）

`rich4_save_files.asm` 的 fread/fwrite 序列（读档 0x00402c70 起、存档 0x0040xx 起）
把这两个全局**原样存进存档**：

| 存档偏移 | 全局 | 含义 |
|---|---|---|
| `0x2682` | `ref_0049911c` | 目标天数 |
| `0x2686` | `ref_00499108` | 目标总资产 |
| `0x2692` | `ref_004990e4` | **已过天数**（每日推进 `inc`） |

两份样本存档的实际值（`loaders/save.ts` + 现写的小脚本读出）：

| 存档 | 日期 | 地图 | 目标天数@0x2682 | 目标金额@0x2686 | 已过天数@0x2692 | 物价指数 |
|---|---|---|---|---|---|---|
| `Save0.dat` | 2002/10/23 | globalMapId 3 | 0 | 0 | 295 | 5 |
| `SAVE1.DAT` | 2002/9/17 | globalMapId 7 | 0 | 0 | 0 | 1 |

⇒ 样本里两条都是 0，与本文「默认档位 0 = 無限」一致；
⇒ 另有一条旁证：`Save0` 的已过天数 295 与日期 2002/10/23 **自洽**
（2002/1/1 + 295 天 = 10/23，零基计数），`SAVE1` 是新局故为 0。

⚠️ **接线时的落点**：`loaders/savegame.ts` 的 `importOriginalSave` 目前把
`totalDays` 硬置 **0**、且 `winConditions` 没有从存档回填（`state.totalDays: 0`）。
若要让"导入原版存档"不丢这两样，需在 `loaders/save.ts` 的 `SaveGame` 上加这三个字段
（偏移见上表），再在 import 里写回 `totalDays` / `winConditions`。

### 5.3 补：「两者都为 0」是**连遍历都不做**

不是在遍历里对每个人判两条，而是函数第 4 条指令就 `ret 0`（0x0041d8a3）。
所以 `hasWinConditions()` 的早退与它**逐字等价**，不是近似。
后果：两条都为 0 时，日推进照常走物价指数 / 行情 / 開獎 / 月結，对局只会因破产结束。

### 5.4 补：判据里的「总资产」是**完整身家**

`call _rich4_calculate_player_wealth`（VA 0x004239b9）——现金 + 存款 − 贷款
+ Σ(持股×**f20 市价**，逐支向零取整) + 住宅/连锁店/设施估值。
不是"现金"或"存款"单项。所以勝利條件档位换算出来的金额要和**身家**比，
UI 上那一栏显示的也是这个数（`0x46cb94[资金档] × 0x46cc00[勝利档]`）。

### 5.5 补：结束时的赢家**不看哪条条件触发**

天数到点也好、金额达标也好，赢家一律是"当时在世者里的首富"（esi）。
若同时有多人并列首富，取**先出现者**（`jge` 跳过替换 ⇒ 严格大于才换人）。

## 6. 同一条缺口的另两处（② 拉幕 / ③ 半亮）—— 落码与复核

### ② 退出时的「拉幕」（原版状态 2）—— 已补
