# 差距清单（PRD ↔ 实现）总览

> 本目录是**阶段 2** 的产出：把 `rich4-spec/` 的权威规格逐系统对照
> `rich4-remake/packages/` 的实现，产出**可执行的差距表**。
> 阶段 3 按本目录逐条修复，并用差分测试验证。

## 一、为什么需要这一层

- `rich4-spec/` 有 21 份系统规格（含 `@source 0xADDR` + 汇编原文），但它**只描述原版**，
  不告诉你"实现落到哪、差在哪"。
- `rich4-remake/docs/known-deviations.md` 记录的是**开发过程中已知的**偏离；
  本轮审计发现**大量偏离从未被登记**（多份报告里"新发现"占比过半）。
- 两者之间的**空白**就是本目录：逐条给出「原版规格（证据）｜remake 现状（文件:行）｜
  差距类型｜严重度｜修复方向」。

## 二、铁律（写报告与**读报告**时都适用）

1. **真值只有 `Rich4/rich4.exe`**。`rich4-re/` 已知有 8+ 处错误，**只能当线索**。
2. **规格本身也可能是错的。** 本轮已经有 **4 处**权威规格被证伪
   （復仇卡触发条件、`tools.md` 的"销毁后自动补放"、炸弹转移对象、`objects_info.+1` 语义），
   而且都是**对照 remake 代码时反过来发现的**（remake 反而是对的）。
   ⇒ **每一条差异都必须回 exe 做第三方裁决**，不能假定"规格一定对"。
3. **引用规格要锁版本。** 审计期间 `rich4-spec/docs/systems/save-format.md`
   从 185 行涨到 337 行；有报告曾据旧版判出"规格块序表偏移偏 4 / 未决 1 未结案"，
   按新版复算后**全部撤回**。凡引用规格的结论，请记录你读的是**哪一版**（行数或段落标题）。
4. **每条结论必须给双方证据**：原版侧 `0xADDR`（必要时附汇编原文），
   remake 侧 `文件路径:行号`。
5. **证据不足写「无法判定」**，绝不猜测。

### 阻断级问题的 6 个「簇」（按簇排期，不要按 240 条逐个修）

多数阻断级问题不是孤立的，而是集中在少数几条**没接上的主干**上。先修主干收益最大：

| 簇 | 影响面 | 典型条目 | 报告 |
|---|---|---|---|
| **A. 释放链没接** —— `confinement.release()` / `tickBlocking().released` 无消费者 | 监狱、医院、保释、路障、地雷、炸弹、神明搭档**全部**受影响（占用表永不清零） | 反复保释幽灵、刑满不回棋盘 | 04、05 |
| **B. 存档没有原版格式的写入路径**（只写 JSON） | 一切"读原版存档 / 写出能被原版读的存档"的验证都做不了 | 在狱/住院标志未导入 ⇒ **读档把人放出狱** | 07 |
| **C. 随机数消耗序列不一致** —— 算法位级正确，但**调用次数/时机**至少 6 类错 | 确定性复现失败；联机（延后项）地基不牢 | `pickNextNode` 单候选不掷、小游戏少掷、抽卡少掷、AI 替身不推进 rng | 05 |
| **D. 语音播放覆盖** —— `#NNNN` 只播 1050..1373 | 610 个低编号 + 金貝貝 27 条**一声不响** | 全 client 只有一处播 `Speaking.mkf` | 06 |
| **E. 月度/结算不清账** —— `+0x42`/`+0x5c`/`+0x60` 月结不清零 | 月度奖项自第 2 个月起用跨月累计值 | 月结、税收、查稅卡 | 01、04、05 |
| **F. 空实现：状态写了但没人读** | 卡/道具"看似实现"却无效果 | 停留卡/烏龜卡是空卡、防御卡命中后不消耗 | 02、03 |

> **簇 A 的剩余一半（诚实边界）**：原版释放还做两件**表现层**的事
> （`@source 0x0040d6be`）：`p[+0x15] |= 0x10`（走回棋盘标记）、
> `p[+0x10] = 朝 board node 的方向`、`node[node_id].+0x24 |= 1<<idx`（登记节点占用掩码）。
> remake 里 `nodeId` 本来就保留着（关押不挪 `nodeId`），且**未建模** `node[+0x24]` 占用掩码，
> 所以这一半**暂时无从验证**（要等客户端的"从监狱走回棋盘"动画接上）。
> 已在 `rules/confinement.ts` 与 `rules/blocking.ts` 注明归属，**不假装已修**。

> ⚠️ **F 类最隐蔽**：状态被正确写入、递减、存档，看起来"实现了"，
> 但引擎里没有任何判据读它来决定行为 —— 这类必须靠**对照原版的判据指令**
> 才能发现；读 remake 代码或跑 remake 的测试**都发现不了**。

### 7.5 几条踩出来的经验（省得重踩）

1. **旧测试会把 bug 钉死。** 本项目已撞上 **4 次**（大盘指数差 1、`pickNextNode` 不掷随机数、
   復仇卡 4 天、`mutateLand` mode 1 只清两项）。改实现前先看断言：它是**真值断言**
   还是**复述实现**？本目录日志里每条修复都注明了对应测试怎么改的。
2. **样本不可观测时，构造字节让断言可证伪。** 两份真实存档里 `flast`/`price_status`/`viewRotation`
   **全是 0**，SAVE1 甚至 `num_lands = 0`。凡是"结构上修对了但样本看不出"的，
   测试都写成**自己往字节里写非 0 值**再断言。
3. **别用百分比代替判断。** 例如 `objects_info` 只建模 5/24 字节，但那 5 个字节
   正是语义上全部有意义的字段；反过来 6,912 字节的 `history` 一眼看不出价值。
4. **一个公式对某个表成立，不代表对同符号的所有出现成立。** `#NNNN` 被这个坑害过
   （`1050+角色×27+事件` 只描述**角色台词表**，不是 `#NNNN` 的解析规则）。
5. **F 类（状态写了但没人读）可以用**机械审计**一次筛出来**（第 38 条新增）：
   `python3 tools/scratch/audit-player-fields.py` 对 `GameState.Player` 的每个字段
   统计「**非写侧**（装载/新建/写档/工厂）的引用文件」——一个引用都没有的就是嫌疑。
   40 个字段里恰好筛出 `ypos` 一个，顺着它查下去就撞上了「位置三元组脱钩 ⇒
   冬眠卡在新局完全无效」（§7.20）。**比通读代码可靠，值得每轮跑一次**
   （对象/地块/全局字段同理，改几行即可）。
7. **「函数写了没人调」要和「状态写了没人读」对称地查一遍**（第 44 条新增）：
   `python3 tools/scratch/audit-uncalled.py` 列出 core 的导出函数里
   **全仓库零引用**的那些。口径必须去掉「只在本模块内被调用」的噪声（那只是封装松），
   否则 `takeSnapshot` 这种重点会淹在几十个测试助手里。这一轮就是靠它撞上
   「破产清算的下線拍卖整段缺失」与「魔法屋拍賣空转」。
8. **死代码会带着测试一起活着，而那些测试钉的不是行为。** 第 44 条删掉的
   `releaseAssets` / `markLand` / `isSealed` 各自都有绿测试 —— 它们断言的是
   **一个没人调用的函数**，看着像覆盖，其实一删就发现真正在跑的那条路
   （`applyBankruptcy` / `applyDistrictMark` / `isSealedStrict`）当时**没被断言过**
   （例如破产清算清 `landTenure`/`facilityTenure` 这两条一直没测试）。
   删死代码时**必须**把断言搬到现役路径上，否则是净损失。
10. **注释里的「先前 / 旧读法 / ⚠️ 订正」是历史，不是现状**（第 74 条新增）。
    `monthly-screen.ts` 里留着「先前多写的 `+ 帧`」这类纠错注记 —— 起草规格的子代理
    把它当成了**当前实现**，于是把一条**早已修好**的问题又报了一遍（§7.55 第 9 条）。
    **复核『remake 现在怎么做』时必看当前代码，注释只用来找线索。**
11. **工具的输出窗口会生产假警报**（第 74 条新增）。`prd_gap_pack.py` 对长函数只给
    前 40 条，于是「`0x44e6eb` 里没有 `[0x48c5ec]`」这种判断就错了 ——
    那条指令在**函数最后一条**（`0x44e7a1`）。判「某全局/某地址有没有被某函数用到」，
    一律 `grep -n '<VA>' gen/db.txt` 看**函数边界内的全部**指令，别信截断窗口。
9. **Python heredoc 别写中文**：本机 `python3` 从 stdin 读源码不按 UTF-8 解码，
   会直接 `SyntaxError: Non-UTF-8 code`。落成文件再跑（本目录 `tools/scratch/` 下的脚本都是这么做的）。
