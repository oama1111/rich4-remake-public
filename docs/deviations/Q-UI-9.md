# Q-UI-9 偏离登记 —— 通用填数窗（`fcn_00453544`）的**键盘**补齐

> **编号说明**：`Q-UI-1..8` 全部用过（`Q-UI-8` 是上一轮「同一个计算器 + 右键关面板」）。
> 本轮补的正是 `docs/deviations/Q-UI-8.md` 第四章第 5 条留的那一笔残留项，
> 故顺延到下一个空闲号 **Q-UI-9**。
>
> 需求方 2026-09-16 原话：「**游戏里所有涉及输入数字的应该调用的都是同一个计算器**」
> —— 所以那个「同一个计算器」的**键盘**也必须 1:1（只补鼠标等于缺一半）。
>
> 本文件登记：① 键表逐项取证（带 VA）；② 每个键的精确语义与边界；
> ③ 与鼠标路径的关系；④ 本轮改了什么；⑤ **没解出 / 有意没动**。

---

## 一、逐项取证

### 1.1 键表在哪儿：`loc_00452e4b`

窗口过程是 `fcn_00452c02`（VA 0x00452c02，`rich4-re/asm/rich4.asm:26722`）。
它的消息分派（VA 0x00452c25 起）里 `0x100`（`WM_KEYDOWN`）→ `loc_00452e4b`：

```asm
; VA 0x00452e4b
00452e4b  xor dl, dl
00452e4d  mov byte [0x48cac2], dl      ; 先清「按下的钮」（序号）
00452e53  cmp eax, 0x35                ; ★ 下面是一棵二叉分派：VK → 钮序号
...
00452ed7  mov byte [0x48cac2], 5       ; —— 每一支都只写这一个全局
...
00452f0e  push 0
00452f10  push 0x48234a                ; 按键音（表 0x48231a 的第 6 项 = 7）
00452f15  call rich4_play_sound_effect
00452f1d  push 0
00452f1f  push 0
00452f21  push 0x202                   ; ★ 合成一条 WM_LBUTTONUP
00452f26  jmp PostMessageA
```

**逐项**（`VK → 序号 → 落点 VA`；序号是 `[0x48cac2]` 的值）：

| VK | 键 | 序号 | 落点 VA | 备注 |
|---|---|---|---|---|
| 0x30 | `0` | 5 | 0x452ed7 | |
| 0x31 | `1` | 0xd | 0x452ee3 | |
| 0x32 | `2` | 0xe | 0x452eef | `cmp 0x33` 的 `jb` 分支 |
| 0x33 | `3` | 0xf | 0x452efb | |
| 0x34 | `4` | 0xa | 0x452f07 | `cmp 0x33` 的 `jmp` 分支 |
| 0x35 | `5` | 0xb | 0x452f2b | |
| 0x36 | `6` | 0xc | 0x452f34 | `cmp 0x37` 的 `jb` 分支 |
| 0x37 | `7` | 7 | 0x452f3d | |
| 0x38 | `8` | 8 | 0x452f46 | `cmp 0x37` 的 `jmp` 分支 |
| 0x39 | `9` | 9 | 0x452f4f | |
| 0x08 | 退格 | 6 | 0x452f6a | |
| 0x0d | Enter | 3 | 0x452f96 | |
| 0x43 | `C` | 4 | 0x452f61 | |
| 0x48 | `H` | 0x10 | 0x452f73 | ★ 不走跳表，见 1.2.6 |
| 0x4d | `M` | 2 | 0x452f58 | |

★ 这张表不是手抄的：`amount-keys.test.ts` 里有一个**几十行的解释器**，
直接把 `0x452e53` 起那棵 `cmp/jb/jbe/je/jmp` 树按原版语义跑一遍，
逐个 VK 取回 `[0x48cac2]` 的序号，再与代码里的 `AMOUNT_KEY_ID_VK` 对账。
原版那棵树里**没有**小键盘（`0x60..0x69`）、没有 `ESC`（0x1b）、没有字母、没有小数点。

### 1.2 每个键的精确语义

**序号 → 字**在表 `0x47e714`（`mov dl, byte [序号 + 0x47e714]`）：
`[5]='0'`、`[7]='7'`、`[8]='8'`、`[9]='9'`、`[0xa]='4'`、`[0xb]='5'`、
`[0xc]='6'`、`[0xd]='1'`、`[0xe]='2'`、`[0xf]='3'`。
**序号 → 动作**在跳表 `0x452bca`（`jmp dword [序号*4 + 0x452bca − 8]`，14 项）：

| 表项 | 序号 | 落点 | 动作 |
|---|---|---|---|
| 0 | 2 | `loc_004530e9` | **M = 最大**：`itoa(10, buf, [0x48ca98])` |
| 1 | 3 | `loc_00453116` | **Enter = 確定**：`Post_0402_Message(atoi(buf))` |
| 2 | 4 | `loc_00453145` | **C = 清零**：`buf = "0"` |
| 3 | 5 | `loc_00453189` | **接数字**（'0'）|
| 4 | 6 | `loc_00453156` | **退格** |
| 5..13 | 7..0xf | `loc_00453189` | **接数字**（7 8 9 4 5 6 1 2 3）|

#### 1.2.1 数字（`loc_00453189`）—— 四条规则

```asm
00453189  strlen(buf) → eax
0045319a  cmp eax, 9   / 0045319d jge loc_0045310a   ; ① 满 9 位：什么都不做
004531a8  cmp byte [buf], 0x30 / jne loc_004531c4    ; 当前是 "0"？
004531b1  cmp byte [0x48cac2], 5 / je loc_0045310a   ; ② 又按 '0' → 不动
004531c0  mov dword [esp+0x68], 0                    ; ③ 按别的数字 → 顶掉那个 0
004531cb  dl = [序号 + 0x47e714]                     ;    这一次的字
004531d5  buf[len] = dl ; buf[len+1] = 0
004531e8  atoi(buf) ; cmp eax, [0x48ca98] / jle …    ; ④ 超过上限 → 改写成 itoa(上限)
```

- **位数上限 = 9**（不是 ATM 的 10）；
- **前导 0 不入位**：`"0"` 再按 `0` 不动；按非 0 的数字把那个 `0` 顶掉；
- 中间/末尾的 `0` 照收；
- **超过上限就夹到上限**（不是拒绝、也不是取模）。

#### 1.2.2 退格（`loc_00453156`）

```asm
00453163  cmp eax, 1 / 00453166 jle loc_00453172     ; 只有一位时
0045316a  buf[len-1] = 0                             ; 否则删末位
00453174  cmp byte [buf], 0x30 / je loc_0045310a     ; 是 '0' → 不动
0045317d  buf[0] = '0'                               ; 非 '0' → 退回 '0'
```

#### 1.2.3 `C`（`loc_00453145`）

`buf[0]='0'; buf[1]=0` —— **清零，不是取消**。取消是另一条路（见 1.3 末）。

#### 1.2.4 `M`（`loc_004530e9`）

`itoa(10, buf, 上限)` —— 填成上限。上限就一个参数（`fcn_00453544(max)` 存在 `[0x48ca98]`）。

#### 1.2.5 `Enter`（`loc_00453116`）

`Post_0402_Message(atoi(buf))` —— 把当前值**原样**交回去（`0` 也算数：`0` = 没填）。

#### 1.2.6 `H`（`loc_00452f73` + `loc_00453394`）—— 它是「按金额栏」

```asm
00452f73  mov byte [0x48cac2], 0x10          ; 序号 = 金额栏
00452f81  add ebx, 0x40                      ; lParam.x = 窗 x + 0x40
00452f8b  add edx, 0x2f                      ; lParam.y = 窗 y + 0x2f
00452fb9  PostMessage(hwnd, 0x200, 0, lParam) ; ★ 合成 WM_MOUSEMOVE
```
0x200 那一支（`loc_00453394`，`[0x48cac2] == 0x10`）算出值：

```asm
00453413  sub ebx, 0xa                       ; 条内 x = 0x40 − 0xa = 54
00453451  循环表 0x47e725（34 项），取第一个 ≥ x 的 i   ; → i = 17（table[17]=57）
0045346c  fild i / 00453470 fdiv [0x46621c]  ; [0x46621c] = 0x42040000 = 33.0f
0045347a  fild [0x48ca98] / 00453480 fmul    ; × 上限
00453484  __round_toward_zero                ; 向零取整
```
⇒ `H` 的值 = **`trunc(上限 × 17 ÷ 33)`**（约 51.5%）。

★ 注意 **H 的值不是跳表给的**：`loc_00452fce`（0x202 的分发）用
`cmp bl,0x10 / jae loc_0045310a`（VA 0x452fe5 / 0x452fe8）把序号 0x10 挡在跳表外，
所以键按下后合成的那条 0x202 对 0x10 号什么都不做（清一下全局就回）。
—— 已用测试钉住这条 `jae`。

#### 1.2.7 「负数 / 小数点」这类规则

**没有**。窗口的状态是一根**十进制数字字符串** `[0x48caac]`（初值 `"0"`），
会被写的就六处：建窗 `0x452c99`（`'0'`）、`C` `0x453145`（`'0'`）、
退格 `0x45317d`（`'0'`）、接数字 `0x4531c4`、`M` / 夹上限 `0x4530e9`（`itoa`）、
拖金额栏到最左 `0x45341a`（`'0'`）。
**一个入口都没有 `-` / `.`**，所以负数、小数在通用填数窗里**不存在**。

### 1.3 与鼠标路径的关系：**同一套状态机**

| 谁 | 决定「哪颗钮」 | 走哪一支 |
|---|---|---|
| 鼠标按下 `0x201` | 查像素命中图 `[0x48ca9c]`（= `Panel.mkf` 资源 0x16 解出来的 128×192 每像素一个序号）| `loc_00452d0e` |
| 键盘 `0x100` | 二叉分派（1.1 那张表）| `loc_00452e4b` → **合成 0x202** |
| 鼠标抬手 / 键盘合成 `0x202` | 已存在 `[0x48cac2]` 里 | **`loc_00452fce`（同一支）** |

`loc_00452fce` 干的事：查几何表 `0x47e6d8`（14 颗钮的 `dx,dy,w,h`）画按下态，
然后 `jmp dword [序号*4 + 0x452bca − 8]` 走 1.2 那张跳表。
⇒ **键盘与鼠标不是两套状态机**，键盘只是「另一种决定序号的方式」，
之后就汇进同一条路。本引擎照此实现：`onAmountKey` 写回同一个 `amountPage`，
`Enter` 走 `onDialogHit(..., 'amountOk')`。

几何表 `0x47e6d8` 顺带把序号焊成了画面上那 14 颗钮（这也解释了那 14 个序号是什么）：

| 序号 | dx,dy,w,h | 钮 |
|---|---|---|
| 2 | 8,63,58,25 | **M = 最大**（顶排左，宽钮）|
| 3 | 64,63,57,25 | **Enter = 確定**（顶排右，宽钮）|
| 4 | 8,95,33,17 | **C** |
| 5 | 48,95,33,17 | **0** |
| 6 | 88,95,33,17 | **退格** |
| 7 / 8 / 9 | y=119 | **7 8 9** |
| 0xa / 0xb / 0xc | y=143 | **4 5 6** |
| 0xd / 0xe / 0xf | y=167 | **1 2 3** |

**ESC 不在这张表里**：`loc_00452fa2`（其余键的出口）发现序号还是 0，直接返回。
关窗的 `0x205` 是**全局键盘钩子**把取消键补出来的（见 `Q-UI-8.md` §2.1），
所以取消那一条仍留在 `panel-cancel.ts` 的梯子上（本引擎原来是这么做的，本轮没动）。

### 1.4 顺带发现：**开页初值是 `"0"`，不是上限**

`loc_00452c91`（`0x401` 建窗那一支）：

```asm
00452c99  mov byte [0x48caac], 0x30    ; buf[0] = '0'
00452ca0  mov byte [0x48caad], ah      ; buf[1] = 0
```

本引擎原先（`Q-UI-8` 那一轮）开页时 `amountPage = { choice, value: max }` ——
**没有 exe 依据**，而且与键盘直接冲突：开页即上限时，按任何数字都会被
「超上限夹到上限」（1.2.1 ④）吃掉，键盘等于不存在。
故本轮把四个开页点改成 `AMOUNT_INITIAL = 0`（见 §3）。这条**超出「键盘」的范围**
（鼠标路径也会看到 0），单独记在这里，理由只有一条：**1:1**。

## 四、没解出 / 有意没动

1. **键位音效没接**：原版每按一次都放一个音 —— 跳表那几支是 `[0x48234a]`（表值 **7**），
   `H` 那条是 `[0x482352]`（表值 **9**）。本引擎的**鼠标**路径本来也没接这些音
   （`onDialogHit` 不播音），所以键盘也没接：只接键盘会变成「键盘有声音、鼠标没有」，
   反而是新的不一致。要接就两边一起接（另开一条登记）。
2. ~~**14 颗钮与金额栏的「画面」没复刻**~~ ✅ **2026-09-16/17 复核订正**：
   `client/amount-window.ts` **已经把 `Panel.mkf` #0x15 的图 0 整块面板画出来**
   （128×192，含金额显示框、指针条、14 颗钮与两颗光标），数字用同一张图里的字库
   （`图 = 字符 + 0x14`，逐位从末位往前贴、字距 12）—— 见该文件头注释的逐条 VA。
   仍**没有**复刻的只剩：
   - `H` 只复刻了「按下点 → 值」这一半（`trunc(上限×17÷33)`，按下点 0x40 是原版写死的）；
   - **鼠标拖金额栏**那条路（`0x200`）**公式已落码、命中区还差一步** ——
     2026-09-17 复核把这条读细了：
     * `loc_00453394` 那条（`cmp dh, 0x10`）：窗内 `x − 0xa` → 查表 `0x47e725`（34 项）
       找第一个 ≥ 它的项号 `i` → `value = trunc(上限 × i ÷ 33.0f)`；`x ≤ 0xa` → 0；
       `x ≥ 118`（表最大 107 + 0xa）→ **什么都不做**（值不变）。
       **这与 `H` 键是同一条式子**（`loc_00452f73` 伪造的按下点 `(0x40,0x2f)` 最终也落到
       `loc_00453470` 的 `fdiv`/`fmul`）—— 已抽成 `amount-keys.ts` 的
       `amountBarStepAt` / `amountFromBarX`，`H` 现在直接调它（两边不可能算出两个值），
       测试钉住表 34 项逐字节 = exe 与全部分支。
     * **还没接的是「哪一片算金额栏」**：逐像素 id 图里 `[0x48cac2]` 有两个相关值 ——
       id **1** 走 `loc_00453241`（用锚点全局 `[0x48caba]`/`[0x48cabe]`，看名字是
       「按住金额栏开始拖」那一片），id **0x10** 走上面那条值公式。
       两片各自的像素范围与 id 1 那支的算法还没读完 ⇒ **接线前先读 `loc_00453241`**；
       在那之前不猜（宁可先只留 `H` 键这一路，也不要接错一片）。
   - 几何表 `0x47e6d8` 只用来核对「序号 2..0xf 确实是那 14 颗钮」，没有用于绘制。
3. **「模态窗吃掉全部按键」没有照抄**：本轮只吃 `0-9 / 退格 / C / M / H / Enter` 这 6 类，
   其它键仍会落到全局热键。原版那扇窗是窗口过程，别的键它自己也不理、
   更不会传给棋盘。**但「ESC 能关窗」这一点两边一致**（都是全局钩子补 `0x205`）。
4. **`Enter` 那两支除返回值之外的副作用没逐条对**：`loc_00453116` 里还有
   `fcn_00402460(0)` 与 `fcn_004021f8(0x1b,1,0)` 两下（看着像收鼠标捕获 / 停声音），
   本轮只对齐了「把 `atoi(buf)` 交回去」这一步（= `Post_0402_Message`）。
   同理建窗那支的 `fcn_004021f8(0x1b,…)` / `fcn_00402460(1)` 也没对。
5. **小键盘不认**：`0x60..0x69` 不在原版那棵树里，故浏览器里也不认（浏览器侧
   `amountVkOf` 只认主键盘 `Digit0..9`）。已用测试钉住。
6. **`main.ts` 的 `atmVkOf` 与 `amount-keys.ts` 的 `amountVkOf` 是同一套规则的两份实现**：
   ATM 那一份是 `Q-BANK-1` 时写的，本轮**没有**去改它（`main.ts` 是别的 agent
   同时在动的文件，尽量只做加法）。要合并时把 `atmVkOf` 换成 `amountVkOf` 即可，行为相同。
7. **`C` / `M` 的纯函数没有抽成共用**：两扇窗这两条语义完全一样，但各自只是一个表达式
   （`'0'` 与 `String(Math.max(0, Math.trunc(limit)))`），再抽一层只会把一行拆成两处间接；
   已用测试钉住两边同值（`amount-keys.test.ts` 最后一组）。数字与退格那两条
   （规则多、容易写错）是真共用。
8. **`H` 与 ATM 的 `H` 不同源**：ATM 是 `atmSeekAmount`（`loc_00437413` 那套
   `(条内x/6+1)×(上限/34+1)` 的算法，按下点屏 x = 220），通用窗是
   `trunc(上限×17÷33)`（按下点窗内 x = 0x40）。**故意不共用**。
9. **五个开页点初值改成 0** 见 §1.4 —— 这是本轮唯一一处「键盘之外」的行为改动。
   如果需求方想要「开页预填上限」，那是一条**有意改良**，应单独登记，
   而不是留在「键盘 1:1」里。
