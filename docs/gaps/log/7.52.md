### 7.52 ★ 第 71 条（本轮）：把「坐标不变量」变成**运行时哨兵**（11 个写入点 → 整局逐步核）

继续用「先枚举原版写入点、再核复刻覆盖」这套普查法，本轮挑的是
**玩家坐标 `xpos/ypos`（`+0x08`/`+0x0a`）**。

#### (1) 原版：22 条写入 = **11 对**（两格永远成对写）

机械扫描 `mov word [.. + 0x496b70/72], ..` 得 11 个函数：
`0x40c05c`、`0x40cc56`、`0x40cd87`（破产）、`0x40d375`（消失）、`0x40d5a5`、
`0x418c55`、`0x41d89e`（胜负收尾）、`0x43d593`（入狱传送）、`0x43ec3f`（入院传送）、
`0x44757c`（两对）。完整表见 `rich4-spec/docs/systems/save-scalars.md`。

★ 其中**破产那处是"重新同步"而不是"移动"**：
```asm
0040cdb0  bx = word [player + 0x496b74]        ; node_id
0040cdbe  ebx = [0x498e80]                     ; ★ 节点表基址（步长 0x28）
0040cdc4  dx = word [ebx + node*0x28 + 0]
0040cdc8  word [player + 0x496b70] = dx        ; xpos = nodes[node].x
0040cde4  word [player + 0x496b72] = dx        ; ypos = nodes[node].y
```
⇒ 只要 `xpos/ypos` 恒等于 `nodes[nodeId]`，**这条是空操作**。复刻把它收进
`rules/position.ts`（`placeOnNode`/`placeOnNodeId`），所以**不需要**再抄一遍。

#### (2) 复刻侧的覆盖核查：**没有漏点**

复刻只有 3 处会改 `nodeId`：走路（`reduce.ts:1041`）、新局（`new-game.ts`）、
传送卡（`teleport.ts`），另有 1 处"停留/转向"直接写坐标（`reduce.ts:1045`，两格一起写）。
逐处确认都经过 `position.ts` 的原子更新（`nodeId`/`xpos`/`ypos` 一起改）✅。

#### (3) 本轮的真正产出：把不变量变成**运行时哨兵**

原版有 11 个写入点、复刻只有 4 个 —— 这种"靠读码保证等价"的结论**无法防止未来出错**。
所以在整局 soak（`state/full-game.test.ts`）里加了 `assertPositionInvariant`：

```ts
// 在场：xpos/ypos 必须 == nodes[nodeId] 的 x/y；离场（nodeId==0）：必须 0/0
assertPositionInvariant(state, nodeIndex, `step ${steps}`);
```
每**一步**都核、4 名玩家全核，并加了**防空跑**断言
（`invariantChecks > 10_000`）——否则这条断言可能因为循环没跑而形同虚设。

种子 2024 的整局（万级回合）**全程通过** ⇒ 复刻的坐标不变量在当前规则集下成立。
**这是"我们没查出 bug"，不是"证明原版等价"**（诚实边界见下）。

#### 诚实边界

- 哨兵只管**复刻自身的一致性**（`xpos == nodes[nodeId]`）；它**不能**证明复刻在这些
  写入点上与原版做得一样（例如"入狱传送该传去哪一格"仍需各自核对）。
- 原版 11 个写入点里，复刻只对应上 4 条路径 ⇒ 其余 7 条要么是同一规则的另一种写法
  （如破产的"重新同步"）、要么落在复刻未实现的系统里；本轮只做了**分类**，没逐条实现。
- 哨兵只覆盖 `state/full-game.test.ts` 跑到的那张地图与那套 AI 决策；
  别的路径（小游戏、物件、联网）不在这条序列里。
