#### (1) 取证：`[0x48c42c]` 是**状态号（低半字节）+ 拍数（高半字节）**

```asm
; @source 0x00437ed0（頒獎屏入口）与 0x00439196（每拍）
00437ed0  mov byte [0x48c42c], dh        ; 进屏清 0
00439196  test byte [0x48c42c], 0xf      ; ★ 低半字节 = 状态
0043919f  call rand15 / mov ebx,eax / sar ebx,0xa
004391a9  test ebx,ebx / jne 0x4391b6
004391ad  or  byte [0x48c42c], 1         ; rand>>10 == 0 ⇒ 状态 1
004391b6  cmp ebx,1 / jne 0x4391c2
004391bb  or  byte [0x48c42c], 2         ; rand>>10 == 1 ⇒ 状态 2
004391c2  mov al,[0x48c42c] / and al,0xf / jmp [eax*4 + 0x437e35]
```

- **状态 0**（低半字节 0）= 「结算屏已全亮，等玩家点一下」；
- 每拍**按 `rand15() >> 10`（∈{0,1,2,3}）决定要不要进状态 1 或 2** ——
  也就是「每拍有 1/2 概率眨眼、1/4 概率走另一条」；
- 状态 1（`loc_004391ee`，`ebx == 1`）里：
  `ebx = ([0x48c42c] & 0x30) >> 4`（**高半字节 = 0..3**），
  帧 0/1/2 走 `0x4759e8` 那张表贴子图，**帧 3** 才走 `exblit` 那一笔，
  画完 `mov byte [0x48c42c], 0`（`0x439280`）把状态清回 0；
  `0x4392d4 add byte [0x48c42c], 0x10` 就是「高半字节 +1」。

★ 结论：这一笔是 **记者小姐的待机眨眼**，不是「窗口转场」——
`exblit` 的参数序实测 `(dst, src, x, y, srcX, srcY, w, h, flags, 0)`
（`0x455e24`：`[ebp+0xc]=src`、`[ebp+0x10]=图素`、`[ebp+0x14/0x18]=x/y`、
`[ebp+0x1c/0x20]=srcX/srcY`、`[ebp+0x24/0x28]=w/h`），
故那一笔 = **把图 19 的 (52,50) 起 80×40 原样拷到 (76,120)**：

| 量 | 值 |
|---|---|
| 源图 | `[0x48c41c] + 0xf0` = **图 19**（记者小姐立绘 186×410）|
| 源矩形 | `(0x34, 0x32)` = (52,50)，`80×40` |
| 落点 | `(0x4c, 0x78)` = (76,120)，`80×40`（**与源同尺寸 ⇒ 原样，不缩放**）|
| 旗标 | `push 0` = **不抠黑**（与图 19 自己的画法一致）|

★ 落点与立绘自己的落点 (24,70) 差 **(52,50) = 源矩形原点** ——
所以这一笔是「把立绘上那一块**再原样贴一次**」，
