### 7.28 ★ 第 47 条（本轮）：规格补出**乞丐规则**，顺手修掉「棋子能落到别人头上」两处

第 46 条的逐函数覆盖工作单继续往下做（`tools/audit_prd_gaps.py`），
本轮补了两段规格，其中一段**直接暴露了两个复刻缺陷**。

#### (1) 规格缺口：**乞丐**（破产者留在地图上的棋子）整段没有

全规格此前只在数据表里出现过「乞丐」这个**名字**（`ui-labels.md` 第 38 项、
`data-tables.md` 类别 5），**没有一处写它的规则**。补进 `places.md` §5b：

- 破产**不收回棋子**：`who_plays` 清 0 后棋子留在原地当乞丐；
- 触发五道闸门（`0x41b5fd..0x41b638`）：同格有人、**只有 `who_plays == 0` 的算**、
  **必须停在这格**（`[0x48baf8] != 0` 即路过不算）、取位图**最低位**那个
  （两人同格时只有下标小的收得到钱）；
- **金额 = 1000 × 物价指数**（`0x41b63a` 的移位链 `p→3p→25p→200p→1000p`），
  字符串「施捨給乞丐%d元」`0x463ab1`，`pay_money(我, −1, 金额, 0)` 进**公库**；
- 换位 `0x40cc56(beggar)` 是一支**通用挪棋原语**：清旧格占用位 →
  `call 0x40aa6c`（**就是物件投放那个挑格器**）→ 写 x/y/node/lastNode/朝向 → 置新格占用位。

#### (2) ★★ 由此暴露的两个真缺陷：挑格时**没算玩家**

`0x40aa6c` 的候选筛选是 `test dword [node + 0x24], 0x80ffff00` ——
**bit31 静态 + bits 8..11 玩家 + bits 12..23 物件**。
复刻不镜像这份运行时状态，改成现算；但**两处只算了物件**（或只算了自己那一格）：

| 位置 | 旧行为 | 后果 |
|---|---|---|
| `giveAlmsIfBeggar` 的乞丐换位 | `filter(n => n !== nodeId)` | 乞丐会挪到**有人站着**或**已有神明**的格子上 |
| `respawnPartner` 的搭档登场 | 只反查物件表 | 神明搭档会**落在玩家头上** |

修法：新增 `rules/object-landing.ts` 的 **`runtimeOccupiedNodes(players, objects)`**
（玩家 `nodeId` ∪ 在场物件的 `nodeId`；`attached != 0` 的不算 —— 它不在图上），
两处都用它。@source 与掩码语义写在函数注释里。

#### 验证

- `rules/beggar.test.ts` 5 → **7 例**：
  ① `runtimeOccupiedNodes` 的三类输入（玩家 / 在场上物件 / 附身物件不算）；
  ② ★★ **三格小地图上三格全被占 ⇒ 乞丐原地不动**（施捨照付）——
  退回旧行为立刻红（反证已跑）。
- `state/object-integration.test.ts` 两处搭档登场各加一条**不变量**断言：
  搭档的落点不在「玩家 ∪ 物件」集合里。
