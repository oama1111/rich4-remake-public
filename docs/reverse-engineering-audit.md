# 逆向源可靠性审计与验证纪律

> 最后更新：2026-09-13

## 结论先行

`rich4-re` 是**极有价值的线索来源**，没有它这个项目根本无从下手。
但它**不是真值**——已发现至少 **5 处实质性错误**，类型各异（工具缺陷、
链接配置错误、结构体漏字段、字段误标、代码转录错误）。

**唯一的真值是原版 `Rich4/rich4.exe` 本身。**

---

## 一、已发现的错误清单

| # | 位置 | 类型 | 后果 | 状态 |
|---|---|---|---|---|
| 1 | `tools/dump_all.c` | 64 位构建下结构体布局缺陷 | **13,034 张素材全部损坏**，旧 `png/` 漏掉 89%、620 张尺寸错误 | 已绕过，自行实现解包 |
| 2 | `asm/mscrt.ld` | 把 `_libc_rand` 重定向到 msvcrt | **随机序列与原版完全不同**，从该 exe 观测的随机行为一律不可信 | 已避开，以原始 exe 反汇编为准 |
| 3 | `csrc/land.h` | **漏字段** | 未记录偏移 `0x20` 的按等级租金表（6 项 uint16），而这是过路费公式的核心 | 已自行反推并以地图数据验证 |
| 4 | `asm/rich4_player_info.h` | **字段误标** | `hostility[6]` 实为 `hostility[4]` + 2 个独立月度金额字段 | 已以存档实证纠正 |
| 5 | `csrc/fortune.c` | **代码转录错误** | case 15 写 `*v = 15`，汇编实为 `*v = 14` | 已按汇编实现 |

> 另有两处**疑似**误标待确认：
> - `total_winter_sleep_days`（+0x42）在月度评分中被当作「本月倒楣天数」折算（Q15）
> - `god_info`（+0x3f）在破产流程中被传给 `remove_object`，与「神明状态」语义不符

## 二、验证纪律

按可靠性排序，**永远优先使用排名靠前的证据**：

| 级别 | 证据来源 | 可靠性 | 说明 |
|---|---|---|---|
| **A** | `Rich4/rich4.exe` 二进制 | **真值** | 数值表、常量可直接提取比对 |
| **A** | 原版存档 `Save0.dat` / `SAVE1.DAT` | **真值** | 结构与数值的实证 |
| **A** | 原版资源文件 `*.mkf` | **真值** | 格式与素材的实证 |
| B | `rich4-re/asm/*.asm` 反汇编 | 高 | 由 exe 机械转换而来，但**标注**可能错 |
| C | `rich4-re/csrc/*.c` 人工还原 | 中 | 可读性最好，但**已证实存在转录错误** |
| C | `rich4-re/*.h` 结构体定义 | 中 | **已证实存在漏字段与误标** |
| D | `rich4-re/docs/*.txt` | 参考 | 多数正确，但属人工笔记 |

### 硬性要求

1. **凡取自 C 代码或头文件的逻辑，必须回到汇编交叉核对**，
   并在实现处写明 `@source` 指向**汇编行号**而非仅 C 文件。
2. **凡数值表，必须以 exe 二进制为基准做常驻测试**
   （见 `packages/data/src/binary-truth.test.ts`）。
3. 发现 C 与汇编冲突时，**一律以汇编为准**，并登记到
   `docs/known-deviations.md` 的 E 系列。
4. 能用原版存档/资源实证的，**优先实证**而非推理。

### 二进制表定位方法

三张数值表的地址是用**特征字节序列**唯一定位的，非猜测：

```python
# 卡片表首两项 {*,1,200,2,2} {*,2,200,2,2}
pat = bytes([0x01, 0xc8, 0x02, 0x02])
# 全文件唯一命中 → VA 0x47fdf2
```

自洽佐证：`0x47fdf2 + 30*8 = 0x47fee2` 恰为道具表地址，两表在内存中相邻。

### PE 映射注意事项

`rich4.exe` 的节表 **VirtualSize 全为 0**（老 Watcom 链接器特征），
做 VA→文件偏移换算时**必须用 SizeOfRawData**，否则所有地址都会解析失败。

```
DGROUP: VA 0x463000, RawPtr 398848, RawSize 158720
```
