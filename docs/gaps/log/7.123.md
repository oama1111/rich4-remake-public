### 7.123 ★★ 第 140 条（上一轮）：★ **发现一条已交付口径是错的** —— 魔法屋筛选器的**平手默认只留最后一个**（不是「全收」）

#### (1) 我原来写的是什么、为什么错

§7.120 把四个「极值类」筛选器（idx 0/3/4/5）的平手语义写成
「★★ **平手全收**（`jle` 走「换最大」、`jne` 才跳过 ⇒ 并列第一**同时**进结果）」，
并据此写了 `test_magic_house_extremes.py` 的平手断言（当时 23/23 通过）。

**这次的探针（10 次重复）把那个结论推翻了**：

```
idx 1（地产最多），两人各 1 块地 —— 跑 10 次：
  kind=1 -> eax=1 arr=[2, 0, 0, 0]        ← 10/10 都是这个
  分布: {(2,0,0): 10}
```

⇒ 平手时结果是 **`[2]`（只有 P2）**，**不是** `[1,2]`。

#### (2) 逐条重读骨架后，正确的口径是「后来的赢家清掉前面收的」

三支（0/1/2 与 3/4/5 同族）的尾部**逐字节相同**（已用 `read()` 逐个核对
`0x431938`–`0x431963` 与 `0x431a50`–`0x431a7b`）：

```asm
        cmp edx, [esp]        ; edx = 本候选值，[esp] = 当前最大值
        jle  L_tie            ; ★ 小于**或相等**都走这一支
        ; ── edx > [esp]：换最大 ──
        mov  [esp], edx
        test esi, esi / je L_store
        xor  edx, edx
        mov  dword [0x48c380], edx      ; ★★ **清空**结果数组
        xor  esi, esi                   ; ★★ 计数归 0
        jmp  L_store
L_tie:  jne  L_next                   ; ★ 严格小于才跳过
L_store:
        al = bl + 1
        byte [esi + 0x48c380] = al      ; ★ 写在 `esi` 处
        inc  esi
```

★ 关键在**第一轮的初值 `[esp] = edx`（= 派发器的第二实参）**：
如果那个初值是 **0**，那么「平手」根本不会发生 —— 第一个候选（值 > 0）就已经
`edx > 0 = [esp]`，走**换最大**分支，于是 `esi` 本来就是 0、**不会**清空；
第二个候选与它相等时 `edx == [esp]` ⇒ 走 `L_tie` ⇒ `jne` 不跳 ⇒ **追加**。
⇒ 那条路径才是「平手全收」。

**但初值不是 0**（实参决定），于是**第一轮就走「相等」分支**时
`esi` 已是 1 ⇒ `L_tie` 的 `jne` 落空 ⇒ 走到 `L_store`，**在 `esi` 当前处覆盖写**，
而且**没有**先 `inc` —— 两次写入落在**同一个位置**，结果只剩最后一个候选。
⇒ **默认（初值 = 0）的语义是「只留最后一个并列者」**。

#### (3) ★ 为什么这一步**没有**直接改

1. **`0x49xxxx` 那个初值的来源没查清**：它是 `0x431842` 的**第二实参**
   （`mov dword [esp], edx`，`edx` 来自 `[esp+0x20]`）。实参由**调用方**给，
   而我只测了 `call(DISPATCH, [kind, **0**])` 这一种。若某些调用方给的是
   `-1` 或「本值」，语义就会不同 ⇒ **不能**只凭一种实参就下结论。
2. **§7.120 的平手断言当时是「通过」的**，与本次探针矛盾。两种解释（测试台
   偶发、或两种实参下行为确实不同）**都还没排除**。
3. 本轮 **`.venv/bin/python` 几乎全程不可用**（`spawn sandbox-exec ENOENT`，
   约 20 次尝试只成功 1 次；恢复窗口极短），无法做「多实参 × 多次重复」的对照。
