### 7.104 ★★ 第 121 条（本轮）：`0x4198b9` 再补 **企業支**（差分 11→16/16）—— 企業格值域是 **6001..7999**

第 120 条把地块两支收进闸门（11/11）。本轮把**企業那一支**也驱动起来。

#### (1) ✅ 实测钉住的两条（字节级）

| 事实 | 证据 |
|---|---|
| **企業格值域 = 6001..7999** | `0x41a99f cmp dx,0x1770 / jbe 尾声` + `0x41a9aa cmp dx,0x1f40 / jae 尾声` ⇒ `6000` 与 `8000` 都在界外 |
| **记录 = `[0x498e7c] + (v−0x1770)×0x34`** | `0x41a9b5 xor eax,eax / mov ax,dx` → `0x41a9ba sub eax,0x1770` → `0x41a9bf imul eax,eax,0x34` → `0x41a9c2 mov ebx,[0x498e7c]` → `0x41a9c8 add ebx,eax` |

★ 注意与地块支的**基址语义不同**：地块那支 `0x4198f2` 是 `add esi,eax`（基址要减 `0x34`），
企業这支是 `0x41a9c8 add ebx,eax`（同样语义，但走的是另一段代码）。
⇒ 两条记录表的「基址」都是**第 0 条的地址**，`(v−base)` 是 **1 基**偏移、
所以 `v = base + 1` 才落在第 1 条上。

#### (2) 已拥有支 / 未拥有支的分岔（`0x41a9e0`）

```asm
0041a9cc  al = byte[企业记录+0x18]        ; ★ 企业表的 +0x18 是**所有者**（1 基）
0041a9cf  edx = [0x49910c] / inc edx      ; 当前玩家 + 1
0041a9e0  cmp eax, edx / jne 0x41ab6d     ; 不等于 ⇒ 未拥有/他人
0041a9e8  al = byte[记录+0x1a]            ; ★ 已在「已拥有」这一支
0041a9eb  cmp al,4 / jb … / jbe 0x41a9fe / cmp al,0xb / je …
```

⇒ **同一个 `+0x18` 在地块表里是「种类」、在企業表里是「所有者」** ——
这条易错点在 `game-loop.md` 早已写明，本轮在**机器上**再确认了一次。

#### (3) ❌ 仍未驱动的（如实登记）

「买企业」那条（`0x41ab6d` 那一大段里的牌价 `word[记录+0x22] × 物价`）
本轮没走到：`owner=1`（= 当前玩家）会落进**已拥有**支（零 `sprintf` 调用），
而 `owner=0` 会落进 `0x41b067`（回手）—— 都不是买地牌价那条。
⇒ 本测试对企業支**只断言格值域与记录寻址**，牌价那条留着，
并在断言文字里写明「尚未驱动成功」。
