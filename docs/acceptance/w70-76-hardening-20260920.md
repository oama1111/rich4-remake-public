## 1. 一条发送失败的连接能让整台服务器退出（严重）

`#broadcast` 与 hub 里各处**直发**都是 `conn.send(...)`，没有任何兜底。而 hub 有两条调用路径
**没有**外层 catch：

| 路径 | 谁调用它 | 抛了的后果 |
|---|---|---|
| `hub.sweepDisconnected` | `ws-server.ts` 的 `setInterval` | **未捕获异常 ⇒ 进程退出**（所有房间一起没）|
| `handle.onClose` | `socket.on('close')` 事件回调 | 同上 |

实测（`hub-fuzz.test.ts`，一条 `send` 一抛就抛的连接）：

```
$ npx vitest run packages/server/src/hub-fuzz.test.ts -t "send 抛异常"
Error: WebSocket is closing
 ❯ Broken.send packages/server/src/hub-fuzz.test.ts:97:11
 ❯ Object.onMessage packages/server/src/hub.ts:324:18      ← 修之前：直接冒到调用方
```

**修**：hub 统一走 `#sendTo(conn, msg)`（吞掉，只掐那一条 —— 那条连接自己会被 `ws` 关掉、
走到 `onClose`，掉线代打那条路接管；**别的座位照常收到**）；`ws-server.ts` 的**扫描定时器**
与 **close 回调**各加一层 try/catch（那两条路没有别的兜底）。

## 2. 连续两次超时之后「刷新页面」⇒ 那个座位从此没人驱动（严重）

重连归还（`#assignSeat`）只处理了 `takenOver`（掉线代打）：

```ts
if (back.takenOver && t.room !== null) { …setAi HUMAN… }
back.takenOver = false;
delete back.info.autopilot;        // ← 只删了「显示用」的那一个字段
```

**超时託管**（`autopilot === 'idle'`）时镜像里的 AUTOPILOT 位没人清 ⇒
`#shouldTime` 从此不给他计时、`#driveComputers` 又认不出他（它只认 `takenOver` 与 `autopilot`）
⇒ **这一桌永远停在他这一回合**。

实测（红）：

```
重连之后 whoPlays = 5（5 = 真人|托管）
AssertionError: expected 5 to be 1
```

**修**：归还条件扩成 `takenOver || autopilot === 'idle' || pendingRestore`，
并把 `pendingRestore` / `strikes` / `lastAwaitingSeq` 一并清干净。

## 3. `Room.submitSystem` 会把镜像**永久**弄坏

`Room.submit` 有「`reduce` 返回 `undefined` 就拒」那道闸（注释里写得明明白白：
「网络来的 action 不可信」），**`submitSystem` 没有**：

```
submitSystem 抛了 = TypeError: Cannot read properties of undefined (reading 'turnCount')
之后还能取指纹吗 = 抛了：TypeError: Cannot read properties of undefined (reading 'turnCount')
```

⇒ `#mirror` 被换成 `undefined`，**这个房间从此每一次取指纹都抛**。
眼下只有服务器自己用 `setAi` 调它，够不到这条路；但两条路必须对称，不然下一次加系统 action 就踩上。

**修**：补上与 `submit` 同样的 `undefined` 闸。

## 4. 登录限流可以被 `X-Forwarded-For` 绕过（E-37）

任务书 W-71 §2 写的是「按 `X-Forwarded-For` **最左一段**分桶」，而 Caddy 的 `reverse_proxy`
对这个头是**追加**（`<客户端自己带的>, <真实来源>`）—— **最左那段是客户端自己写的**。
每次换一个假值就是一个新桶 ⇒ 5 次/分钟的上限形同虚设。

**修**（`gate.ts` 的 `clientIp`）：① 只认**对端是回环**的 `X-Forwarded-For`（直连一律用 socket 地址）；
② 取**最右**一段。

端到端实测（真服务器，每次左段都换、右段固定 = Caddy 追加的真实来源）：

```
第 1 次（假值 1.1.1.1）→ 401
第 2 次（假值 2.1.1.1）→ 401
第 3 次（假值 3.1.1.1）→ 401
第 4 次（假值 4.1.1.1）→ 401
第 5 次（假值 5.1.1.1）→ 401
第 6 次（假值 6.1.1.1）→ 429      ← 换不掉桶了
```

⚠️ 这与任务书写的「最左一段」**相反** —— 已登记 **E-37** 请首席确认；
若坚持最左，正确做法是在 Caddyfile 里 `header_up X-Forwarded-For {remote_host}`（**覆盖**）。
