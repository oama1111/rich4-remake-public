### 7.66 ★ 第 85 条（本轮）：上一轮改动的**副作用**——惡人段那条路径漏了一天（自己抓到自己）

#### (1) 怎么发现的

第 84 条把递减从"旧玩家"挪到"新当前玩家"之后，进入下一位玩家有**两条**路径：

| 路径 | 谁把"轮到下一位"写进状态 | 第 84 条之后是否会走那一天 |
|---|---|---|
| 常规 | `endTurn` 自己（`nextAlivePlayer` → `turnStart`） | ✅ |
| ★ **惡人段**（棋盘上有惡人时**每一輪**都走） | `npcStep` → `npcRoundStep` 收尾 | ❌ **漏** |

第 84 条当时只改了 `endTurn`，于是「一輪的惡人逐个走完之后」那一条路径**不给新玩家递减**。
后果不是小数目：**每一輪**都会漏掉同一位玩家的一天（惡人在盘上是常态）
⇒ 该玩家的在押/住宿/冬眠/保险**永不到期**。

★ 全套 5,116 条测试当时**全绿** —— 说明没有任何测试盯住"惡人段之后新玩家的一天"。

#### (2) 先写测试、确认它真的红，再修

```ts
// state/npc-round.test.ts
it('★★ 惡人段走完后，下一位玩家的「一天」照样要走（第 85 条）', () => {
  const withSleep = ...players[0].blocking.sleeping = 5...;
  let t = reduce(withSleep, { type: 'endTurn' }, ring);      // 走第 1 个惡人
  while ((t.pendingNpcSlots ?? []).length > 0) t = reduce(t, { type: 'npcStep' }, ring);
  expect(t.currentPlayer).toBe(0);
  expect(t.players[0]!.blocking.sleeping).toBe(4);           // ← 修前红：实际 5
});
```

#### (3) 修法：把「给新玩家走一天」抽成**唯一**一份 `beginActorTurn(state, topo, index)`

- `endTurn`（常规路径）与 `npcStep`（惡人段收尾，判据 = `npcRoundStep` 把相位切到了 `turnStart`）**两处都调它**；
- `npcRoundStep` 自己**不**调（否则同一 action 内走完时会与 `endTurn` 重复跑一天）；
- 函数头写清 `@source 0x418f95 → 0x41902e → 0x419039`（游标先 ++ → 推日期 → 递减），
  并注明"两条路径都必须调它"。

#### (4) 机械闭环
