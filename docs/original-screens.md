## 0. ★ 工具列的 11 颗按钮 —— 全部定死了

需求方给出前三颗（遊戲百科／設定／託管AI），其余九颗由截图 + 热键表**闭合验证**：

剩下的**恰好十一条**，与工具列**一一对上**，顺序基本是热键表的倒序：

十一比十一、无一多余，故这张表可以当结论用，不再是「按图标外观猜的」。

★ **S6 里小地圖左上角那两颗蓝／紫圆箭头 = `地圖向左旋轉` / `地圖向右旋轉`。**
这就是需求方早前问的「切換視角」功能所在，不在工具列里。

**摆位与命中（2026-09-15 从 exe 补上，先前是照底条图反推的）**

```asm
00415d81  mov eax,ebx / shl 2 / add eax,ebx / shl 3   ; eax = i * 40
          add eax, 0x14                                ; ★ 画点 x = i*40 + 20
00415dc5  push 0x14                                    ; ★ 画点 y = 20（常态与悬停**同一个 y**）
          lea edx, [ebx + 1]                           ; 图号 = i+1（i+12 是悬停那一版）
          call fcn_00456418                            ; 带锚点：落点 = 画点 − 图自带的 x/y
loc_00418b0a  mov ebx, 0x28 / idiv ebx                 ; ★ 命中 = x / 40
              cmp esi, 0x1b8                           ; x ≥ 440 → 不在工具列
              cmp edx, 0x28                            ; y ≥ 40  → 不在工具列
```
即 **11 格 `[40i, 40i+40)`、从 x=0 起、铺满 440**，与底条图（439×40）无关。
⚠️ 先前照底条 439 宽反推成「间距 39、两侧各留 5」—— 拿底条宽去凑按钮格，
于是最左那颗偏右 4.5px、最右那颗偏左 5.5px（需求方 2026-09-15 报的现象）。
**悬停高亮**是 `[0x48bde4]`（WM_MOUSEMOVE 里按 `x/40` 更新、移开置 −1），
与「按下」用的 `[0x48be28]`（WM_LBUTTONDOWN 写）是**两个变量** —— 没按也会亮。

0041e594  for (i = 0; i < 玩家数; i++) {

**⚠️ 档案订正（T-021 实现时实测）**

入口的 `[0x48a05c]` **不是 Data.mkf**（`[0x48a0e4]` 才是，见 `assets.ts` 角色精灵那段）。
两个都解出来看：

| 档案 | 资源 77 |
|---|---|
| `Data.mkf` | 80000 字节、头 `ff 26 de 22`，`parseSpriteSheet` 解不出来 |
| **`Panel.mkf`** | **SMP 18 张，图 0 = 435×355 的对话框底图** ← 就是这一屏 |

图 0 渲染出来正是那张绿面板（左侧木纹条、右侧粉条上两颗米色按钮、中间五个圆点、
底部两条滑槽），与截图完全一致。资源内的分工：图 1/2 = 选项行底色的**亮/暗**两态
（实测暗 = 亮整体压暗约六成）、图 3 = 圆点单图、图 4/5 = 滑槽箭头、**图 6..17 = 12 个
角色头像**。

**截图证实的两件事**

1. **这一屏只列「人類」座位**（`+0x15 & 1`）—— 所以截图里只有一个头像（孫小美）。
   **托管 = 把自己的座位交给 AI**，不是调对手的 AI。
2. 左侧那颗 LED 就是**托管总开关**（改 `+0x15`）。

**★ 由此修正一条既有结论：`+0x17` 是「個性」，不是「保釋倾向」。**

`personality.ts` 现在把 `+0x17` 注为「保釋倾向 0/1/2」。截图上它明确写着
`個 性：乖寶寶 / 普通人 / 大老奸`，而 exe 里它是一条**通用闸门**：

```asm
0041e69e  ; gate(action)
0041e6a4  edx = [0x47fdf1 + action*8]        ; 每个 AI 行为的「所需个性」
0041e6b2  eax = 當前玩家.+0x17                ; 自己的个性
0041e6bd  edx -= eax
0041e6c1  if (edx >= 2) return 0              ; 差两档以上：从不做
0041e6c9  if (edx == 1 && rand()%3 != 0) return 0   ; 差一档：1/3 概率做
0041e6e6  return [0x475324 + action*4]()      ; 够格：照做
```

即「乖寶寶只做温良的事，大老奸什么都做」。保釋只是**受它管的诸多行为之一**。
行为表 `0x47fdf1`（步长 8）与跳表 `0x475324`（步长 4）是 M3 的下一块硬骨头。

## S13 · 公佈欄（工具列 #10）★ 整屏

上一轮从汇编里把规则做出来了，截图给出画面与**两条新信息**：

  格子 = 商品图标 + 下方一条淡蓝标价条）。
- **右上两颗按钮**：`SALE 💰`（上架）与 `EXIT 🚪`（离开）。
- **右下角**趴着一只**大黄猫吉祥物**。
- 点自己的挂件弹出**绿色详情框**：

  ```
  ┌ 孫小美 ─────────────── [商品图] ┐
  │  類型 :        路障              │
  │  市價 :     3,000元              │
  │  賣價 :     8,200元              │
  │      [ 撤件 ]   [ EXIT ]         │
  └──────────────────────────────────┘
  ```

**★ 新信息一：「市價」的算法被截图证实了**

截图里 `路障` 的**市價 = 3,000元**。而 `data/tools.ts` 里 `路障.price = 30`，
当时的**物價指數 = 1**（S6/S7 都显示 `物價指數 1`）。

```
30 × 100 × 1 = 3000  ✓
```

即 `notice-board.ts` 里那条 `標價 × 100 × 物價指數`（`CARD_LIST_MULTIPLIER = 0x64`，
@source 0x00428935）**对道具同样成立**，且**这就是 UI 上「市價」那一行**。

**★ 新信息二：「賣價」是卖家自己填的**

`8,200` 既不是市價的整数倍也不是任何档位价，故上架时有一个**输入价格**的步骤。
引擎里 `listItem()` 的 `price` 字段正对应它，UI 需要提供输入框。

**待补**：`撤件` 按钮 = 已实现的 `withdrawItem()`；`SALE` 按钮 = `listItem()`。
★ 输入价格的**上限**＝市價 × 10（股票例外＝持有股數）：`0x453544` 把它存进 `0x48ca98`，
越界输入在 `0x4531f6`（`cmp eax, edx / jle`）处被就地夹回上限——已实现，
见 `board-screen.ts` 的 `LIST_PRICE_MAX_FACTOR`。
（`known-deviations.md` 的 Q-BOARD-1 已于 2026-09-14 结案，四种市價全解。）
