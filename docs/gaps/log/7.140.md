#### (2) ★★★ 订正一：**「放弃转嫁时嫁祸卡照样被消耗」是错的**（§四之二 第 11 条的括注）

§四之二第 11 条写着「放弃转嫁时嫁祸照样被消耗（原版在 `cmp eax,-1` **之前**就扣）」。
`test_passive_cards.py` 逐指令 + `UC_HOOK_CODE` 直证**相反**：

```asm

004449ea  je   0x444a53          ; ★ 放弃 ⇒ 直接走人，**不经过扣卡点**
004449ef  call 0x441343          ; remove_card(target, 19)
```

（真人放弃出口 `0x444863`、电脑放弃出口 `0x444973` 都落在 `0x4449e7` 上。）
⇒ **放弃转嫁 / 无人可嫁 ⇒ 19 留在手里**；只有真的改写了目标才扣。

**修法**：`cards/passive.ts` 的 `applyDefensiveCards` 不再消耗 19（只报触发）；
`cards/frame.ts` 与 `cards/sleepwalk.ts` 在 `picked != -1` 之后才 `consumeCard(…,19)`。
这正是 §7.139(6) 记的「旧测试钉死 bug」的**第 9 次**：`frame.test.ts` 里那条

#### (3) ★★★ 订正二：`0x437d1a` **有调用者** —— §7.19 的「忠实于无调用者」不成立

`gen/functions.json` 的 `callers` 是空的，但那是 `root=speculative` 口径问题。
字节级证据：

```asm
00438240  e8 d5 fa ff ff   call 0x437d1a     ; 前一条 2e ff 15 … 长 7 B，边界对齐
00438245  mov [0x48c42f], al                 ; ★ 返回值 = 悲情人物在候选表里的下标
```

下游 `0x43853b mov al,[0x48c42f] / mov al,[eax+0x48c418]` 映射回玩家 id 画立绘；
`0x4383a1` 置状态 2，由 `0x439196 jmp [eax*4+0x437e35]`（5 项表）分派 —— 是月结屏的常规一支。

⇒ 两条后果：
1. **`+0x44`（衰運）真的影响玩法**（决定「本月悲情人物」是谁），
   §7.19「`+0x44` 唯一读者是死函数 ⇒ 神明三项修正对玩法无影响」**后半作废**；
2. 复刻**核心 `rules/monthly.ts` 空转、`client/monthly-screen.ts` 自抄了一份**

**顺带修掉的两个真问题**：
- **字段名与 exe 的 UI 语义相反**：exe 自己的串是 `0x464def`「本月意外損失：」画在

  把 `+0x5c` 叫 `windfall`、`+0x60` 叫 `unexpectedLoss`。已按 exe 语义对调命名

  `−2147229796`；`+0x5c=0x7fffffff`、`+0x60=−1` ⇒ `−2147483648`），复刻的 JS number 不回绕。
  `monthlyScore` 已显式 `| 0`，并补 2 例边界断言。

#### (5) ★★★ Q-TOOL-3 结案：**原版 AI 会放核彈**，remake 的推论错

`tool-policy.ts` 的注释推断「`0x40a0b1(x,y,-1)` 的半径 −1 = 全图 ⇒ 中止判据恒真 ⇒
原版从不放核彈」，因而把 13 放进 `AI_NEVER_USES`。`test_nuke_card_ai.py`（113/113）证明**不成立**：

- 半径 −1 属实（`0x00421f92 push -1`，差分逐次实测恒 `0xffffffff`）；
- 但 `0x40a0b1` **不是** `0x40a45c(r)`：它先 `memset(0x474938, 0, 0x5e880)` 清空**整张** 440×440 实体图，
  再只把**格距 ±0xe = ±14 格**内的有主地块/設施写进去（`0x40a232 add ebx,0xe` / `0x40a251 cmp ebx,0x1c`），
  玩家标记只画**当前玩家**、被关押时不画；`r` 只决定**扫这张图多大**（`-1 → 0x1b8` = 全图）。
- ⇒ 中止判据的真实语义是「**我的棋子在候选 ±448px 内**」，对远处候选**为假**，
  于是走到「我的产业占比 `< 1/(存活数+2)`」那一支 ⇒ **发**。

`rules/tool-effects.ts` 的 `NUKE_RADIUS = -1` 本身没错；错的是 AI 侧把
「扫描窗口半径」与「效果伤害半径」（`0x40ac7b` 才把半径转交 `0x40a45c(r)`）混为一谈。
**修法（未做，见 (6)）**：补 `hedan` handler 并把 13 撤出 `AI_NEVER_USES`。
