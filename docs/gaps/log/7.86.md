### 7.86 ★★ 第 103 条（本轮）：**時光機還原 `0x448544`**整段差分（34/34）—— 28 个快照区与复刻表**逐项相同**

#### (1) 通道 2 差分：`rich4-spec/tests/test_restore_last_state.py`（34/34）

`0x448544` 是通道 2 工作单第 2 名（1338 字节）；它把**每个玩家一块 10,008 字节
（`0x2718`）的快照**（`0x48cb80 + p*0x2718`）搬回全局。本测试**不靠人工抄表**：

1. **两趟不同花样 + DGROUP/.bss 做差**（花样 `p2 = p1 ^ 1` ⇒ 逐字节都不同，差集**恰好**
   等于被还原的区）；
2. **反汇编扫描**两种搬运形状 → `(快照源偏移, 目标全局, 长度)`：
   - memcpy：`push <长度>` …乘加链 `… + 0x48cb80 + K`… `push eax` `push <全局>` `call 0x456de8`；
   - 单字段：`mov <reg>, dword ptr [<reg> + 0x48XXXX]` + `mov dword ptr [<全局>], <reg>`。
     ★★ 这一支的基址是 **`0x48f240`**（= `0x48cb80 + 0x26c0`）——**同一个块的另一种寻址**，
     只看字面地址会以为是「另一张表」（我第一遍就卡在这儿）。

结果两条独立路径**吻合**：

| 事实 | 值 |
|---|---|
| 区数 | **28**（与复刻侧 `SNAPSHOT_REGIONS` 表长一致）|
| 快照偏移集合 | `[4, 8, 424, 504, 1608, 1668, 1728, 1758, 1768, 1772, 8684, 9068, 9500, 9836..9864, 9868, 9904, 9912, 9920, 9924, 9928, 9964]` —— **与复刻侧逐项相同** |
| 逐区字节 | 目标 == 快照花样 `p1(源偏移 + j)`（逐区逐字节，唯 12 支股票首 dword 例外）|
| 收尾重绘 | `if (i < 人数) 画; else if (i < 4) 跳过; else 画` ⇒ 4 人局重绘 0..8、0 人局重绘实体槽 4..8 |
| 地图 | `memcpy([0x47493c], [p*0x2718 + 0x48f294], [0x498e94])` —— 每玩家的**地图副本** |
| 角色表回填 | 玩家结构 `+0` ← `0x47e80c + character*0x68`（**函数自己写的**，不是快照内容）|
| ★ 股票首 dword | 12 支股票每笔的**首 dword 不在快照里**（还原后被另一处写入覆盖 ⇒ 两趟花样在该处相同）|
| 快照块边界 | `0x48cb80 + 4*0x2718 = 0x4967e0`（正好接上公佈欄，互不重叠）|

打桩：`0x456de8`（CRT memcpy，本仿真器跑不了）用 `rep movsb` 版；
★ **必须 `pushad/popad` 包住** —— `0x448544` 全程用 ebx 当循环计数，
桩里不保存就会把调用方寄存器打乱（现象是后面某次 memcpy 写到未映射地址）。
