## 0. 一句话

网页版在进標題畫面**之前**一次下完 7 个档案（含 Speaking / Effect），带一条只有百分比的
进度条；下完的字节进 Cache Storage（键带 `?v=<sha256 前 8 位>`）—— **刷新后 7 个 `.mkf`

### 1.2 单测

`asset-loader.test.ts` **21 条**：首次 7 个都走网络且都 `put`；第二次素材 **0 次请求**
（只剩那一次 `cache: 'no-store'` 的清单探测）；版本变了 ⇒ 旧键被删、**只重下变了的那一个**；
进度单调不减且终值恰好 = 7 个 `size` 之和；长度不符 ⇒ 重试 2 次后整体失败；
缓存里那份长度不对 ⇒ 删掉重下；`caches` 缺席 ⇒ 静默降级成纯 `fetch`；
并发峰值 ≤ 3（实测 3）；没有清单 / 清单少一个 ⇒ 退回逐个按名字拉、不进缓存、不报进度。

## 4. 已知 / 未做

- **E-28**：`assets-manifest.json` 必须加进 W-70 的素材白名单，否则客户端吃到 404
  （实测确认）。已加，并给它 `no-cache`（它是版本指针，标 `immutable` 会一直发旧版）。
- **E-29**：清单里登不登记 `hd-manifest.json`，判据是「清单在**且** `assets/hd/` 非空」——
  仓库里那份清单一直在（3.9 MB），只看它就会白拉。E-26 由此结清。
- 桌面壳（`isDesktop()`）一行没变：仍然边拉边开那 5 个基础档案、`ensureSpeakingArchive()`
  仍按需拉 Speaking.mkf、Effect.mkf 仍后台拉。
- 没有 Service Worker；素材没有打进 `dist-web`；`MkfArchive` / 解码器一行没动。
- 本次验收**没有**用 DevTools 的 Fast 3G 限速（无头 CLI 里设不了）：进度条是在
  真实网速下采到的中间值（3%…37%）。限速下应当只会把同样那几档拉长。
