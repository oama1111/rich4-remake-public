### 7.85 ★ 第 102 条（本轮）：**两张事件牌堆的洗牌**整段差分（19/19）—— 复刻的洗牌现在可判定「与原版同一个排列」

#### (1) 通道 2 差分：`rich4-spec/tests/test_deck_shuffle.py`（19/19）

命運 `0x44baea`（37 张 → `0x496b38`）与新聞 `0x448b81`（36 张 → `0x499090`）
是**同一段代码**，本轮第一次整支驱动：

```asm
0044bb1f  mov edx,eax / sar edx,0x1f / idiv esi   ; ★ 用的是 edx = **余数**
                                                  ;   ⇒ k = rand() % 剩余数（不是商！）
0044bb30  cmp byte [esp+eax],0 / dec edx           ; 只对未使用槽计数
0044bb37  test edx,edx / jl adopt                  ; k 归零 ⇒ 就用这个槽
0044bb0d  mov byte [ebx+0x496b38], al              ; deck[placed] = 槽号 = 事件号
0044bb3f  mov dword [0x4990b4], 0                  ; 游标清零
```
⇒ 「**选择采样**」而非 Fisher-Yates。「商」被 `xor eax,eax` 丢掉了 —— 这一处容易读错
（我第一遍就把它当成 `rand()/剩余数`，那样会推出「最后一格恒为 37」的假结论）。

| 钉住 | 值 |
|---|---|
| `rand()` 消耗 | **恰好 = 牌堆张数**（37 / 36）|
| 全 0 序列 | 退化成 `[0,1,2,…]` |
| 恒定 32767 | `k = 32767 % 剩余数`（余数随剩余数变）|
| 两条固定序列 | 排列与模型**逐项相同**、是合法排列、游标清零、前后哨兵未动 |

#### (2) ★★ 复刻侧从「都是排列」升级为「同一个排列」

`packages/core/src/events/deck.ts` 的 `shuffleDeck()` 早已照抄这段（注释很准），
但测试只验了「是 0..n−1 的一个排列」+「消耗 size 次」。本轮把 exe 的两条固定序列
搬进 `deck.test.ts`（喂 `below(n) := SEQ[i] % n`），断言**逐项等于 exe 的排列**
（命運：[24,12,7,8,35,1,18,0,…]；恒定 32767：[22,7,8,28,35,36,0,…]）。
⇒ 「复刻洗牌 == 原版洗牌」现在是**可判定**的，而不是「都恰好是排列」这种弱性质。
（用户口径仍是不要求位级一致；这里能对上是因为**算法本身**照抄了。）
