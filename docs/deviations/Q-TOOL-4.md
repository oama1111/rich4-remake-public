## ① 回 exe 读全道具 9

函数就是 `rich4_use_tool_jiqigongren`，**VA 0x00447295**。下面是直接反汇编
`Rich4/rich4.exe` 得到的全文（`python3 tools/disasm.py va 0x00447295`）：

0044729c  edx = [0x49910c]                     ; 当前玩家
004472a7  al  = [player + 0x13]                ; 角色号 → 台词表
004472b0  ecx = [0x480d7a]                     ; _tool_strings + 32 = 第 9 条台词
004472ba  call 0x44ef41                        ; rich4_player_say(...)
004472c9  cmp byte [player + 0x15], 1          ; 行动者是电脑？
004472d0  jne 004472de
004472d2  push 0x2090006 / call 0x446ae8       ; ★ 真人：select_instance_with_mouse(0x2090006)

### 1.1 效果本体 `fcn_0040b110`（VA 0x0040b110）：免费、不看归属、住宅上限 5

```asm
0040b110  edx = 参数（**实例编码**，不是节点号！）
0040b117  cmp edx, 0x7d0 / jle 0040b170        ; ≤ 2000 → 不是地块
0040b11f  cmp edx, 0xfa0 / jge 0040b170        ; ≥ 4000 → 不是地块
0040b127  ecx = (edx - 0x7d0) * 0x34           ; ★ 地块下标 = 实例编码 - 2000
0040b138  cmp byte [land + 0x18], 0 / jne …    ; type == 0（住宅）
0040b13e  cmp byte [land + 0x1a], 5 / jae …    ; level < 5
0040b144  eax = 1
0040b149  cl = [land + 0x18] / cmp cl, 1       ; type == 1（連鎖店）
0040b151  cmp cl, [land + 0x1a] / jbe …        ; 1 <= level → 不可建（即只有 0 级可盖）
0040b161  cl = [land + 0x1a] / inc cl / mov [land + 0x1a], cl   ; ★ level++
0040b169  cmp cl, 5 / jne / or al, 0x80         ; ★ 刚满 5 级 → 置 bit7（给 0044736d 用）
0040b170  cmp edx, 0xfa0 / jle 0040b21f
0040b17c  cmp edx, 0x1770 / jge 0040b21f
0040b188  ebx = facility_info + (edx - 0xfa0) * 0x38
0040b1a0  cmp byte [ebx + 0x1a], 0 / jne 0040b1f9 ; 設施等级
0040b1ad  test byte [player + 0x15], 6          ; 电脑 / 托管？
0040b1c1  owner == 当前+1 → type = rand()%4+1 ; 否则 type = 0（公園）
0040b1e2  真人 → 种类 = fcn_00440aac(0)          ; ★ 真人要选种类的那一屏
0040b1ef  level = 1
0040b1f9  level >= MAX[type]（表 0x474940）→ 失败；否则 level++
```

**逐条回答需求方给的四个问句：**

| 问题 | exe 的答案 | 依据 |
|---|---|---|
| 要求什么目标？ | **任何**地块或設施的实例 —— **不看归属**（自己的、别人的、无主的都行） | 0x40b110 全文没读 `+0x19`（owner） |
| 效果是什么？ | 住宅：**等级 +1**（上限 5，硬编码）；連鎖店：**只有 0 级**能盖到 1 级；設施：0 级 → 先定种类再盖到 1 级，否则 +1（不超该种类上限） | 0x40b138..0x40b16e / 0x40b1a0..0x40b21f |
| 钱从哪出？ | **完全免费** —— 这条路上没有任何金额运算（不是「房价 × 物价」） | 同上 |
| 上限从哪来？ | 住宅是**立即数 5**；設施是种类表 `byte [type + 0x474940]` | 0x40b13e / 0x40b1f9 |
| 前置？ | 只有「等级没到上限」；**无主地、别人地、没钱都能盖** | 同上 |
| 用完之后的表现？ | `read_mkf(data_mkf, 0x229)` 的大锤动画 + `0x41d476` 落点 + 满级那一下 `0x40b0cd`（资源 `0x20b`）→ 最后 `refresh_screen` | 0x447325..0x447378 |

★ **「只能盖自己的地」不是效果的限制，是 AI 判定函数 `0x421ba6` 在做选择**
（`mov bl,[eax+0x19]` / `inc edi` / `cmp ebx,edi` / `jne 跳过` —— owner 必须是「当前玩家+1」）。
真人那条路（`0x4472d2` 的 `push 0x2090006`）没有这道过滤，`0x40b110` 也没有。
所以 `ai/tool-policy.test.ts` 里「别人的地产不盖」测的是**AI 判定**，不是规则。

### 1.2 拾取参数 `0x2090006`：只认**地块与設施**，不认路面

`_rich4_select_instance_callback`（VA 0x00445e4d）的悬停判定按参数低 16 位的
**类别位**逐条 `test byte [0x48c594], X`：

| 位 | 含义 | 判定 VA |
|---|---|---|
| `0x1` | **格子**（路面；实例值 < 2000） | 00446235 |
| `0x2` | **地块**（2000..4000，路边的**白格/建筑**） | 0044624e |
| `0x4` | **設施**（4000..6000） | 0044627d |
| `0x10` / `0x20` | 玩家棋子 / 特殊棋子 | 004462b3 / 004462e7 |
| `0x8` | 「目标必选」（右键不许取消） | 004466b8 |
| `0x80` | 光标贴边推镜头 | 0044609b |
| `0x40` | 「什么都收」：初始化时展开成 `0x37` 并**清掉 bit3** | 00445ec1 |

機器工人的 `0x2090006` 低 16 位 = **`0x0006`** → 只有 bit1|bit2。
即**光标压在路面上是「不能选」（红叉），压在建筑/白格上才行**。

### 1.3 命中是**像素级实例表**，命中的是「画在那儿的那个实例」

```asm
00446229  call 0x40a9d7            ; _rich4_get_instance_from_position(x, y)
0040a9d7  … eax = word [0x474938][440 * y + x]   ; ★ 每屏幕像素一格的实例表
```

而地块/設施是按**各自的记录坐标**画的：
`004090fc  movsx eax, word [ebp]` / `movsx edx, word [ebp+2]`（`ebp` = 地块记录）。
`known-deviations.md` 的 Q-LAYOUT-4 已钉过这件事：
「**建筑在路边的白色格子里，不在路面上**」，地图 1 的 node 39 (1463,239) ↔ land 1 (1463,192)。

## ② 我们现在为什么用不了

**两件事，一件是需求方的预期与 exe 不符，另一件才是真 bug。**

### 2.1 规则层本来就是通的（不是缺口）

给玩家 1 件道具 9、把某块地的 owner 写成本人，`canUseTool` 与 `useToolAction`
都返回「生效」（见 ④ 的测试）。先前 `tool-landing.test.ts` 也一直是绿的。
需求方预期的另外三条**与 exe 相反**（按铁律以 exe 为准）：

| 需求方的预期 | exe 的真相 | 依据 |
|---|---|---|
| 别人的地 → 不生效 | **生效**（替他盖一级） | 0x40b110 不读 owner |
| 无主地 → 不生效 | **生效**（盖完仍无主） | 同上 |
| 钱不够 → 不生效 | **生效**（完全免费，现金分文不动） | 同上 |

（真正「只认自己的地」的是 AI 的判定函数 `0x421ba6`，见 ①。）

### 2.2 真 bug：候选**挂在节点（路面）上**，而用户点的是白格/房子

`packages/client/src/picking.ts` 的 `pickCandidates` 先前把**所有**候选一律放在
`node.x / node.y`。而：

- 地图 1 实测，同一块地的**地块记录**与**节点**在人物视角下相差
  **屏幕 41.15 .. 65.73 像素**（**全部 50 块地 × 8 个视角**逐个量过；
  镜头停在那一格时，4 个正交视角分别是 44.4 / 53.5 / 42.5 / 54.8 …）；
- `hitCandidate` 的命中半径是 **24** 像素（照抄 `render.ts` 的 `pickNodeAt`）。

于是 **41 > 24 —— 用户点自己的白格/房子永远落在候选之外**，
指针是红叉、抬手只播一声失败音（`main.ts` 的拾取分支），看起来就是「用不了」。
更巧的是機器工人的类别位**恰好只要地块/設施、不要格子**（①1.2），
所以它可点的区域与用户会去点的地方**正好相反**：

| | 原版 | 先前本引擎 |
|---|---|---|
| 光标压在**白格/建筑** | 機器工人光标（可选） | **红叉** |
| 光标压在**路面（节点）** | **红叉** | 機器工人光标（可选） |

同一个 bug 也影响**所有以地块为目标的卡片**（換地/漲價/查封/天使/惡魔/拆除…）：
它们同样只能点到路面、点不到那栋房子。

## ③ 改在哪

只动 `packages/client/src/picking.ts`（**不含任何规则**这条没破：合法性仍然全问 core）：

1. 新增 `PICK_CLASS`（类别位）与 `pickClasses(param)`（①1.2 的 `0x401` 规范化，
   含 bit6 → `0x37`、顺手清 bit3）；
2. 新增 `instanceAnchor(topo, node, classes)`：按类别位把候选落到**实例自己的绘制坐标**——
   地块 → 地块记录的 `x/y`、設施 → 設施记录的 `x/y`、格子 → 节点 `x/y`；
3. `pickCandidates` 收下 `param`：道具按类别位分流（機器工人 → 白格/建筑；
   路障/地雷/炸彈/傳送機 → 路面；飛彈/核子 = `0xc0` 展开成 `0x37` → **两处都算**）；
   卡片按目标种类（`entity` / `facility`）落到对应实例；
4. `startPick` 的 `cancellable` 改读**规范化之后**的类别位（与 0x4466b8 一致）。

`core` 一行没改：`useTool` 的目标契约本来就是这个引擎的**节点号**
（`actions.ts` 的注释、AI 的 `toToolAction`、UI 都按它），内部自洽。
★ exe 那边传的是**实例编码**（2000+下标 / 4000+下标），本引擎用节点号 ——
这是既有的架构选择，不是本次的缺口，**未改**（见 ⑤-4）。

## ⑤ 没解出 / 有意不做 / 仍存的偏离

1. **真人用機器工人盖「等级 0 的設施」要先选种类**（`0x40b1e2` 的
   `fcn_00440aac(0)`，那是另一屏 UI）。本引擎没有那一屏，`useTool` 的 `value`
   缺省 0 会被 `freeBuildFacilityById` 当成**公園**。与 Q-CO-1（建設公司同一条）
   同类，**未做**。当前表现：真人对 0 级設施用機器工人 → 盖上公園。
2. **消耗时机**：exe 是「选到就扣」（0x004472fb 在 0x00447345 之前），
   连盖不动的地也扣。本引擎的既定口径是「只在真正生效时才收走道具」，
   且 UI 不会把盖不动的地列成候选，**观察不到差别**，未改。
3. **命中仍是「半径 24 的圆 + 实例锚点」的近似**，不是原版那张 440×440 的
   **像素级实例表**（`0x40a9d7`）。像素表要等距投影与镜头，属表现层近似
   （与 `render.ts` 的 `pickNodeAt` 同一取舍）。建筑精灵很高，锚点在脚下，
   极端取景下边界可能与原版差几个像素。
4. **`useTool` 的目标编码**：exe 传实例编码（2000+下标 / 4000+下标），本引擎传节点号。
   自洽，**不改**；若日后要让 AI 判定函数照抄原版的 `[0x48be64]` 语义，再统一。
5. ~~**bit7「光标贴边推镜头」仍未做**（Q-PICK-1）~~ ✅ **已接并目视验收（2026-09-16）**：
   四条边、方向箭头（34/40/38/36）、`SetTimer(…, 0x32, 0)` 的 8→12→…→68 步长、
   钳位 [220, 2084] 全部实测对上；另订正了一处**移植版特有**的 bug（非整数倍
   缩放下「下边」那一条相等判据取不到 ⇒ 先 `Math.round` 量化回舞台像素）。
   规格与实测数据见 `docs/known-deviations.md` 的 Q-PICK-1。
6. ~~**表现层未接**：大锤动画（`data_mkf` 资源 `0x229`）、満 5 级那一下
   （资源 `0x20b`，`0x40b0cd`）、以及 `0x41d476` 的落点。属 T-026 / Q-TOOL-1 同一类。~~
   ✅ **已接（Q-TOOL-6）**：大锤 `Data.mkf` **0x229**（68 帧 × 57 ms、440×440、
   落点屏幕 `(0, 0x28)`）+ 剛滿 5 級的 `0x20b`（66 帧 × 42 ms）
   —— 规格与逐条 VA 见 `docs/deviations/Q-TOOL-6.md`，落码在
   `packages/client/src/build-fx.ts` + `main.ts` + `render.ts`。
   `0x41d476` 的**强制镜头对准**仍未接线（本引擎相机是人控的），同样登记在 Q-TOOL-6 ⑤-2。
7. **工程車（12）仍不在 `TOOL_SELECT_PARAM` 里**（原版不调拾取函数，目标来源没跟）。
