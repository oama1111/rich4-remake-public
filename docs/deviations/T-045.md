## D-045-1（订正 · 已修）8 行格图（图 **2 / 3**）原来**整个没画**

### 一、上一版错在哪

上一版把「原版那些 `add eax, imm`」的图号按 **`imm / 2`** 读，得出：

```text
0x18 → 2（章名条）、0x24 → 6、0x30 → 7、0x3c → 4、0x48 → 5
```

**真值是 `index = (imm − 0xc) / 12`**（图像记录从资源数据 +0xc 起、每项 0xc 字节；
同一结论见 `assets-pipeline/src/mkf.ts:176` 与 `monthly-screen.ts:149`）：

```text
0x0c → 0   0x18 → 1   0x24 → 2   0x30 → 3   0x3c → 4
0x48 → 5   0x54 → 6   0x60 → 7   0x6c → 8   0x78 → 9
```

于是上一版把**图 1**（66×33 章名条）当成了图 2、把 `(108, 78+34i)` 那 8 张格图
（图 **2** 常态 85×33 / 图 **3** 选中 87×33）**整个漏掉**，还用「图 6/7 是珊瑚底三角、
贴上会盖掉绿带」这个**基于错图号**的观察把它登记成了「有意不画」。
实测 `assets-clean/help/0000_0NN.png`：6 = 20×18、7 = 18×14（那一族是珊瑚底小三角），
**根本不是** exe 在这里画的两张。

### 二、现在的画法（逐条照 exe）

@source `loc_0044e301`（画）+ `loc_0044e2b2`（名字）：

```asm
; ① 8 张格图（一轮）
0044e301  mov esi, [eax*4 + 0x4761c4]   ; entry + 0x10 = 滚动位置
0044e315  add esi, ebx                  ; + 行号 i
0044e317  cmp esi, [eax*4 + 0x4761c0]   ; 与 entry + 0x0C（资源数）比
0044e31e  jge 0x44e376                  ; 越界 → 两轮都停
0044e320  mov ecx, [0x48c5e4] / add ecx, 0x6c      ; x = 面板.x + 108
0044e329  mov eax, ebx / shl eax,4 / add eax,ebx / add eax,eax
0044e332  add eax, [0x48c5e8] / add eax, 0x4e      ; y = 面板.y + 78 + 34i
0044e33b  cmp esi, [0x47601c]           ; scroll + i == scroll ?
0044e34a  add eax, 0x30   → 图 3（选中）  /  0044e362 add eax, 0x24 → 图 2（常态）
```

- 落点 **(面板.x + 108, 面板.y + 78 + 34i)**；
- **`scroll + i == scroll`** 的那一条用图 **3**，其余用图 **2**；
- 分项名在 **(面板.x + 150, 面板.y + 94 + 34i)**（`flag 2` = 以该点为**中心**），
  字从**该章的分项表**取（见 A-045-2），`0x44e2b2` 的 `add eax, 0x96` / `+0x5e`。

### 三、行数

两个循环**都硬编码 8 行**（`inc ebx / cmp ebx, 8 / jge`，@0x44e2f7 / 0x44e2f8），

## D-045-2（字段读法已订正 · 章↔资源映射已修）剩下的唯一开放问题：滚动单位

> 本节原来的结论（「条目表第 4 个字段是 `maxScroll`，与解出的行数对不上，
> 需中央复核」）**已作废**：那是把条目表 5 个 dword 的后两个读反了。

### 一、字段读法（已订正）@source VA `0x4761b4`，20 字节/项 × 8 项

| 偏移 | 含义 | 0..7 的值 |
|---|---|---|
| +0x00 | 章名串指针（串表 `0x466052` 起，每串 9 字节） | 操作說明 / 遊戲畫面 / … |
| +0x04 | **该章的分项名指针数组**（见 A-045-2） | `0x476028 / 0x47602c / 0x476044 / …` |
| +0x08 | **起始资源号** | 1, 2, 8, 20, 23, 39, 57, 87 |
| +0x0C | **该章占几个资源** | 1, 6, 12, 3, 16, 18, 30, 13 |
| +0x10 | **当前滚动位置**（运行时会写它） | 全 0 |

权威 dump（自己复跑核对）：

```bash
python3 - <<'EOF'
import importlib.util, struct
spec=importlib.util.spec_from_file_location('d','tools/disasm.py'); m=importlib.util.module_from_spec(spec)
try: spec.loader.exec_module(m)
except SystemExit: pass
exe=open('../Rich4/rich4.exe','rb').read(); off=m.va_to_off(0x4761b4)
for i in range(8):
    t,f2,start,cnt,scroll = struct.unpack_from('<5I', exe, off+i*20)
    o=m.va_to_off(t); e=exe.index(b'\x00',o)
    print(i, exe[o:e].decode('cp950'), 'items',hex(f2), 'start',start, 'count',cnt, 'scroll',scroll)
EOF
```

1. **+0x0C 是「该章占几个资源」，不是 `maxScroll`。** 证据：8 组区间首尾相接
   （`1 → 2 → 8 → 20 → 23 → 39 → 57 → 87 → 100`），第 7 章收在资源 99
   （`87 + 13 − 1`），与 `help.mkf` 的资源区间严丝合缝；取正文那条
   `read_mkf(help, entry.res + scroll, 0, &size)` @0x44e179 正是按资源号走的。
   旧版把它当 `maxScroll`（读出 0 / 22 / 0 / 12 / 1 / 0 / 739 / 95），语意不通。
2. **+0x10 是「滚动位置」，不是「左列格高 `h`」。** 下滚 @0x44e944 与上滚
   @0x44e881 都直接 `add / sub` 这个 dword（exe 初值全 0）。旧版
   `HELP_CHAPTERS[i].h` 是把它误读出来的，绘制里也没用到，已删。
3. **+0x04 是分项名的指针数组**（不是「未解」）。见 A-045-2。

### 三、剩下的唯一开放问题：滚动单位是**资源**还是**行**

exe @0x44e944 的下滚夹取是 `max = [entry+0x0C] − 8`，而 `[entry+0x0C]` 是
**资源数**；滚动量 `[0x47601c]` 被**加到资源号上**再 `read_mkf` @0x44e179，
每次只读**一个**资源，再把该资源缓冲按 NUL 切行、画到下一个 `@` 或画满 14 行
（`cmp ebx, 0xd` @0x44e1be，@0x44e2b2 那条名字的循环也是 8 行）。
也就是说：原版的滚动单位像是**资源**，一屏画的是一个资源的正文（不是 14 行）。

本模块的 `scroll` 是**行**偏移（一屏 14 行、上/下滚步长 14 行），
`maxScroll = max(0, 行数 − 14)`。两者只有在「滚动单位 = 资源」时才等价。
需要中央定案的只有这一条：

- 若原版确实「一屏一资源、上/下滚各跳 8 个资源」，本模块要把 `scroll` 改成
  资源号（`read_mkf(help, res + scroll)`），夹取改成 `max(0, resCount − 8)`；
- 若下滚箭头是逐屏滚，则现口径（行 − 14）成立。

**判据缺口（登记）**：`fcn_0044dfb4` 只读资源 0，asm 里正文文本的取用
**只有 0x44e179 这一处 `read_mkf`**，没找到第二条取正文的路 —— 所以
「一屏 = 一个资源 / 每次跳 8 个资源」那句还差一张实机截图（卡片章按一下下滚，
看是跳 8 个资源还是跳一屏）才能闭环。在此之前**不猜着改**。

### 四、`tools/gen-help-lines.py` 的 `ROWS` 还是 8（未同步 · 登记）

生成脚本第 60 行 `ROWS = 8` 就是 `maxScroll = 行数 − 8` 那个口径，
本轮把口径改成 **14**（一屏 14 行）之后**脚本没改**（本卡只许动
`help-screen.ts` / `help-screen.test.ts` / 本文件）。后果：
`python3 tools/gen-help-lines.py` 现在会报不一致（它想写回 96/94/…
那一组旧值），**不要跑 `--write`**。

处置建议（给中央）：把脚本的 `ROWS` 改成从 `HELP_TEXT.rows` 读（或直接写 14），
再跑一次 `--write` 对齐。在那之前 `HELP_CHAPTERS` 的 `maxScroll` 以
`help-screen.ts` 里现在这一组（0/90/88/176/65/98/324/134）为准 ——
单测逐章按 `HELP_TEXT.rows` 现算，脚本不改也测得过。

## D-045-3（**已作废**）「上／下滚的画与命中错位」—— 原版本来就是对的

上一版写：

## A-045-2（**已订正**）分项名是**每章一张指针数组**，不是一张固定表

`entry + 0x04` 是**该章自己的**一张 dword 数组（`0x476028 / 0x47602c / 0x476044 /
0x476074 / 0x476080 / 0x4760c0 / 0x476108 / 0x476180`），画的时候按 `scroll + i` 索引：

```asm
0044e2d2  mov edx, [0x476018]        ; 章号
0044e2df  mov eax, [eax*4 + 0x4761b8]  ; ★ entry + 0x04 = 该章的分项指针数组
0044e2e6  mov edx, [eax + esi*4]     ; [scroll + i]
0044e2ee  call _rich4_draw_text
```

所以第 0 章是 `遊戲操作 / 日、月曆 / … / LOAD`，第 2 章是 `LOAD / SAVE / 卡片 / …`，
第 7 章是 `工程車 / 地雷 / …`。上一版把「第 0 章那张数组的第一个元素」当成了
全表表头（`HELP_INDEX_NAMES`），于是每一章都顶着「遊戲操作」。

八章的 8 项都 dump 进 `HELP_CHAPTER_ITEMS`（`python3 tools/disasm.py dump 0x476028 8 4` 起）。
越界（`scroll + i >= 8`）给空串、跳过那一行 —— 别猜到 `load_mkf` 缓冲区后面是什么。

★ 右列顶上那一行（`(140, 57)`）画的是**当前那一条**的名字（`chapterItem(chapter, scroll)`），
不是固定的「遊戲操作」；`HELP_INDEX_LABEL` 只当兜底。
章内那个小标题（`(270, 63)`）画的是 `itemAt(chapter, scroll)`。

| 组 | 干什么 | 命中项 |
|---|---|---|
| 0 | 左列八行选章（**整列** 22..91 × 38..361，另有一条逐行判据拿 `cell`）| 0 / 1 |
| 1 | 上一章 / 下一章 | 2 / 3 |
| 2 | 上滚 / 下滚（一屏）| 4 / 5 |

本模块按这个实现了 `hitHelp` / `applyHelpHit`，`helpScreen.hotkey(HOTKEY.help)`
开关屏（`HOTKEY.help = 24`，`hotkeys.ts` 的 `help`）。

★ **命中表第 0 / 1 项是整列**（`22,38,91,361` / `104,78,196,361`），上一版读成
`(77,38,104,78)` —— 那一组数在 exe 里不存在，症状是「左列只有第 1 格点得中、
右列 8 行格图完全点不动」。探针：`python3 tools/disasm.py dump 0x476254 24 4`。

## 有意近似（本轮）

1. **描边色分两族**：绿列那些字用 `#101010`（@source `create_font(0xf, 0x101010,
   0x101010, 3, 2)` @0x44e296）；珊瑚列那两行（8 行分项名 + 分项标题）的描边实测
   是**深红**（`assets-clean/help/0000_000.png` 取样 `0x842929`），本模块按这个色画。
   原版那一路的颜色参数没有逐个 dump（`create_font` 的入参在两个 draw_text 分支里），
   色值取自底图实测 —— 属**近似**，不是 exe 常量。
2. **字色一律白**：`create_font(…, 0xffffff, …)`，绿列/珊瑚列都实测白字。
3. **正文左上对齐**：原版 `flag 0`（`DrawTextA(DT_LEFT|DT_TOP)`），本模块用
   `helpTextLeft()`（`textAlign:'left'` + `textBaseline:'top'`）。上一版按「居中」画。
4. **canvas 没有 GDI 的 `DrawText` 排版**：长行不自动折行（原版正文每行都短，
   14 行 × 18 像素里不会撞到面板边），本模块照原版的行边界逐行画。
