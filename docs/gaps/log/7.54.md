#### (1b) ★ 同一轮发现：**「桶 4 = 0」是假阴性**，又查出 8 个被真正 `call` 的函数

收口过程中顺手验了一下长期报 0 的那个指标（`audit_spec_coverage.py` 的桶 4
「有调用者却真遗漏」），发现它用的是 `functions.json` 的 **`callers` 字段** ——
递归遍历的副产品，**已知不可靠**。实例：

```
$ grep -c "call    0x43a155" gen/db.txt   → 4 处（0x43a44b / 0x43a75e / 0x43b28d / 0x43b3fe）
$ functions.json 里 0x43a155 的 callers  → []          ← 假阴性
$ grep -rn "43a155" rich4-spec/docs/     → 无
```

新增 **`rich4-spec/tools/audit_call_targets.py`**（纯文本口径：扫 `db.txt` 里
所有 `call 0x…` / `jmp 0x…` 的目标 → 判断宿主函数是否出现在 `docs/**/*.md`；
排除 `≥0x450000` 的 CRT 区），并接进门禁 **3.55/5**（`--strict` 只对 **CALL 档**硬失败）。
它把目标分成两档：

| 档 | 现状 | 含义 |
|---|---|---|
| **CALL**（至少被一处 `call` 指向）| **8 个 / 1,630 字节 → 已补进 PRD，现为 0** | 真信号：货真价实的子程序 |
| JMP（只被 `jmp` 指向）| 76 个 / 7,773 字节（**待分类**）| 尾调用与遍历器**切分产物**混在一起 |

补记的 8 个写在 `rich4-spec/docs/coverage-by-function.md` **§五之五**，
逐个给了「调用点 + A 级事实 + 未决」；其中 3 个值得单独点名：

- `0x4019d2`（11 字节）= **模态消息泵深度 −1**（`dec [0x46cad8]` + `jmp`）—— `ui.md` 一直在用这个全局却没登记这个封装；
- `0x4024c0`（166 字节）= **UI 元素内的 32×32 局部命中矩形**（`GetCursorPos` → 用 `[0x48a172]` 索引元素记录表 `[0x48a0f4]` → 钳进 640×480）；
- `0x43a155`（392 字节）= **拍卖项几何**（记录步长 **120**、基址 `+0x50`），4 个调用点全在竞价循环附近。

#### (2) 新发现并**已修**：`+0x42`「本月倒楣天數」漏了三处累加点

写 `+0x42` 的时候为了给出「这个字节到底是什么」，把全 exe 的
`add byte ptr [… + 0x496baa]` 穷举了一遍 —— 共 **6 处**，而 remake 只实现了 **3 处**：

| # | VA | 场景 | remake 旧状 |
|---|---|---|---|
| 1 | `0x0040d431` | 「消失」施加函数 `0x0040d375`（命運 6/7、航空轉盤）| ❌ **漏** |
| 2 | `0x0041a83f` | 住宿（旅館過路費尾段）| ✅ `reduce.ts` 有 |
| 3 | `0x0043d755` | 送入監獄 `0x0043d593` **公共尾部**（新判+加刑都走）| ❌ **漏** |
| 4 | `0x0043ee04` | 送入醫院 `0x0043ec3f` 公共尾部 | ❌ **漏** |
| 5 | `0x004441a1` | 冬眠卡（`dh = 5`）| ✅ `hibernate.ts` |
| 6 | `0x00444372` | 夢遊卡（字面量 `5`）| ✅ `sleepwalk.ts` |

**后果是玩家可见的**：`+0x42` 有两个读点 —— 月结屏把它显示成
`本月倒楣天數：%d天`（`0x464e0d`/`0x464e1c`，`VA 0x004387a8` 起），
月度奖项评分按 `天数 × 物價指數 × 2500`（`VA 0x00437d55`）折算成金额。
少加 ⇒ **这两处都偏低**（少算 2500/天 × 物价指数）。

**修法**（`rich4-remake`）：

- 新增 `rules/monthly.ts` 的 `misfortuneDaysAfter(current, days)` / `addMisfortuneDays(player, days)`，
  把「**8 位加法、按 256 回绕**」这条口径**收成一份**（原版六处全是 `add byte ptr`）。
- `rules/confinement.ts` 的 `confine()`：监狱与医院**两条路径都加**（原版那一句在公共尾部，
  加刑也走得到）；注意 `0x40d761`（首次关押清 `+0x32..+0x35`）**不清** `+0x42`。
- `events/fortune-effects.ts` 的「消失」分支：加上天数值（原版只在**首次**分支加，
  而命运这一支本来就把"已在外"的人整个跳过 ⇒ 口径一致）。
- 三处旧有的累加点（住宿 / 冬眠 / 夢遊）改成调同一个 helper，消掉重复的 `& 0xff` 口径。
- 字段名 `totalWinterSleepDays` 是**误名**（沿自早期线索源）——本轮**不改名**（会牵动
  存档读写与多处测试），但在 `monthly.ts`、`save-format.md` §三之三、`ui-screens.md` 里
  写明真名与 6 处写点。

**测试**：`confinement.test.ts` +6（新判/加刑/他人不受影响/256 回绕/0 天）、
`monthly.test.ts` +2（helper 的回绕与"0 天同引用"）、`fortune-effects.test.ts` +2（首次累加、
翻倍后按翻倍值累加、神明档位 1 一天不算）。
