# 逆向源可靠性审计与验证纪律

> 最后更新：2026-09-13

## 结论先行

`rich4-re` 是**极有价值的线索来源**，没有它这个项目根本无从下手。
但它**不是真值**——已发现至少 **7 处实质性错误**，类型各异（工具缺陷、
链接配置错误、结构体漏字段、字段误标、代码转录错误）。

**唯一的真值是原版 `Rich4/rich4.exe` 本身。**

## 一、已发现的错误清单

| # | 位置 | 类型 | 后果 | 状态 |
|---|---|---|---|---|
| 1 | `tools/dump_all.c` | 64 位构建下结构体布局缺陷 | **13,034 张素材全部损坏**，旧 `png/` 漏掉 89%、620 张尺寸错误 | 已绕过，自行实现解包 |
| 2 | `asm/mscrt.ld` | 把 `_libc_rand` 重定向到 msvcrt | **随机序列与原版完全不同**，从该 exe 观测的随机行为一律不可信 | 已避开，以原始 exe 反汇编为准 |
| 3 | `csrc/land.h` | **漏字段** | 未记录偏移 `0x20` 的按等级租金表（6 项 uint16），而这是过路费公式的核心 | 已自行反推并以地图数据验证 |
| 4 | `asm/rich4_player_info.h` | **字段误标** | `hostility[6]` 实为 `hostility[4]` + 2 个独立月度金额字段 | 已以存档实证纠正 |
| 5 | `csrc/fortune.c` | **代码转录错误** | case 15 写 `*v = 15`，汇编实为 `*v = 14` | 已按汇编实现 |
| 6 | `asm/rich4_stocks.h` | **字段类型误标** | `player_stock_info { int amount; int _; }` —— 第二字段实为 **float 持仓成本均价**，汇编以 `fmul`/`fstp` 按浮点读写 | 已按汇编实现 |
| 7 | `csrc/cards.c`（2018 旧版） | **公式错误** | 均富卡的敌意增量写作 `average / 100`，原版实为 `(cash − average) / 100` | 已按 exe 反汇编实现 |

> 两处原先**疑似**误标的字段，现已澄清（均非错误）：
> - ~~`total_winter_sleep_days`（+0x42）~~ ✅ **命名无误**。冬眠卡（VA 0x004440ea）
>   让玩家冬眠 5 天的同时执行 `add byte [player+0x42], 5`，直接证明该字段
>   就是冬眠天数累计。月度评分把它折算为「倒楣天数」亦自洽。
> - ~~`god_info`（+0x3f）~~ ✅ **语义已澄清**：它存的是**物件下标**（1 基），
>   而非神明种类本身。送神符（VA 0x00444c45）的用法是
>   `objects_info[god_info - 1].type`，再与 {5,6,7,8,10,15} 比对——
>   真正的神明种类在物件表里。`+0x40`（f64）同理也是物件下标，
>   两者在破产时都被传给 `remove_object`，与此一致。

## 二、验证纪律

按可靠性排序，**永远优先使用排名靠前的证据**：

| 级别 | 证据来源 | 可靠性 | 说明 |
|---|---|---|---|
| **A** | `Rich4/rich4.exe` 二进制 | **真值** | 数值表、常量可直接提取比对 |
| **A** | 原版存档 `Save0.dat` / `SAVE1.DAT` | **真值** | 结构与数值的实证 |
| **A** | 原版资源文件 `*.mkf` | **真值** | 格式与素材的实证 |
| B | `rich4-re/asm/*.asm` 反汇编 | 高 | 由 exe 机械转换而来，但**标注**可能错 |
| C | `rich4-re/asm/rich4_*.c` 人工还原（**2026 新版，在维护**） | 中高 | 上游仍在持续把 asm 转 C，最近一次 2026-09-10 |
| C | `rich4-re/csrc/*.c` 人工还原（**2018 旧版**） | 中低 | ⚠️ **与新版存在矛盾**，卡片实现尤其不可靠 |
| C | `rich4-re/*.h` 结构体定义 | 中 | **已证实存在漏字段与误标** |
| D | `rich4-re/docs/*.txt` | 参考 | 多数正确，但属人工笔记 |

### 硬性要求

1. **凡取自 C 代码或头文件的逻辑，必须回到汇编交叉核对**，
   并在实现处写明 `@source` 指向**汇编行号**而非仅 C 文件。
2. **凡数值表，必须以 exe 二进制为基准做常驻测试**
   （见 `packages/data/src/binary-truth.test.ts`）。
3. 发现 C 与汇编冲突时，**一律以汇编为准**，并登记到
   `docs/known-deviations.md` 的 E 系列。
4. 能用原版存档/资源实证的，**优先实证**而非推理。

### 二进制表定位方法

三张数值表的地址是用**特征字节序列**唯一定位的，非猜测：

```python
# 卡片表首两项 {*,1,200,2,2} {*,2,200,2,2}
pat = bytes([0x01, 0xc8, 0x02, 0x02])
# 全文件唯一命中 → VA 0x47fdf2
```

自洽佐证：`0x47fdf2 + 30*8 = 0x47fee2` 恰为道具表地址，两表在内存中相邻。

### ★ 终极裁决手段：直接反汇编 exe

`tools/disasm.py` 可直接反汇编原版可执行文件，是本项目的最终真值来源：

```bash
python3 tools/disasm.py table card        # 打印卡片效果函数指针表
python3 tools/disasm.py card 1 80         # 反汇编第 1 张卡（均富卡）的实现
python3 tools/disasm.py va 0x00442f4d     # 反汇编任意虚拟地址
python3 tools/disasm.py find 01c80202     # 按字节模式搜索
```

已内置的函数指针表：

| 表 | VA | 项数 |
|---|---|---|
| `card_functions[]` | 0x475d5c | 31（第 0 项为 NULL 占位） |
| `events_calls_table[]`（新闻） | 0x475e24 | 36 |
| `fortune_call_table[]`（命运） | 0x475ef0 | 37 |
| `magic_house_functions[]` | 0x475724 | 12（每项 16 字节） |

**错误 #7 就是靠它裁决的**：两代 C 版对均富卡的敌意增量各执一词，
反汇编 `0x00442171` 处为

```asm
mov  edx, [eax + 0x496b84]   ; players[i].cash
cmp  esi, edx                 ; esi = average
jge  0x442190                 ; average >= cash → 跳过
sub  edx, esi                 ; ★ cash - average
mov  ecx, 0x64                ; 100
idiv ecx                      ; ★ (cash - average) / 100
```

结论：2026 新版正确，2018 旧版错误。

### PE 映射注意事项

`rich4.exe` 的节表 **VirtualSize 全为 0**（老 Watcom 链接器特征），
做 VA→文件偏移换算时**必须用 SizeOfRawData**，否则所有地址都会解析失败。

```
DGROUP: VA 0x463000, RawPtr 398848, RawSize 158720
```

### 已查明：被动卡的触发机制

复仇(18)/嫁祸(19)/免费(20)/免罪(21) 四张卡的 `card_functions` 项都指向
同一个 2 字节空桩 `xor eax,eax; ret`（VA 0x004420d5），**无法主动使用**。

真实机制是：**有害卡命中目标时，施害卡先查目标是否持有防御卡**。

@source 梦游卡 VA 0x004442f2：
```asm
push 0x15              ; 21 = 免罪卡
push ebx               ; 目标
call 0x4413ad          ; _rich4_player_has_card(player, cardId)
cmp  eax, 1 / jne 下一项
push ebx / call 0x444bb2   ; 免罪卡生效 → 免疫并中止
push 0x13              ; 19 = 嫁祸卡
call 0x4413ad
```

`_rich4_player_has_card`（VA 0x004413ad）扫描该玩家的 **15 个卡槽**
（`0x499120 + player*15 + i`，循环上界 `cmp ecx, 0xf`），
与存档中 `rich4_player_cards[60]` = 4 玩家 × 15 槽的布局一致。

**检查顺序有先后**：先免罪卡、后嫁祸卡，免罪命中即中止。
已实现于 `packages/core/src/cards/passive.ts`。
