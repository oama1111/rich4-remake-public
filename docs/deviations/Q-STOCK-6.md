## 〇、需求方报的现象与根因

> 「股市模块除了那几个蓝色的股票以外，其他股票点击查看【上市公司】资讯跳出的弹窗是错误的」
> （「蓝色的股票」= 股名是青色 / `listed` 的那几支）

原实现（`stock-detail.ts` 的 `stockDetailFrom`）**无条件**按「有上市公司」那套版式摊卡：

```ts
const comm = stock.commercialIndex;              // ★ 0 = 这支股票没有上市公司
const funds = state.companyFunds[comm] ?? 0;     // ← 企业表是 1 基的，读了第 0 格
const profit = state.companyProfit[comm] ?? 0;
const owner = state.commercialOwners[comm]?.owner ?? 0;
...
icon: commType === null ? 0 : iconImageOf(...)   // ← 图 0 = 资源 75 的 640×480 整屏页
```

于是未上市的股票会：① 打出企业表第 0 格的垃圾数字；② 在 (50,107) 贴一张
**640×480 的整屏页**（资源 75 的图 0 是行情页），把整张卡盖掉 —— 这就是看到的「弹窗错误」。

## 一、exe 读到什么（逐条 VA）

窗口过程 `fcn_00429d65`（VA 0x00429d65）：0x401 建窗、0xf 画、0x202/0x205 抬手退卡。
画的那一大段在 `loc_00429dae`（0x00429dae）里，**贴完底图、画完股票名之后立刻分叉**：

```asm
00429e9a  mov  edx, [eax + 0x496984]   ; = word [stock + 4] = 1 基企业序号
00429ea0  test dx, dx
00429ea3  je   0x429fc5                ; ★ 0 = 没有上市公司 → 直接跳到「只剩行情数字」那一段
```

### 1. 有上市公司（`stock+4 != 0`）才画的三处 + 一个图标

| 画什么 | 落点 | 取证 |
|---|---|---|
| 企业图标（表 `0x475530` 查出的图号）| (0x32,0x6b)=(50,107)，不透明贴图 | `loc_00429f05` = 0x00429f05，`call 0x4563f5` |
| `本月盈餘` = `currency(企業+0x28)` | (0x135,0x7b)=(309,123) flag 6 | `call 0x452793` @0x00429f36，`draw_text` @0x00429f4e |
| `平均盈餘` = `currency(企業+0x2c ÷ [0x499084])`（總天數为 0 时直接用 +0x2c）| (0x135,0xa2)=(309,162) flag 6 | @0x00429f56 起那支 |
| `經 營 者` = 業主名（`企業+0x18` = player_id+1，**为 0 就连这一格也不画**）| (0x10d,0xcb)=(269,203) **flag 2 居中** | `cmp byte [esi+0x18],0` @0x00429f99，`je 0x429fc5`；画画 @0x00429f9f–0x00429fbc |

### 2. 两支**都有**的那 8 个数字（`loc_00429fc5` = 0x00429fc5 起）

| # | 画什么 | 落点 | 格式 / 取证 |
|---|---|---|---|
| 1 | `成交價` = `[stock+0x14]` | (0x1c5,0x7b)=(453,123) | `sprintf(表 0x475518[dec])` |
| 2 | `漲  跌` = 现价 − `[stock+0x10]`(開盤) | (0x1c5,0xa2)=(453,162) | `sprintf(表 0x475524[dec])`（**与成交價同一枚 dec**）|
| 3 | `交易量` = `word [stock+0xa]` | (0x24d,0x7b)=(589,123) | `sprintf("%d")`，串 @0x464018 |
| 4 | `漲跌幅` = 涨跌 ÷ 開盤 × **100.0f** | (0x24d,0xa2)=(589,162) | `sprintf("%.2f")`，串 @0x463f64、乘数 @0x46401c |
| 5 | `週均價` = 从今天**往前**数 6 个非零项的平均 | (0x1c5,0xcb)=(453,203) | 循环 @0x0042a147（`cmp esi,6`）|
| 6 | `月均價` = 同样数 0x18=24 个 | (0x24d,0xcb)=(589,203) | 循环 @0x0042a1f8（`cmp esi,0x18`）|
| 7 | `歷史高價` = 144 格最大 | (0x24d,0xf3)=(589,243) | 循环 @0x0042a2b3（`cmp esi,0x90`）|
| 8 | `歷史低價` = 144 格最小 | (0x24d,0x11b)=(589,283) | 同上那圈的 `[esp+0xf4]` |

`dec = fcn_00429691(现价)`：价格 `< 15.0f`（@0x463ff0）→ 0 位小数的表项序号 0
（= `%.2f`）、`< 150.0f`（@0x463ff4）→ 1、否则 2。两张表逐项 dump：

```
0x475518: 0x463f64 "%.2f" | 0x463f69 "%.1f" | 0x463f6e "%.0f"
0x475524: 0x463f73 "%+.2f" | 0x463f79 "%+.1f" | 0x463f7f "%+.0f"
```

★ 第 7/8 格**无条件画**：初值 `高 = 0.0f`、`低 = 10000.0f`（@0x0042a290 / @0x0042a299），
扫完 144 格直接 `sprintf`，**没有「没历史就不画」这一说**，也没有把 10000 换成 0 的处理。

## 三、本轮**没解出 / 有意没动**的

### Q-STOCK-6-a　饼图 `0 < ratio < 1` 那一支少画了一层**底椭圆**

- **现象**：原版在这一支里先 `CreateSolidBrush(0xd00000)` + `Ellipse(414,343,591,401)`
  画一整块深红「厚度」（@source **0x0042a526**），再用深红 `Pie` 画自己那份、
  深蓝 `Pie` 画其余（`Pie@36` 两次，box 都是 (414,336)-(591,394)、起点 (502,336)）。
  本引擎 `drawPie` 的 `0 < ratio < 1` 只画了两段扇，**没有那块底椭圆**。
- **为什么没动**：那块底椭圆被后画的两段扇盖住，只在下缘露出约 7px（394→401）；
  要改就得同时决定「扇的覆盖关系」，**无法目视核对**（本轮不起 dev server 之外的东西，
  也不想凭想象改图）。`ratio == 0` / `ratio >= 1` 那两支的「两个椭圆」本引擎是对的。
- **处置**：**未做**，留给能目视核对的会话。

### Q-STOCK-6-b　饼图右侧那道 `FloodFill` 黑边没复刻

- **取证**：`fld [esp+0xe4]`(ratio) `fcomp 0.25`（@0x464054）`jbe` → 跳过；
  否则若饼的端点 x `< 0x24d`(589) 就 `FloodFill(dc, 589, 374, 0)`（**涂黑**，
  @source **0x0042a638–0x0042a64c**，`call dword cs:[0x4622a0]`）。
- **没解出**：GDI 的 `FloodFill` 从 (589,374) 起填的是哪一块边界内的连通区
  （取决于当前 DC 上的位图内容），**静态读不出来**。
- **处置**：**未做**，登记在此。

### Q-STOCK-6-c　图标贴图用的是**不透明**还是**抠黑**（结论：不影响，暂不改）

- **取证**：原版这一支与底图走的是**同一个** `fcn_004563f5`（@0x00429f05 与 @0x00429dae），
  而 0x004563f5 → 0x00455b3a = 连 0 一起拷的**不透明**贴图；抠黑的是另一个函数
  0x00456418（本仓库 `lottery-screen.ts` 的文件头已把这条映射写死）。
  但本引擎画图标用的是 `colorKeyBlack = true`。
- **实测影响**：把资源 75 的图 3 解出来数过 —— **纯黑只占 0.1%**（背景是浅蓝灰
  `(115,132,165)`），卡上那一格是暗红 `(33,0,0)` 一类。⇒ 抠不抠黑**看不出差别**。
- **处置**：**不动**（改了没有可观测收益，却会动到「有公司」那张卡）。

### Q-STOCK-6-d　均价一个非零项都没有时原版出的是 `NaN`

- 原版 `fild` 计数（0）后 `fdivr` 求和 → `0/0`，`sprintf("%.2f")` 在现代 CRT 上是
  `-1.#IND` / `nan`。本引擎 `recentAverage` 在 `n === 0` 时**收口成 0**（上一轮既有行为，测试已钉住）。
- **处置**：**有意保留**（原版那一格的串是什么，取决于当年的 msvcrt，未取证；
  而「历史一格都没写过」在真实对局里只可能出现在开局第一天）。

### Q-STOCK-6-e　12 行股票列表里 `保留股份 / 累積盈餘` 对未上市股票也读了第 0 格

- **现象**：`stock-screen.ts` 的 `stockRowsFrom` 与本次修掉的是**同一类**：
  `state.commercialShares[comm]` / `state.companyFunds[comm]` / `commercialOwners[comm]`
  在 `comm === 0` 时全部落在 1 基企业表的第 0 格上。
- **本轮没查**：需求方这次报的只是**详情卡**；那两列（图 1 那页的 `保留股份`/`累積盈餘`）
  原版**怎么处理未上市行**（跳过整行 / 画 0 / 也读 0 号格）**这一轮没有去 exe 取证**。
- **处置**：**登记**，下一轮按 `stock+4` 是否 0 取证后再改（别照详情卡的样子类推）。
