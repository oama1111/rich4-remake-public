### 7.59 ★ 第 78 条（本轮）：**物件收回 `0x40e14d` 的通道 2 差分**（31/31）+ 挑格器的一个可崩点

接着上一轮的路子，挑了工作单里体积最大的一支纯规则函数：
`_rich4_remove_object 0x0040e14d`（**341 字节 / 98 条**）。

#### (1) 新测试覆盖到的六类行为

| # | 行为 | 依据 |
|---|---|---|
| 1 | `handle == 0` 原样返回 | `0x40e153` |
| 2 | 路障/地雷/定時炸彈各自让 `0x497321/22/23` 的 byte `+1`（互不串）| `0x40e17f/0x40e18a/0x40e195` |
| 3 | 定時炸彈清**携带者**的 `+0x40`（`f64`）；路障/地雷没有这一步 | `0x40e1a1`..`0x40e1b2` |
| 4 | 神明（默认支）清 `+0x3f`（`god_info`）并按三张表把 `+0x44/+0x46/+0x48` **减回去** | `0x40e1ba`..`0x40e204`，表 `0x4749e2/0x474a06/0x474a2a` |

#### (2) ★ 顺带测出挑格器 `0x40aa6c` 的一个**可崩点**

「搭档登场」要挑一格，`0x40aa6c(原节点)` 的判据是
（`test dword [node+0x24],0x80ffff00 / jne 跳过` + 四个 `adjacent` u16 至少一个非 0），
再 `rand15() % 候选数`；参照点非 0 时还要 `|dx|`/`|dy|` **任一 ≥ 300** 才收，否则**重掷**。

★★ **候选数为 0 时原版直接 `idiv 0` 崩**（`0x40aae9` 的 `ebx` 就是候选计数）——
本轮测试**真撞到了**（把所有节点的物件字节设成非 0 即可复现）。
复刻 `pickObjectNodeDistant` 在 `candidates.length === 0` 时返回 0 ⇒ **有意偏离**，
已写进 `known-deviations.md` 的 Q-OBJ-2（原版此刻没有可观测的正确行为）。

★ 另外两条也已核对**复刻是对的**（无需改）：挑格器**用掉一个随机数**（`0x40aadf`
`call rand15`）且复刻把 `draw` 回调传了进来 ⇒ RNG 序与原版一致；
「`+0x18`/`+0x1c` 至少一个非 0」= 「四个 `adjacent` u16 里至少一个非 0」=
复刻的 `walkable`（`map-format.md` §节点记录 已登记这一对 `cmp`）。

#### (3) 机械闭环

通道 2 工作单 **165 个 / 70,327 字节 → 164 个 / 69,986 字节** ——
差额 **341 字节 = `0x40e14d` 的函数体大小** ✓。

#### (4) 测试台又添一条经验

本轮又踩到一个**工具坑**：`rand` 的状态块打桩地址与节点表同处 0x600000 起的
64 KB scratch 区，`SCRATCH_BASE+0x40` 恰好是 `node[1]+0x18` —— 于是 `rand` 的
状态推进把节点字段写坏，表现为「候选数恒为 0」。**scratch 区里给不同用途
分页**（本测试把 rand 状态挪到 `+0x8000`）已写进测试注释。
