### 2.1 取证口径（为什么这个「指纹相等」可信）

- **独立比对用全量状态摘要**：`tools/net-e2e.js` 的 `checkpoint()` = `JSON.stringify(state)` 的
  FNV-1a 32 位散列（**比传输指纹更严**，全量字段都进），并且是**把两端都停手 2 秒后再比** ——
  这样比的是同一个逻辑点，不会把「一端领先一条 action」的瞬时差当成不一致。
- **传输路上另有权威信号**：服务器每 10 条 action 收一次 `checksum`（`hub.ts` 的 `checksumEvery`），
  不一致就广播 `desync`。本次五个步骤全程**只有第 4 步那次故意造的失步**，其余一次都没有。
- 第 2 步之外的每一步都是**真实状态迁移**：回合由两端各自按 `dispatch → net.submit → 服务器定序 → 广播`
  推下去（`tools/net-e2e.js` 里没有旁路 reduce）。

## 3. 工具做了哪些事（`tools/net-e2e.js`）

1. 大厅阶段每 500 ms 点一次「開始」（非房主点不到，命中判定自己会拒）；
2. 轮到自己座位时按 `turnStart → awaitingRoll → moving → settling → turnEnd` 自动推进
   （与 `tools/soak-browser.js` 的 legacy 阶梯同一套判据，只是 action 走 `dispatch` ⇒ 联机下由服务器定序）；
3. 记录座位号、每回合的全量摘要、菜单里的失步/自愈日志行；
4. 提供 `stop()` / `resume()`（冻结两端比对）、`tamper()`（人为改坏状态以验证自愈）、
   `checkpoint()` / `summary()`。

★ 与 soak 同一条坑：页面动作一律 `browse eval <file>`，不要用 `browse js "$(cat …)"`。

## 4. ⚠️ 发现一个真死锁：4 座（2 真人 + 2 电脑）时拍賣卡死 → issue [#9](https://github.com/oama1111/rich4-remake/issues/9)

`SEATS=4`（两个真人客户端 + 两个电脑座）那一轮，打到**第 7 回合**硬卡死（90 秒不动）：

```
seed = 968029213   map 0   --seats 4 --takeover 8000
phase = 'awaitingDecision'
currentPlayer = 3                      ← 电脑座
pending = { kind: 'auction', seat: 0 }  ← 下一个该举牌的是真人座 0
```

两端摘要**仍然相等** —— 不是失步，是**没人能出牌**。读码定位到两条互锁的判据：

1. 定序器只收「当前座位」的意图：`sequencer.ts` 的 `submit()` 判 `seat !== currentSeat()`
   就 `notYourTurn`，而 `currentSeat = mirror.currentPlayer`（`room.ts:94,103`）
   ⇒ **真人座 0 提交 `auctionBid` 会被服务器拒**；
2. 服务器替电脑代打时，`decideAction()` 在 `kind === 'auction'` 且轮到**真人**举牌时
   **有意返回 `null`**（`ai/policy.ts`，那条路留给表现层）⇒ 电脑座那一端也没有页面能驱动。

单机与 4 真人局都不受影响；**只有「回合主人是电脑/掉线托管座 + 下一个举牌者是真人」这一种组合**会死锁。
修法涉及联机契约语义（放宽定序器 or 换驱动判据），**不在 W-40 里自行改**：已开 issue #9，并在
[`docs/escalations.md`](../escalations.md) 记 **E-2** 等首席/需求方拍板。

### 4.1 ✅ 已修（首席，issue #9 / E-2）—— 契约定为「**谁举牌谁提交**」

- 判据收敛成 core 的一个函数 `actingSeat(state)`（`packages/core/src/net/acting-seat.ts`）：
  竞价期间 = `pending.bidders[pending.seat]`，其余 = `currentPlayer`。
- 服务器：定序器的「轮到谁」改问它（`room.ts`）；代打循环也按它走，轮到 AI 控制的那位
  （电脑 / 掉线代打 / 自己开了託管）由服务器出那一口 —— **哪怕回合主人是真人**（`hub.ts`，
  问的是与屏、与 `decidePending` 同一个 `auctionNextBid`）。
- 客户端：联机时拍賣屏只让**本机座位**点钮，电脑那一口不再由客户端发（`auction-screen.ts`、`main.ts`）。
  ⇒ 顺带堵掉原先一个没卡死但不对的口子：回合主人那一端能替**别的真人**出价。
- 回归（`packages/server/src/auction-acting-seat.test.ts`，2 真人**不开託管** + 2 电脑，各 200 回合）：
  两个方向的现场各钉一个种子，并断言「现场数 > 0」；旁人代出价必须被拒（`notYourTurn`）且不被定序。
  **可证伪已验**：撤掉定序器那一半 ⇒ `座位 0 的 auctionBid 被拒：notYourTurn`；
  撤掉代打那一半 ⇒ `卡死：seed 5 第 33 回合 … currentPlayer=1 actingSeat=2`。

**4 座浏览器实测（同一个种子 968029213，`SEATS=4 SEED=968029213 bash tools/net-e2e.sh`）：**

```

PASS 2) 同一回合 56：digest b2766671 vs b2766671
PASS 3) 重连后同一回合 120：digest 7a6e3960 vs 7a6e3960
PASS 4) 自愈后同一回合 217：digest 773b0f0f vs 773b0f0f

A 端驱动计数：auctionBid 提交 7 口，其中 3 口是「回合主人不是自己」时举的；errors = []
```

⇒ **「4 座 50 回合指纹全等」现已验收**（原先卡死的第 7 回合那场拍卖正常收场）。
  为了能复现，服务器 CLI 加了 `--seed N`，`net-e2e.sh` 认 `SEED=`；驱动脚本的真人在竞价里一律 PASS
  （⚠️ 不能回 `declineDecision` —— 那会把整场拍卖清掉）。
