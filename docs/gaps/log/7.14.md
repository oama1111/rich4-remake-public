### 7.14 ★ 第 32 条（本轮）：为「扣卡时机」造好**机制 + 哨兵**（未翻任何调用点）

按第 31 条查清的规则，给 `registry.ts` 的 `fail` 加了第二个参数：

```ts
const fail = (error: UseCardError, consumes = false): UseCardResult => { … }
```

`consumes: true` ⇒ 即使失败也把卡从施卡者手上扣掉（对应原版"目标已选定后任何 early-exit 都扣卡"）。

**本轮只造机制、一个调用点都没翻**（`fail(...)` 的 23 处全用默认 `false`），
因此**行为与从前完全一致** —— 证据是 4,914 个既有测试全绿，无需任何断言调整。

> ★ **为什么不直接翻**：翻 `true` 之前必须**逐张卡回 exe 读出"目标选定"发生在哪一行**
> （23 处 `noEffect`，每处的"目标是否已锁定"都不同）。在没有逐张证据的情况下批量翻标志，
> 就是"猜"，而本项目整轮的纪律正是**不猜**。造好机制后，那件工作就从"设计问题"
> 降级为"照规则逐张核对"，风险低得多。

另外加了一条**哨兵测试**（`registry.test.ts`）：把当前的一处已知偏离
（替身已冬眠时夢遊卡**不**被扣）**显式断言下来**，并在测试名里写明"原版会扣 —— 待第 31 条修复"。
它的用途是：**等哪一轮真去翻标志时，这条会红**，提醒同步更新，
而不是让偏离悄悄被"修好"或被遗忘。
