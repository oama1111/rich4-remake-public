#### (1) ★★ 逮到并修掉一个**玩家可见**的表错位

`@rich4/data` 的 `MAGIC_HOUSE_OPTIONS`（魔法屋 12 个功能的图号/摆位/名字）
一直按「基址 `0x475724`、字段序 `{name, frames, x, y}`」提取。本轮把两条读取点读全：

```asm
00431d00  mov eax, esi / shl eax,4          ; ① 0 基：效果处理常式读「动作名称」
00431d05  mov ebx, [eax + 0x475724]         ;    = 记录 i 的 +12
00432db3  shl eax, 4                        ; ② 1 基：指针高亮那一支
00432dc4  mov edx, [eax + 0x475708]         ;    = 记录 (k-1) 的 +0（图号）
00432db6  mov edi, [eax + 0x475710]         ;    y（同一条记录）
00432dbd  mov ebp, [eax + 0x47570c]         ;    x（同一条记录）
```
`0x475708 + 16k == 0x475718 + 16(k-1)` ⇒ 两支读的是**同一条 16 字节记录**，
真正的字段序是 **`{+0 img, +4 x, +8 y, +12 name}`、基址 `0x475718`**。

⇒ 旧提取法**名字恰好对、图号与 x/y 全是「下一个功能」的值**：
十二个图标、十二个高亮框、十二个名字整体被**旋转了一位**（玩家可见）。
修法：

- `packages/data/src/magic-house.ts` 整表订正（`frames` → **`img`**，值 = 9/10/7/6…，
  x/y 全部回退一格）；第 11 项在正确字段序下完全合规（img=9, x=122, y=154），
  「那 16 字节不符合字段模式」的旧结论**作废**（它只是转不到而已）；
- `binary-truth.test.ts` 的 VA 改成 `0x475718`、**12 项逐字段**校验，
  并加一条「1 基读取落在同一条记录」的交叉印证（旧测试用同一个错基址，所以一直绿）；
