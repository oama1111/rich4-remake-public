### 7.44 ★ 第 63 条（本轮）：**银行结算**补差分（22/22），顺带订正了 PRD 里漏掉的两道 guard

工作单第 2 名 `0x00436b0a`（560 字节，`bank.md` §3.4 早有逐句注解）。

#### (1) 差分：`tests/test_bank_settle.py` **22/22**

| 验到的点 | 结论 |
|---|---|
| 银行识别 | 在**設施表** `0x498e7c` 里找 `+0x1a == 7 && +0x18 != 0`；**最后一条赢**；`+0x18 == 0`（无主）**不重置** `edi` |

| ★★ `arg = 0` | **跳过银行经营者本人**，再跳过出局者；其余欠款者各按**自己的** `+0x28` 全额还清并清零 |

#### (2) ★ PRD 被实测订正（remake 反而一直是对的）

`bank.md` §3.4 的 `arg = 0` 伪码只写了 `if (+0x28 == 0) continue`，
**漏了 `cmp ebx,edi / je`（跳过经营者）与 `whoPlays == 0`（跳过出局者）**，
而且标题写作「经营者的特别融资必须还清」—— 实测是「**除经营者以外**的人还」。
漏掉第一道 guard 会让语义整个反过来（把经营者的准备金义务当成他的欠款收掉）。

复刻侧 `reduce.ts` 的 `sweepSpecialFinance` / `bankReserveCall` 一直带着这两道 guard
（注释里也写了「除銀行董事長以外…没有董事長时人人都收」）—— 又是一例
**remake 知道、PRD 没写**，已在 §7.3 9.5 的口径下补回规格。

#### (3) 测试台：第三类「纯仿真跑不了」的 CRT 写法

`0x452946`（取玩家名）内部调 `0x45825d` = **`strlen`**，用 `mov es, ds` + `repne scasb`
—— 与之前踩到的 `memcpy`（`movsd es:[edi]`）**同一类**段寄存器写法，Unicorn 直接
`UC_ERR_READ_UNMAPPED`。本用例把整条表现层链打桩（窗口 / 取名 / sprintf / 弹窗），
并逐个给出 `writes` 依据证明它们不含规则状态。

> 累计已记录 **三类** 纯仿真限制：① CRT `memcpy` 系（`mov es,ds`）；
> ② 表现层图形/窗口状态（`0x415fa6`、`0x417e26`）；③ **MKF 资源装载**
> （破产 `0x40cd87`、胜负 `0x41d9b9` 支，`0x450471`）。

#### 诚实边界

- 缺口大到把经营者打空时，破产处理走 MKF 资源而中途异常 ⇒ 只断言到
  「两边归零 + `whoPlays` 清 0」；`+0x28 -= 缺口` 那一句在纯仿真里到不了。
- `+0x28` 在经营者身上是「准备金义务」（`arg=1` 读）、在别人身上是「自己的特别融资」
  （`arg=0` 收）—— **一字段两用是实测**，「为什么」仍未解。
- 两个调用点（`0x43784f` ATM 取款确认、`0x437c14` AI 比例重分）本轮**没有**跑整条
  调用链，只单调了 `0x436b0a` 本身。
