#### (2) 钉住的四条公共事实（12 支共用骨架）

| # | 事实 | 意义 |
|---|---|---|
| 1 | 结果数组 `0x48c380` 的每一项 = **玩家下标 + 1**（1 基） | 与乐透号码槽、`[0x48c377]` 得主同一套编码 |
| 2 | ★★ 一律先过 `player + 0x15 != 0`（**在场**）这道闸 | 出局/未参战的玩家不会被选中 |
| 3 | ★ 返回 1 当且仅当结果数组非空（`0x431c62 setne al` + `and eax,0xff`） | 「一个候选人都没有」时可据此走另一条路 |
| 4 | ★ 入口只写 `[0x48c380]` 的**一个 dword**（结果数组按 C 串用，逐次覆盖 + 补 0） | 不是「整体 memset 36/4 字节」 |

★ 类型 10/11 的谓词**只差 `player + 0x14` 的正反**：
男 = `+0x15 != 0 && +0x14 != 0`，女 = `+0x15 != 0 && +0x14 == 0`
—— 与 `state/types.ts` 对 `isMale` 的说明（`+0x14 != 0` 是男）**互为印证**。

#### (3) ★ 工具坑：这一段**必须用 `call()`**，不能用 `eval_block()`

实测（同一份注入、同一个人数）：
`call(0x431842, [10, 0])` → `eax = 1`（正确，数组 `[1,3,0,0]`）；
`eval_block(0x431842, 0x431c62)` → `eax = 0x138`（= 循环里 `imul eax,ebx,0x68`
留下的残值，`setne al` 之后的结果**丢了**）。
另有一个更迷惑的连带现象：**去掉自定义 hook 时**它连「停在 0x431c62」都做不到。
⇒ 不再用 `eval_block` 打这个函数，并把它记为**工具已知限制**（不影响被测代码的结论）。
凡遇到「`eval_block` 返回的寄存器与 `call()` 不一致」，**以 `call()` 为准**。
