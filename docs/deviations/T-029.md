## D-BANK-1（**订正 Q-BANK-1 的原文**）面板是 200×280，不是 280×200

`Q-BANK-1` 原文写「280×200（`fcn_00433d6e`）」「200×200（`fcn_00433f24`）」。
回 exe 核后：

```asm
004366d0  push 0        ; y0
004366d1  push 0        ; x0
004366d2  push 0x118    ; ★ 280
004366d3  push 0xc8     ; ★ 200
004366d6  call 0x451a5a ; allocate_graph_st(宽=200, 高=280, 0, 0) → [0x48c3b8]
004366e4  push 0xc8 / push 0xc8 / call 0x451a5a   ; 日期面板 200×200 → [0x48c3b4]
```

`fcn_00451a5a` 的 arg1 写 `+0`（宽）、arg2 写 `+2`（高）（`00451a75` / `00451a7c`），
而 `Panel.mkf` 资源 23 的**图 15 恰好是 200×280**（资源 2 的图 0..3 是 200×200）。
所以贴法是 **宽 200 的玩家面板 @`(0,y)` + 宽 200 的日期面板 @`(280,y)`**。

★ 静态 y 是 `0x1b8 = 440`（`[0x48c3d5]` 的到位值），**不是 0** ——
200×280 的面板顶边停在 440，也就是只从屏幕下缘露出 40 行。原版就是这么写的
（`loc_004355f7` 的 `cmp [0x48c3d5], 0x1b8`），照抄不做「看起来更合理」的调整。

## D-BANK-2（**订正 Q-BANK-1 的原文**）`loc_00437904` 不是「悬停反馈」

`Q-BANK-1` 把 ATM 的 `loc_00437904` 记成悬停反馈。那一支（`0x200 WM_MOUSEMOVE`）
**只做一件事**：

```asm
00437904  cmp byte [0x48c40b], 4      ; 只有「正按着金额栏」才理
0043790b  jne 0x4370d8                ; 否则直接回去（什么都不做）
0043790d  push ecx (lParam) / push 0 / push 0x201 / push hwnd
0043791e  call PostMessageA           ; ★ 把这次移动原样转成一次 WM_LBUTTONDOWN
```

也就是说它是**按住金额栏拖动＝连续点它**（拖进度条），原版 ATM **没有任何悬停高亮**。
本引擎照此实现（`atmDragToClick` + `atmSeekTo`）。

## D-BANK-3（**cross lines 解开**）`fcn_00433c20` 里那次 `fcn_0045643d` = 擦掉三条数额

`Q-BANK-1` 原文：「`fcn_00433c20` 里那次 `fcn_0045643d` 的 8 个参数只解出
『一块 113×117 被贴到 (135,278)』，语义未明」。

回 exe 逐条读（`fcn_0045643d` 的形参序 = `draw_img_rect(surface, 图, x, y, sx, sy, w, h)`，
见 `0x0045643d` 与 `0x00455e24` 的用法）：

```asm
00433c46  [esp]   = 0x16   ; 22
00433c4d  [esp+4] = 0xa1   ; 161
00433c55  [esp+8] = 0x87   ; 135
00433c5d  [esp+0xc] = 0x116; 278      → rect = (22,161)-(135,278) = 113×117
00433c7b  push 0x75 (h=117) / push 0x71 (w=113)
00433c7f  push 161 (sy) / push 22 (sx) / push 161 (y) / push 22 (x)
00433c8b  mov eax,[0x48c3c0]; add eax,0x24    ; ★ 资源 23 图 2（董事長室 640×480）
00433c9b  call 0x45643d
```

即 **`fcn_0045643d(图2, x=22, y=161, sx=22, sy=161, w=113, h=117)`** ——
**源与目标同一块**，从干净的董事長室底图上把这一块**原样拷回来**，
紧接着才画三条数额（`0x80/0xa3`、`0x80/0xd3`、`0x80/0x103`，右对齐）。

所以它不是「cross lines」也不是什么遮罩，而是标准的**「先擦掉上一次的三条数字，
再画新的」**。同一手法在 `fcn_00436d3a`（擦金额行 202×32）与樂透屏（擦眼睛/嘴）都用过。

★ 目标 surface 是**锁住的离屏面像素指针**（`0x48a068 + 0x24` = `DDSURFACEDESC.lpSurface`，
`Lock` = vtable `+0x64`、`Unlock` = `+0x80`）—— 原版不能从一张图 `Blt`，
只能这么软件拷。本引擎每帧整屏重画，因此**这一步不需要实现**。

## D-BANK-4（**已实现**）貸款屏进屏的两块滑入面板 + 状态机

| 是什么 | 实现 | @source |
|---|---|---|
| 玩家面板 200×280 | `drawLoanPanels()`：图 15 + `map.mkf` 头像 + 名字 + 現金/存款/貸款 | `fcn_00433d6e` |
| 日期面板 200×200 | 季节底图（表 `0x475218`）或**節日插画**；日 60 号 / 星期 / 年 / 月 / 距還款日 | `fcn_00433f24` |
| 滑入 `y`：640→440（每拍 −40）、收尾 440→640（+40） | `loanSlideIn/Out/Step/Done` | `loc_00435d48` / `loc_004357a7` / `004355f7` |
| 定时器 50ms | `LOAN_TICK_MS` | `SetTimer(hwnd, nIDEvent=[0x46cad8], uElapse=0x32, 0)` |
| 状态机 `[0x48c3dd]` | `LOAN_ST` + `loanStep()` | `fcn_00435062` 的跳表 |
| 气泡（10 句，串号 #0075..#0085） | `LOAN_MSG` / `drawLoanBubble()`（图 21 @(240,80)，字心 +20）| `0x48c3xx` 串表 / `fcn_00434186` 尾 |
| EXIT 按下图（图 19 / 复原图 18） | `LOAN_EXIT_IMAGE` + `drawLoanPressed()` | `loc_00435cca` / `loc_00435ea2` |

状态机（`loanStep` 的转换，逐条对 `fcn_00435062` 的 `0x113` 跳表）：

```
进屏  → st=1 说「歡迎光臨」(#0075)   （cfg[1] != 0；本引擎恒开）
       否则 st=3
1     → 3 + #0076「需要我為您服務嗎」
3     → 4（★ 只有 4 受理点钮；st<4 时点一下＝收掉气泡回 3）
4 + 申請貸款 → 5 滑入 + #0078（`loan >= 總資產` 时换 #0081）
4 + 償還貸款 → 9 滑入 + #0082（`loan == 0` 不理）
4 + 窗（只董事長）→ 0xa + 开特別融資子对话框
5     → 6 + PostMessage(0x409) → 通用填数页（額度 = 總資產 − 已借）
6 + 额>0 → 7 + #0079 ；额=0 → 8（不挂气泡）
7     → 8 + #0080（請於三個月內還清貸款）
9     → 0xa + PostMessage(0x40a) → 通用填数页（額度 = 已借）
0xa + 额>现金+存款 → 9 + #0083 ；否则 8 + #0084
8     → 4 + 滑回去
pressed 是 EXIT 且抬手（或右键）→ 0xb + #0085
0xb   → 关屏（Post_0402_Message）
```

★ **`fcn_0044ee18`（气泡那支）在没有气泡时也返回 1**（`0044ee1c je 0x44ef2a` →
`mov eax,1`）—— 所以「st=8 且没气泡」那一拍照样会走 `case 8`（滑回去），
不会像先前担心的那样卡住。本引擎的 `bankTick` 按同一口径发 `bubbleEnd`。

## 未决（本轮**没有**做，登记在此）

### Q-BANK-1a：特別融資子对话框（`fcn_00434492`）整屏没复刻

它是**另一个窗口过程**（`Wait_0402_Message(fcn_00434492)`，自 `loc_00435ddb`），
自己挂 50ms 定时器、自己的状态 `[0x48c3cc]`、自己的气泡与跳表：

```asm
0043453a  SetTimer(hwnd, 0x64, callbackSize, 0)   ; ★ 子对话框用 0x64
00434593  循环累加 [0x48c3c8] = Σ 其它玩家的存款（player+0x20）
004345ac  fcn_004563f5(屏, 资源23 图 2, 0, 0)      ; 董事長室整张
004345f7  fcn_00433c20([0x48c3c8])                ; 三条数额（含 D-BANK-3 那次擦除）
0043460?  fcn_0044ec30(资源23 图 21, 0xd6, 0x32, −10, 0, 0x101010, 0)
```

已解出的几何：两处 `InvalidateRect` 的矩形
`(0x1f0,0xa2)-(0x236,0xde)` = `(496,162)-(566,222)` 与
`(0x1f0,0xa2)-(0x236,0xc5)` = `(496,162)-(566,197)`；
按钮跳表 `ref_00434476`（7 项，`0x435052` 那张是主屏贷款屏的，别混）；
`0x409` = `額度−已用` 走 `fcn_00453544`、`0x40a` = 还款；返回标志 `[0x48c3d0]`。

**没解出**的：那两颗钮（週轉現金 / 歸還款項那对）各自的**命中矩形**与按下图、
`週轉現金` 那句提示的串指针、以及 `[0x48c3ce]` 那套店主表情位（图号表 `0x475880` 起）
的完整语义。**本引擎暂时把「窗」那颗钮退化到通用填数页**
（`main.ts` 的 `loanEffect` 里 `openFinance` → `openLoanAmount('financeBorrow')`），
金额流程能走通，但看不到董事長室那张屏。

### Q-BANK-1b：`_rich4_ui_bank_atm_entry` 里另外两条分流没做

`0x4379c9` 的入口有三岔（本引擎只做了中间那条）：

1. `player+0x3b != 0`（**銀行拒絕往來**）→ 弹「銀行拒絕往來\n\n還剩%d天！」（串 `0x464bed`）
   然后直接退屏。★ 这条是**规则**（`core` 的 `daysRejectedByBank` 已经在落点时挡掉了，
   `interaction.ts` 的 bank 分支直接返回 null），所以表现层也见不到 —— 与现状一致。
2. `player+0x15 != 1` → **不是真人**那一条：不画 ATM，改为**按比例把現金/存款重新分配**
   （`pct = player+0x19 / 100.0`，`cfg[1]` 影响 ×1.5 / ×0.5，夹在 `[0.1, 0.9]`，
   两头比值差在 ±0.25 以内且现金非 0 就跳过；最后 `player+0x1c = trunc(总额×pct)`、
   `player+0x20 = 余额`，@source 0x00437acd..0x00437c16）。**这是规则，不在本卡范围**。
3. 真人（`player+0x15 == 1`）→ ATM 面板（已复刻）。

### Q-BANK-1c：`fcn_00434186` 的董事長那一支往**图 2** 上画、却 blit **图 0**

### Q-BANK-1d：三条数额那 113×117 的擦除块没实现（有意）

见 D-BANK-3：本引擎每帧重画，`fcn_00433c20` 那一步（擦掉上一次的三条数字）
**不需要**、也不该照搬。`bank-loan.ts` 的 `LOAN_FINANCE_ROWS` 每帧重画即可。

### Q-BANK-1e：`fcn_00433f24` 的節日分支只做了「有/没有」两态

`fcn_004521f0(今天) != −1` 时原版会 `read_mkf(Data.mkf, HOLIDAY_ART_BASE[地图] + 節日序号)`
直接读进日期面板的像素区（`Data.mkf` 那批资源**没有 SPR/SMP 头**，是裸 200×200 RGB555）。
本引擎复用 `main.ts` 里**侧栏日曆**那份 `holidayArt`（`loadHolidayArt`）——
它按今天的節日序号解一张 200×200 的位图，语义相同。
★ 差别：侧栏那份只服务**今天**，而日期面板要的也是**今天**，所以一致；
若哪天要显示别的日期，这条得改成按日期取。
