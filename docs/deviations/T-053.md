# T-053　搶奪卡（13）的「从对方手里挑一件」窗

> 立项理由：`docs/known-deviations.md` 的 Q-CARD-2 一带一直记着
> 「**真人**用搶奪卡走不通 —— 本引擎没有『从对方手牌里挑一张』的界面」。
> core 那一半（`cards/rob.ts` 的卡片路径与道具路径、`robbableCards` / `robbableTools`）
> 早就完整，缺的只是表现层这一窗。本文件是它的取证与落点。

## 一、出处（`rich4_ui_use_card.asm`，全量反汇编）

效果函数 **`fcn_0044192a`**（VA `0x0044192a`，文件 `:533`）。签名三个实参：

| # | 含义 | 谁传的 |
|---|---|---|
| 1 | **对方**席位（被抢的人）| `_rich4_use_card_qiangduoka`（`rich4_card_qiangduoka.asm:86`）`push esi` |
| 2 | **收件人**席位（得手的人）| 同上 `push [0x49910c]`（当前行动者）|
| 3 | **模式** | 同上 `push 1`；命運 5「生日收卡」那一支 `push 0`（`rich4_fortune.asm:649`）|

真人那一支（`cmp byte [eax + (_rich4_all_players_state + 21)], 1 / jne` = `whoPlays == 1`）：

```asm
read_mkf(panel_mkf, 0xb, 0, 0)              ; 底图 = 资源 11（与自己道具/卡片欄同一张）
fcn_00447c6e(0, sheet, 对方)                ; 画对方的**道具**欄
fcn_00441b0a(0, sheet, 对方)                ; 画对方的**卡片**欄
fcn_004563f5(dst, [sheet+0xc], 0xe, 0x46)   ; 图 0（卡片框）→ (14,70)
if (模式 == 1) fcn_004563f5(dst, [sheet+0x18], 0xe, 0x10e)  ; 图 1（道具框）→ (14,270)
fcn_00451e7e(RECT(0,0x28,0x1b8,0x1e0))      ; ★ 存下中间那块（浮窗）
Wait_0402_Message(fcn_004413ec, (模式 << 16) | 对方)
```

★ 精灵表是 12 字节一项、表头 12 字节，所以 `[sheet+0xc]` = **第 0 项**、`[sheet+0x18]` = **第 1 项**
（与 `assets-pipeline/src/mkf.ts` 的 `parseSpriteSheet` 一致）⇒ 图 0 卡片框、图 1 道具框。

窗口过程 **`fcn_004413ec`**（VA `0x004413ec`，同文件 `:87`）：

| 消息 | 代码 | 语义 |
|---|---|---|
| `0x401` | `[0x48c53c] = lParam & 3`、`[0x48c540] = lParam >> 16` | 对方席位（**只留低 2 位**）、模式；并清 `[0x48c538] = 0` |
| `0x201` | 见下表 | 记选中：`[0x48c538] = 选中值`（0 = 没选中）|
| `0x202` | `cmp [0x48c538], 0 / je 什么都不做` → `Post_0402_Message([0x48c538])` | **抬手才抛出去**（按下之后拖到窗外松手也算）|
| `0x205` | `push 0; call Post_0402_Message` | **右键 = 取消**（返回 0）|

### 命中带（`0x201` 分支）

| 欄 | x | y | 备注 |
|---|---|---|---|
| 卡片 | `0x13 ≤ x < 0x1a3` | `0x4b ≤ y < 0xf3` | 每格 `0x50 × 0x38`、5 列 3 行 |
| 道具 | 同上 | `0x113 ≤ y < 0x1bb` | ★ **只有 `[0x48c540] != 0`（模式 1 = 搶奪卡）才认** |

`slot = floor((y - 带下界) / 0x38) * 5 + floor((x - 0x13) / 0x50)`；
卡片取 `player_cards[对方 * 15 + slot]`（**0 = 空格，当场什么都不做**），
道具取 `[0x48c548 + slot]`（由道具欄绘制**紧排**填成，值 = 道具号）。

命中值与两条带的边界都能与本项目的几何对上：
`0x4b + 3*0x38 = 0xf3`、`0x113 + 3*0x38 = 0x1bb`、`0x13 + 5*0x50 = 0x1a3`。

### 按下时的选中框

`0x201` 分支在把选择交给 `fcn_00451b9e`（VA `0x00451b9e`，`rich4_graph_struct.asm:156`）
之前算了一个矩形（卡片带 VA `0x00441499` 起）：

```
x0 = col*0x50 + 0x14      x1 = col*0x50 + 0x62
y0 = row*0x38 + 0x4c      y1 = row*0x38 + 0x82
```

即**格内缩 1px 的框**（卡片带格原点 `(0x13,0x4b)`；道具带把 y 换成 `+0x114 / +0x14a`）。
本引擎按这个矩形画 1px 框（`STEAL_SELECT_INSET = 1`）。

### 拿到选择之后（`fcn_0044192a` 尾巴 VA `0x00441ab9` 起）

```
if (bh & 0x80) → after_player_use_tool(对方, id)(0x445aa2) + receive_tool(收件人, id)(0x445a4d)
else           → consume_card(对方, id)(0x441343)        + receive_card(收件人, id)(0x4412e4)
```

⇒ **这一窗只回答「挑哪一件」**；转移与敌意增量都在 core（C-ARC-2）。
调用方 `_rich4_use_card_qiangduoka` 拿到返回值后：
`test eax,eax / je loc_00441f1b` 直接返回（**卡不消耗**），
只有抢成了才 `consume_card(13)`（`rich4_card_qiangduoka.asm:100`）与
`update_hostility`（:93）。

## 四、仍未做 / 已知近似（不许静默）

1. **命運 5「生日收卡」的真人那一支仍是随机抽。**
   exe 里它复用**同一个** `fcn_0044192a`（模式 0 ⇒ 只有卡片欄），但那一支是在
   `applyFortuneEffect('birthdayCard')` **里面**对**每一位**有牌的人各弹一次窗 ——
   core 现在一次算完，没有「中途停下来等真人挑」的出口。要接得给 core 加一个
   待决交互（`pending.kind = 'stealCard'` 一族），让命运效果分帧落地。
   现状：真人当寿星也走 `pickCardToSteal` 随机抽（`docs/known-deviations.md` 已记）。
2. **对方两手空空时本引擎不开窗**（原版会开一个空框，只能右键取消）。
   判据写在 `needsStealPick`：两欄都空则照旧 `dispatch`，由 core 以 `nothingToRob` 失败、
   走「用不成」那条路（失败音 + 卡片欄弹回）。**这是有意偏离**：空框对玩家没有任何信息量。
3. 选中框的**颜色**是近似的 —— 原版那个矩形交给 `fcn_00451b9e`（直接改像素的例程），
   本引擎用 1px 白框表示（矩形几何有 VA 依据，颜色没有）。
4. AI 那一支不受本窗影响：电脑仍在 core 里按 `get_ai_card_param_value` /
   `player_drop_random_card` 的参数选定（`cards/policy` 一带），走的是**无屏**那条路
   —— 与服务器（无头）一致。
