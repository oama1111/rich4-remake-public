### 7.49 ★ 第 68 条（本轮）：沿「同一条规则、兄弟路径漏改」这条线，修掉**卡牌入狱不占床位**

上一轮在命運路径修掉「单一 occupancy」，本轮按同一形状查了**卡牌路径** —— 果然也漏，
而且漏得更大：**plumbing 根本没接**。

#### (1) 缺口：嫁禍/復仇卡把人关进监狱，却**不占床位**

`cards/frame.ts` 的 `applyFrameCard` 有一个 `occupancy` 参数，但

```ts
occupancy: readonly number[] = new Array<number>(CONFINEMENT_SLOTS).fill(0),   // ← 默认全 0
```
而唯一的调用方 `cards/registry.ts` **从来没传它** —— 于是那个"监狱占用表"是个
**临时全 0 数组**，`confine` 写进去的 `nextOcc[victim] = 1` 随返回值被丢掉；
`UseCardResult` 里也**根本没有 occupancy 字段**，状态里那两张表一动不动。

后果是**玩家可见**的：客户端 `client/src/confine-fx.ts` 靠
「占用表 0 → 1 的跳变」播**关押动效**（`after.prisonOccupancy[i] === 1 && before !== 1`）
⇒ 被嫁禍/復仇的人**连动效都没有**；监狱格占用统计也一直是错的。

#### (2) 修法：把两张表接进卡牌路径（与命運那次同形）

| 文件 | 改动 |
|---|---|
| `cards/frame.ts` | `occupancy` → `prisonOccupancy` + 新增 `hospitalOccupancy`；`confine(..., otherOccupancy)` 让首次入狱清医院那一格（= 原版 `0x41a7c5 call 0x40d761` 的两道闸）；结果两个字段都返回 |
| `cards/registry.ts` | `UseCardContext` / `UseCardResult` 各加两格；switch 里两个局部量；嫁禍支把结果写回；`return` 带上 |
| `state/reduce.ts` | 卡牌 ctx 传两张表；结果写回 `state.prisonOccupancy` / `hospitalOccupancy` |

> ★ 这条与 §7.48 的命運那次**是同一个 bug 的两个副本**：
> 「一个模块只有一个 occupancy 参数」的旧形状，改成两张表时**只改了一条路**。
> 现在 新聞（§7.46 之前）/ 命運（§7.48）/ 卡牌（本轮）三条都接上了；
> 剩下 `placeLanding`/`ball` 之类的路径见 §7.3 的待办。

#### (3) 回归用例（+4）

`packages/core/src/cards/frame.test.ts`：默认表 → 目标那格变 1 / 传入的表被继承
（不是从全 0 重来）/ 首次入狱清医院那一格 / 已在狱者的加刑语义。

#### 诚实边界

- ★ 「卡牌这条入狱是**加刑**还是**覆盖**」**尚未差分**：原版 `0x41a7c5` 之后还有
  分支没读完，本轮的用例只钉住**当前实现**（`confine` 的 2+5=7），
  已在测试里显式标注，别把它当已验证事实。
- 客户端动效（`confine-fx.ts`）本轮**没有**跑起来看；"占用表跳变触发动效"是从
  源码读出的（`after.prisonOccupancy[i] === 1 && before !== 1`）。
- `0x41a3be`（1384 字节的过路费/事件阶梯）**整体未差分**；本轮只用到它里面
  `0x41a7c5` 这一处的语义（`0x40d761` + 20×天×物价的敌意 + 「被关 N 天」台词）。
