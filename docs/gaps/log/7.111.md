### 7.111 ★★ 第 128 条（本轮）：股市「股票」交易支 `0x42565c` **进闸门**（差分 19/19）—— 三个「取址/停址」坑

#### (1) 这一支是什么

`0x4255da(arg1, arg2)` 是股市交易窗口「确认」的处理：先把**挂牌行价格**与当前
玩家现金比一遍，再按挂牌行 `kind`（`1..4`）分派。跳表 `0x4255ca`（实测 dump）
= `[0x42565c, 0x42577d, 0x4257d2, 0x425841]` 依次是
**股票 / 不动产 / 道具 / 卡片**；本轮只驱动第 0 项（股票），也就是复刻
`reduce.ts` 的 `transferListing(stock)` 那一段。

#### (2) 钉住的三条事实（全部由**内存差**实测，不靠读汇编）

| # | 事实 | 对应复刻 | 结论 |
|---|---|---|---|
| 1 | 买家持股 `+= 股数`、卖家 `−= 股数`（u32，不回绕夹紧） | `to.amount` / `from.amount` | 一致 |
| 2 | ★ 卖家清零时**「均价」被写成刚算出的 `edi`**（`0x4256bc` 存的是 `sub` 之后的值，已是 0），而**不是**写常量 0 | 注释 `if (from.amount === 0) from.avgCost = 0` | **语义等价**；本条把「为什么是 0」钉死在机器码上 |
| 3 | ★ 买家新均价 = `(trunc(旧持股 × 旧均价) + 挂牌价) / 买家新持股数`；`oldTotal` **先向零取整**，除完 `fstp dword` ⇒ **32 位 float** | `recalcAvgCost` 的 `Math.trunc` + `Math.fround` | **6 组用例逐位相同**（含 `(1,0.9)`、`(1000,12.345)` 这类易露精度的点） |

另加两道闸：**现金 < 挂牌价 ⇒ 一笔都不动**（`jge`，恰好相等即成交）、
`kind ∉ 1..4` ⇒ 不成交。`_rich4_player_stocks` 的记录布局同时被再次实测确认：
**玩家步长 0x60**（`(p*4−p)*32`）、股票步长 8、`+0` 持股 `i32`、`+4` 均价 `f32`。

#### (3) ★ 三个坑（都记进测试注释）

1. **挂牌表的地址**：`ebx = 0x4967e0 + arg1*0x54 + arg2*0xC` 是**绝对地址**，
   不是「表基 + 偏移」。`0x4967e0` 只落在**已映射的 .bss 内**（`0x48A000+64512`），
   所以注入只能写进真实 DGROUP，不能指望搬到 `SCRATCH_BASE`。
2. **必须走真入口 `0x4255da`**：直接跳 `0x42565c` 时 `ebx=0`，会读到**别的**挂牌行
   （第一次就是这么测出「卖家和买家是同一人」的假象）。
3. **停址取函数尾声 `0x4258b9`**：股票支与「现金不够」那条**提前退出**
   （`0x425639 → 0x4258b9`）都汇到这里；取更早的 `0x42575c` 只覆盖前者，
   走后者会跑飞（`ret` 到哨兵外）。
   ★ 另外踩到一次**字段取址**错误：`_rich4_player_stocks` 的玩家步长一度被我
   按 `0x20` 算（`(p + p*4)*32` 误读成 `(p*4 − p)*32`），导致读出来的「卖家持仓」
   其实是另一个槽位 —— 与 `docs/systems/stocks.md` §5.1 的 `0x60` 对照后订正。
