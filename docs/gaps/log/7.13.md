### 7.13 ★ 第 30 条（本轮）：夢遊卡的**冬眠闸门**（第 28 条留下的另一半，已补齐）

原版 `@source 0x004442be` / `0x004442c5`：

```asm
004442b2  cmp  ebx, 4                  ; 目标下标 ≥ 4 → 替身分支
004442be  cmp  byte ptr [eax + 0x496b9e], 0   ; ★ +0x36 = 冬眠中
004442c5  jne  0x44449b                ; ★ 在冬眠 ⇒ 跳过**整段**（不记敌意、不查防御卡、不施加）
```

关键是**卡仍然被消耗**：原版由调用方在进入处理函数前就 `remove_card`，
所以本实现返回 **`ok: true` + 新的 `outcome.kind = 'ineffective'`**，
而**不是** `ok: false`（那会被 `registry` 当成"打不出去"从而**不扣卡**）。
这类"有效但无效果"与"打不出去"的区分很容易搞错，故用独立的结果类型显式表达。

新增 2 例测试：冬眠目标 ⇒「不施加、不记敌意、`ok` 仍为 true」；
以及**闸门优先于防御卡**（目标同时持免罪卡时**不查、不消耗**它 —— 因为原版在查防御卡之前就跳走了）。

> ★★★ **第 31 条（本轮）：把上一条"策略问题"追到了根 —— 它其实是一条精确规则**
>
> 我上一轮说这是"一个策略决定"，**那个定性不准确**。逐指令读 `0x004441dc` 的开头后，
> 原版的规则是**机械的**：
>
> ```asm
> 004441e0  imul eax, dword ptr [0x49910c], 0x68
> 004441e7  cmp  byte ptr [eax + 0x496b7d], 1   ; 当前玩家是人类？
> 004441ee  jne  0x4441fc                       ; 电脑 → 跳过选择框
> 004441f0  push 0xe0c0710 / call 0x446ae8      ; 人类：弹目标选择框
> 004441fc  push 0 / call 0x41e6f2              ; 电脑：取默认目标
> 00444206  mov  esi, eax                       ; esi = 目标
> 00444208  test esi, esi
> 0044420a  je   0x4444b8                       ; ★ 选不到目标 → 直接返回（**卡未扣**）
> 00444210  push 0x10                           ; ★ 16 = 夢遊卡
> 00444212  mov  ecx, dword ptr [0x49910c]      ; 施卡者
> 00444219  call 0x441343                       ; ★ remove_card(施卡者, 16)
> ```
>
> ⇒ **规则**：**卡在「目标选定之后、效果之前」被移除**。因此
> · **选不到目标** → **不扣卡**；
> · 目标选定之后的**任何** early-exit（冬眠闸门、免罪卡、嫁祸放弃、已在梦遊…）→ **都扣卡**。
>
> remake 的消耗点在**函数末尾**（`registry.ts:829`），所以一切 `fail` 都不扣卡 ——
> 与规则不符的地方就是**所有"目标已选定、但效果没生效"的路径**。
>
> **修法（机械、可逐张核对）**：把每张卡的 `consumeCard` 从函数末尾挪到
> **"目标选定之后"**（即 `applyXxxCard` 内部、拿到合法目标的那一刻），
> 或给 `fail` 加一个 `consumes: true` 让调用方区分。
> 两种都行，但**必须逐张回 exe 确认"目标选定"发生在哪一行** —— 这是剩下的工作量。
>
