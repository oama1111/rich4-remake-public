```
[0] 0x42fa88   ; 状态 1（hello）→ 置 2 + 气泡表 0x4755f8[2]
[1] 0x42fac5   ; 状态 2（price）→ 置 3 + 气泡表[3]

```

**② 建屏那段的三件事**（`0x401` → `0x42f885`）：
五个状态字节清零 → `call 0x42f32c`（做离屏表面）→ `SetTimer(hwnd, [0x46cad8], 0x64)`
→ 现金闸 `cmp dword[player+0x1c], 0x3e8 / jge`：
不足 ⇒ `PostMessage(0x405, 4, 4)`；够且动画关 ⇒ `[0x48c370] = 3`；够且动画开 ⇒ `PostMessage(0x405, 1, 0)`。

#### (2) ❌ 撞到的工具门槛：**User32 的导入跳转桩跑不了**

`WndProc` 里每次 `call dword cs:[0x462324]`（SetTimer）、`[0x462310]`（PostMessageA）…
都是**间接跳进 `.idata` 的桩**，而那些桩的内容是

```
0x462324 的 dword = 0x626fa   ; 而真正的桩在 0x626fa：`EA xx xx xx xx 06 00` = jmp far 0x06xx:xxxxxxxx
```

⇒ 目标是**映射之外的地址**（`0x62xxx` 那一带这个仿真器没映射），
一进去就 `UC_ERR_FETCH_UNMAPPED`。本轮试过两条路：

1. 把 thunk 覆盖成 `xor eax,eax; ret` —— 无效（间接 `call` 走的是 thunk 里存的**地址**，
   不是 thunk 所在的那 4 个字节）；
2. 把 thunk 的**内容**改成 `jmp rel32` 指向自建桩（`SCRATCH_BASE+0x3000`）——
   `rel` 算出来是 `0x1a0cd7`，跳到 `0x1a0cdfff` 仍然未映射。

⇒ **根因未定**（`SCRATCH_BASE` 的实际值与我的预期不符是头号嫌疑），
**如实登记为新工具门槛**：以后凡要驱动**会调 User32 的窗口过程**，都得先解决它。
