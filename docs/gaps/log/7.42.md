### 7.42 ★ 第 61 条（本轮）：**胜利判定**补差分（29/29），并揪出一个「按现数算终局码」的真偏差

按第 60 条做出来的工作单，取分数最高的可驱动目标
（`0x0041d89e`，451 字节、**0 个被调函数** = 自包含），它是全局**唯一的胜负判定**，
返回值直接决定日推进要不要当场收摊（`0x41cfb6 cmp eax,1 / je`）。
而 `checkVictory` / `victoryEndCode` 此前**一个用例都没有**。

#### (1) 差分：`tests/test_victory.py` **29/29**

| 验到的点 | 结论 |
|---|---|
| 两条条件都没开 | 直接返回 0（连遍历都不做） |
| 金额条件 | `首富 >= 目标`（**>=** 而非 >）；赢家 = 在世首富 |
| 天数条件 | `目标 <= 已过天数`（恰好到期也算） |
| ★ **首富资产为 0 时天数条件整个跳过** | 原版 `test edi,edi / je` 如此，不是笔误 |
| ★ 平手 | 取**下标小的**（`jge` 跳过替换 ⇒ 严格大于才换人） |
| 出局者 | 既不参评资产、也不会被选为赢家 |
| 终局码 | 判据是**全局** `[0x499104]`，赢家真人 → `[0x499104]==1 ? 2 : 3`；赢家电脑 → 1 |

两处表现层打桩：`0x41906a`（窗口，`writes` 只有 `0x475110`）与 `0x44ef41`
（`player_say` 台词，`writes` 只有 `0x46caf4`/`0x4762c8`）—— 写入面都不含
玩家/金钱/地图/股市，故打桩只去掉表现层（注意：**清 `whoPlays` 在这两个调用之后**）。

#### (2) ★★ 真偏差：终局码按「现数在场真人」算 —— 多人局里有人先出局就错

原版 `[0x499104]`（人类玩家数）**只在开新局写一次**
（`0x407166` 清零 / `0x407250 inc`），此外只有存档装载会恢复它
（`0x402b81`/`0x40307d push 0x499104`）；**破产处理 `0x40cd87` 不写它**。
差分实测：

| 步骤 | `[0x499104]` | `whoPlays` |
|---|---|---|
| 2 人局初始 | 2 | `1,1,2,2` |
| 把 0 号破产后 | **2（不变）** | `0,1,2,2` ⇒ 现数只得 **1** |

⇒「2 个人类里有 1 个先破产、之后靠时间/资产结束」这一局，原版终局码是 **3（多人）**；
复刻 `victoryEndCode` 按 `whoPlays` 现数得 1 ⇒ 错成 **2**。
（`state/types.ts` 里那条"必须存"的注释、以及 `save-writer.ts` 把 `0x01b0`
一直挂在 carry 上的理由，指向的正是这同一个矛盾。）

#### (3) 修法：把 `[0x499104]` 从 carry 升成**状态字段**

| 改动 | 文件 |

★ 顺带把状态块的三分表从 **30 完全 / 5 部分 / 7 carry** 推到 **31 / 5 / 6**

#### 诚实边界

- `[0x499104] == 1` 且**赢家是电脑**那一支（`0x41d9b9` 起：重置位置、`fillBytes32`
  清玩家 `+0x32..+0x68`、`0x40b93b`、`0x407842`）会走到 `mkf_read_resource`
  而 `UC_ERR_READ_UNMAPPED @0x450471`（与破产处理同一限制）⇒ 该支只钉了故障地址。
- `[0x499104]` 与 `player+0x64` 在 Save0 上仍不一致（`2` vs 只有 1 个奇数）；
  现在复刻**不推导**它（存下来），但这个不一致本身**仍未解**（见 §2.17(c)）。
- 差分是「摆好全局再调一次」；原版真实调用点在日推进里，本轮未跑整条日推进链路。
