### 7.124 ★★★ 第 141 条：**定论** —— 那第二个实参在原版里是**未初始化的栈垃圾**（两个调用点都只压 1 个实参）

> 本条是 §7.123 的收口：把「平手语义取决于第二实参」这件事**查到底**。
> 结论是**确定的**，而且是原版自己的一个缺陷。

#### (1) 两个调用点都只压**一个**实参

`fcn_00431842` 在 `rich4_magic_house.asm` 里只有 **2 处**调用（已 grep 全仓）：

```asm
; @source 0x00432719 起（第一处）
00432719  call _libc_rand
0043272b  ecx = 0xc
0043272f  idiv ecx
00432732  byte [0x48c3a3] = dl          ; ★ 随机挑一个「目标类型」
00432735  al = dl
00432737  push eax                      ; ★★ 只压了 **1** 个实参
00432738  call fcn_00431842
0043273d  add esp, 4                    ; ★ 只清 4 字节
00432740  test eax, eax / je 0x432719   ; 返回 0（一个候选都没有）就重摇

; @source 0x00433910 起（第二处，同构）
00433910  call _libc_rand / idiv 0xc
00433920  bl = dl
00433923  push eax                      ; ★★ 同样只压 1 个
00433924  call fcn_00431842
00433929  add esp, 4
0043392c  test eax, eax / je 0x433910
```

而派发器要读**两个**：

```asm
; @source 0x00431842
00431893  sub esp, 4                    ; 序言：push×4 + sub 4 = 0x14
00431896  ecx = dword [esp + 0x18]      ; arg1 = **类型**（0..11）—— 调用方压的那个
0043189a  … jmp [ecx*4 + 0x431812]
; 各分支开头：`mov dword [esp], edx` —— ★ edx 就是 **arg2**（位于 [esp+0x1c] = [esp_entry+8]）
```

⇒ **arg2 从来没有被调用方压过** ⇒ 派发器读到的是**调用方栈帧里那块位置原有的垃圾值**。
这是原版自身的缺陷（不是我的测试口径问题）。

#### (2) 为什么它「看起来有时对有时错」

按 §7.123 的机制：arg2 决定「最大值槽」的初值，而初值决定平手走哪条路 ——
**所以「并列第一」到底同时进结果、还是只留最后一个，在原版里是不确定的**。
我先前观察到「有时 `[1,2]`、有时 `[2]`」，正是这个未初始化值在不同调用路径下
取到不同内容的结果。

#### (3) ★★ 对 1:1 复刻的含义（这条是要紧的）

| 情形 | 原版 | 复刻该怎么定 |
|---|---|---|
| 无平手（唯一最大） | **确定** | 照抄（已由 §7.114/§7.120 覆盖） |
| 有平手 | **不确定**（未初始化） | 必须**主动定一个**；复刻选了「**平手全收**」（`ai/magic-house.ts` 的候选集） |

⇒ 复刻的做法**不是错**，但 PRD 里**不能**把它写成「原版如此」——
它是**对未定义行为的合理收敛**。按本仓的 `known-deviations` 口径，这应当记为
一条**偏差（原版未定义 / 复刻定为全收）**，而不是「实测一致」。

#### (4) 因此 §7.120 的那一行要改（下一轮动手，理由见下）
