# T-086 大地圖彈窗（工具列第 6 顆「大地圖」／熱鍵「地圖」）—— 有意偏离与未解出的假设

> 复核命令：`python3 tools/disasm.py va 0x0040a801`、`va 0x0040a86d`、
> `va 0x0040a9bd`、`va 0x00407fc0`、`va 0x00407f9e`、`dump 0x474abc 28 4`。
> 窗口过程 **VA 0x0040a801**、入口 **VA 0x0040a9bd**（文件
> `rich4-re/asm/rich4_ui_small_map.asm`）；工具列那一支在
> `rich4_ui_clicking_top_panel.asm` 的跳表 `0x417d39` **第 5 项**（0x00417dd2）。
>
> ★ 结论一句话：**它不是缩放，是一扇 400×400 贴在 (20,60) 的模态浮窗**，
> 只有右键（`WM_RBUTTONUP` 0x205）能关。原先那套「把镜头切成整图取景」
> （`main.ts` 的 `setViewMode`）是本引擎自己发明的，已删。

## D-086-1（有意偏离）「在世」判据改用 `isAlive()`，位置改用节点坐标

@source 标记循环 VA 0x0040a8a1 起：

```asm
0040a8b0  cmp  word [edx + 0x496b70], 0   ; word [player + 0x08] —— **世界 x 坐标**
0040a8b8  je   0x40a922                   ; 为 0 就跳过这个玩家
...
0040a8bc  mov  cx, word [edx + 0x496b70]  ; x = player + 0x08
0040a8dd  mov  dx, word [edx + 0x496b72]  ; y = player + 0x0a
```

**现象**：原版判的是 `player + 0x08`（玩家的**世界坐标 x**）非 0，位置也直接读它
（`+0x08/+0x0a`）。这两个字在破产处理里就是照抄节点结构（VA 0x0040d288：
`mov dx, word [node_ptr + n*40 + 0]` → `player+8`、`+2` → `player+0x0a`），
走路时由 `fcn_0040c332`（VA 0x0040c332）按浮点累加逐帧改写。

**本引擎为什么不能照抄**：`Player.xpos/ypos`（`core/src/state/types.ts` 的
`+0x08/+0x0a`）只在**传送**（`rules/teleport.ts`）与开局写过，开局那一下还写的是
`0`；走路位置在渲染器里（`render.ts` 的走子补间），**没有回写进状态**。照抄判据
会一枚标记都画不出来。

**处置**：
1. 判据用 `isAlive(p)`（`whoPlays & 3 != 0`）—— 与 `xpos != 0` 在本作里**等价**：
   实测八张地图的**任何节点**世界坐标都非 0（min x = 179、min y = 192，
   见 `parseMap` 全部 8 张），所以原版那条判据对真正在场的玩家永不落空；
   两者只在「空座位 / 出局座位」上一致地排除。
2. 位置取 `map.nodes[p.nodeId - 1]` 的世界 x/y —— 这正是原版 `player+8/+0x0a`
   在**站定**时的值（破产处理那段就是节点 → 玩家记录的直接拷贝）。
   ⚠️ 差别只在**走子途中**：原版那两字是插值中的实时坐标，本引擎取的是所在节点。
   模态弹窗只在等待输入时能开（原版那扇窗开着时消息循环根本不跑走子），
   所以稳态下两者相同；这一条如实记在这里。

## D-086-2（有意偏离）浮窗底下的那一帧是**重画**的，不是「存下来再贴回去」

**原版**：WM_PAINT 把整张 640×480 离屏面清掉（VA 0x0040a880 的
`[vtable+0x64]` 调色填充）后只画那 400×400，然后**只 Blt 那块**
（VA 0x0040a938 的 rect `{0x14,0x3c,0x1a4,0x1cc}` → VA 0x0040a95f 的
`BltFast(primary, 20, 60, offscreen, &rect, 0x10)`），所以主面上**除了那块以外
一个像素都没动**。实机截图 S6 也印证：大地圖开着时右侧栏照样显示「資金」页。

**处置**：本引擎的登记屏契约原来是「整屏接管」（画布先清成黑、棋盘不许画），
照那样做会把周围 20px 边条与整个右侧栏涂黑，与 S6 不符。故给契约加了一个
**`windowed?: boolean`**：声明它的屏在 `main.ts` 的渲染链里会**先照常画一整帧
棋盘**（`drawGameStage()`），再把浮窗叠上去。⚠️ 与「原版把旧像素留着」的差别：
本引擎是**重画**同一帧（棋盘是静态的，画出来逐像素相同；但若底下那一屏正在动
—— 例如走路补间 —— 原版会冻住、本引擎会继续动）。

## D-086-3（未解出 · 需中央复核）右键关窗走的是浏览器 `contextmenu`，而它的时机随平台变

原版**唯一**的出口是 `WM_RBUTTONUP`（0x205，VA 0x0040a854：`fcn_00402460(0)` +
`Post_0402_Message(0)`）；左键（0x201/0x202）、中键、键盘一律 `DefWindowProc`。

本引擎按仓库既有惯例把它映到浏览器的 `contextmenu`（股市 / 資產表 / 道具欄 /
設定屏都是这么接的）。⚠️ `contextmenu` 在 Windows 上是**右键抬起**触发、
在 macOS/Linux 上是**右键按下**触发 —— 本屏只认「关」这一个动作，两种时机
结果相同；但若将来有人在这扇窗上加「按下记账、抬起成立」的交互，
**必须**先把这条时机差异处理掉。

## D-086-4（有意偏离）键盘在弹窗里被**全部吞掉**，但吞的位置在 `hotkey` 钩子里

原版窗口过程对 `WM_KEYDOWN` 走 `DefWindowProc`（VA 0x0040a9a4），
所以钥匙盘关不掉这扇窗、也推不开别的屏。本引擎的 `handleHotkey` 会先问登记屏，
故本屏声明 `hotkey()` 在**开着的时候返回 true**（一个键都不放行，
`BIG_MAP_ALLOWED_HOTKEYS` 是空表）。
⚠️ 这依赖 `main.ts` 的「登记屏先认领熱鍵」那一段；调试键（Ctrl+Shift+X）不受影响。

## D-086-5（有意偏离）删掉了 `setViewMode` 与它带来的整套「地图视角」

`setViewMode('map')`（把镜头换成 `fitCamera` 的整图取景）在**原版里没有对应物**：
`HOTKEY.map` 与工具列第 6 颗在原版都只开那扇弹窗。改接弹窗之后它一个调用点都
不剩，按铁律 3「不许改良」删掉，同时删掉只为它引入的 `fitCamera` 导入。

⚠️ **连带影响（未一并清理，留给后续）**：`camera.mode` 从此恒为 `'character'`，
于是下面三处判断永远走不到：

| 位置（`main.ts`） | 原用途 |
|---|---|
| `case HOTKEY.cursorUp..cursorRight` 的 `if (camera.mode !== 'map') return false` | 游標鍵平移地图 |
| 滚轮那支 `if (camera.mode !== 'map') return`（VA 0x004185d8 那一族） | 地图缩放 |
| 拖棋盘那支 `if (camera.mode !== 'map') return` | 地图拖拽 |

三处都是**本引擎自己发明**的（原版的地图交互是**侧栏那 200×200 小地图**上的点选
与拖动，见 `hud.ts`）。没有一并删是因为它们散在别的 agent 正在改的区域里，
本轮只做加法、避免冲突 —— 下一轮清掉时把这一段一起收掉。
`render.ts` 的 `fitCamera` 本身保留（`render.test.ts` 仍逐条钉着它的算法）。

## ★ 2026-09-16 结案：D-086-5（`setViewMode` 删除的连带）

上一轮删掉 `setViewMode` 时登记了「三处 `camera.mode === 'map'` 判断随之成为
走不到的分支」，本轮清干净：

| 清掉的 | 原行为（自造） | 现在 |
|---|---|---|
| `Camera.mode` / `ViewMode` / `fitCamera()` | 「地图视角」整图取景 | **删除** —— 原版只有等距投影那一种看法 |
| `worldToScreen` 的 map 支 | 平移缩放 | 删除 |
| `#drawGround` 的 map 支（含压暗底图） | 平铺 + 压暗 | 删除 |
| 三处 `const k = cam.mode === 'map' ? cam.scale : 1` | 随缩放放大图素 | `k = 1` |
| 滚轮缩放 | 自造 | **删除**（原版没有缩放） |
| 拖棋盘平移 | 自造 | **删除**（原版镜头恒以当前玩家为中心） |
| **方向鍵（游標）** | 自造：平移地图视角 | **什么都不做**，见下 |

### 方向鍵为什么是「什么都不做」

原版这四个鍵是**移动鼠標指针** —— `rich4_keyboard_hook.asm` 开头就是
`GetCursorPos` + `SetCursorPos(x±10, y±10)`（@source VA 0x00401059..0x004010a9），
是给纯键盘用户指方向用的。**浏览器里移不了系统光标**，所以既不能照抄，
也不该拿它去做原版没有的事（先前那个「平移地图视角」就是自造的）。
⇒ 如实登记为**本引擎的已知差异**：方向鍵无作用。

（若将来要做「虚拟指针」——在游戏内部维护一个指针位置并合成 hover/click ——
那才是 1:1 的做法；本轮不做，登记在此。）
