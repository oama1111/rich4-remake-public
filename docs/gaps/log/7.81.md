### 7.81 ★ 第 99 条（本轮）：**四个「踩上去」物件落点**整段差分（51/51）—— 逮到「另外三个惡人踩地雷不受伤」＋ 查出「寶箱写死槽 14」的正当性

#### (1) 通道 2 差分：`rich4-spec/tests/test_object_landing_fragments.py`（51/51）

驱动的四个入口是**大落点分派器**（函数体 `0x41b42d`，帧 `sub esp,0xa8`，
真尾声 `0x41c844`）的跳表成员：寶箱 14 `0x41bb0c`、路障 16 `0x41bceb`、
地雷 17 `0x41be5f`、炸彈 18 `0x41bfd2`。逐条钉住（全部 `@source` 在测试文件里）：

| 类别 | 玩家 0..3 | 小偷 4 | 5..7 | 8 |
|---|---|---|---|---|
| 14 寶箱 | `remove(**0xe**)` + `+0x30 += 500`（16 位回绕）+ 事务 + 文字框 + `say(自己,0,…)` | `remove(0xe)` + **主人** `+0x30 += 500`、**主人**说台词、收尾 `refresh_map()` | 无事 | 跳表外 |
| 16 路障 | `remove(槽号)` + `[0x48baf8]=0` + `say(自己,1,#0247)` | `remove` + `receive_tool(主人,2)`（+文字框） | `remove` + `[0x48baf8]=0`，不说台词、不回收 | 跳表外 |
| 17 地雷 | 停稳才炸：`remove` + 毁座驾 + MKF 动画 + `say(自己,1,#0248)` + **住院 3 天** | `remove` + `receive_tool(主人,3)`，不毁车不住院 | **停稳时：`remove` + 动画 + 住院 3 天**（不毁车、不说） | 跳表外 |
| 18 炸彈 | `+0x40 = 槽号` + 记录 `+5=自己+1`/`+4=0x26` + 清当前格 `[node]+0x26` + 事务 + `say(自己,2,#0249)` | `remove` + `receive_tool(主人,4)` | 无事 | 跳表外 |

三条订正性结论：

1. **`0x41b3d0` 不是本分派器的尾声** —— 它是上一层 `0x4198b9` 的（`add esp,0xf8`）。
   第 94 条那套「把 `0x41b3d0` 打成 `ret`」之所以能跑通，是因为那些得點券格
   **不写 `[esp]`**；四个物件处理器里有两支要 `sprintf`，而
   `0x41bc26 lea eax,[esp+0xc]` 算出的目标**正好等于 `[esp]`** ⇒ 返回地址会被
   台词文本覆盖。**正解是 `eval_block(入口, 0x41c844, …)` + 手搓帧**
   （`STACK_TOP+0x98/0x9c/0xa0/0xa4` 四个字；见 `verification.md` 通道 2 的新注记）。
2. **actor 8 根本进不了跳表**：`0x41b4e7` 在跳表**之前**就把它截住，
   只做「`0x40fafd` 打飞 + `remove_object`」。所以各处理器里那些 `cmp …,8 / jge`
   对娃娃是死代码，真正生效的是 `rules/special-actors.ts` 的 `runDoll`。
3. **`0x445a4d` 是 `receive_tool(玩家, 道具号)`，要从商店池扣 1**（`0x445a73`
   读 `remain_tool_amount[道具-1]`、为 0 直接返回；`>8` 才跳过）——
   「小偷拆陷阱给主人」不是凭空造一件。
4. ★ **分派器入口本身也驱动了**（同文件 `[F]` 组 7 例）：只写**地图格编码字**
   `[node+0x24]`（低 8 位格子种类 / 8..11 玩家占位 / 16..23 槽号）与当前格号，
   让 `0x41b461 → 0x41b47f → 0x41b491..0x41b4e0` 自己拆帧、按 `[esp+0x9c]` 查跳表。
   钉住：空槽 ⇒ 零调用；槽 14+类别 14 ⇒ `+500` 且拆槽 14；`[0x48baf8]=1` ⇒ 寶箱不生效；
   **actor 8 ⇒ 照飞照拆但 `+500` 不发生**（跳表外截住）；actor 5 + 地雷 ⇒ 住院 `(5,3)`。
   ⇒ 工作单里 `0x41b42d`（986 B）由此划掉。
   （★ 分派器里「踩到乞丐」那一段 `0x41b5fd` 起 = `施捨給乞丐%d元`：
   已由 `rules/beggar.ts` + `object-integration.test.ts` 覆盖，本测试不重复。）

#### (2) ★★ 「寶箱写死 `0xe`」的正当性：槽号→类别是**固定表** `0x47ed3c`

装载地图时 `0x407d4e..0x407d68` 把 46 字节常量逐字节写进 `objects_info[i].+0`：

```
槽  1..14 → 类别  1..14      （每类恰好 1 槽）
槽 15..16 → 类别 15           （`0x41c164` = 不处理）
槽 17..26 → 类别 16 路障       （10 个）
槽 27..36 → 类别 17 地雷       （10 个）
槽 37..46 → 类别 18 定時炸彈    （10 个）
```

⇒ 类别 14 只可能在槽 14，`push 0xe` 不是笔误；同族还有类别 11（`push 0xb`）、
类别 13（`push 0xd`）。**路障/地雷/炸彈有 10 个槽，必须用帧里的真实槽号**
（`[esp+0xa4]`）。已写进 `tools.md` §6.1.2 + §6.3.0。

#### (3) ★★ 逮到复刻侧一个真缺口：**另外三个惡人踩到陷阱不疼**

`rules/npc-walk.ts` 原来只实现「小偷（actor 4）拆陷阱」，
而原版地雷/路障的**玩家分支**对 5..7 同样生效（`cmp …,4 / je` 只排掉 4）：

- **路障**：任何一步都拦（不看剩余步数）⇒ `remove_object` + 停步；
- **地雷**：**只有停在这一格**才炸（`cmp [0x48baf8],0 / jne`）⇒ `remove_object` + 住院 3 天。

两者的陷阱都**回商店库存**、**不进任何人的道具栏**（与 actor 4 那一支不同）。
已实现：`NpcEvent` 新增 `{ kind:'trap', node, object, objectType, hospital }`，
`runNpc` 在 actor≠4 时按上述规则收场，`applyNpcEvents` 负责拆除 + 回库存，
`reduce.ts` 两处调用点把「住院」同步进 `hospitalOccupancy`。
测试：`npc-walk.test.ts` +4（路障半途拦下、地雷路过不炸、地雷停在最后一格住院、
小偷不上当）。
