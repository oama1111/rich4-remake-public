### 7.29 ★ 第 48 条（本轮）：回头核上一轮写的神明改租 —— **订正规格形参，确认复刻口径正确**

第 47 条写 `gods.md` §6b 时，函数签名是**按入口那段猜的**。本轮把调用点
`0x419d70` 的压栈与序言对齐，发现**猜错了中间那一个参数**，顺带把一条
要紧的口径也钉住了。

#### (1) 订正：`0x41d709` 的三个形参

序言 `push ebx / push esi / sub esp,0x80` 一共让出 `0x88`，故
`arg1 = [esp+0x8c]`、`arg2 = 0x90`、`arg3 = 0x94`。对上调用点的三次 push
（自下而上 `ebp` / `[0x47517c]` / `[0x49910c]`）：

| 位置 | 实参 | 用途（本轮证据） |
|---|---|---|
| arg1 | `[0x49910c]` = **当前玩家** | `imul …,0x68` 后读 `+0x3f` ⇒ **取付款方身上的神明** ✔ 原判正确 |
| arg2 | `[0x47517c]` | 分支里被 `push edx / push 0x463c67 / call sprintf` 当 **`%s` 的实参** ⇒ 是**提示文本**，**不是「設施」** |
| arg3 | 压在栈上的 `ebp` | **要调整的租金** |

⇒ 规格里 `adjust_toll_by_god(payer, facility, toll)` 的 **`facility` 是错的**，
已改为 `(player, text, toll)` 并新增 §6b.4。（教训与 §五 同类：
**入口那段看不到调用约定，必须回去读调用点**。）

#### (2) ★ 确认复刻口径正确：神明乘在**合并总额**上

调用点 `0x419cbd` 先 `add ebp, edx`，**之后**才把 `ebp` 交给 `0x41d709`；
紧接的 `fild edx / fild ebp / fdivp` 算出 `edx/ebp` 存进 `[esp+0xc4]` ——
那是**显示用的比例**（先算总额、再拿比例格式化），与本函数无关。

⇒ 复刻 `rules/rent.ts` 的 `adjustTollByGod(ownerPart + allyToll, 付款方.godInfo)`
**口径一致**：神明按「地主那份 + 同盟那份」的**合并总额**加减，
不是只乘地主那一份。**本轮没改复刻代码**（它本来就对），只把「为什么对」写进了规格。
