## 本轮（T-041 补修）：屏幕中部那块**纯黑矩形**

**现象**：真浏览器里把日期推到月底，结算屏中部一块约 `(208,70)-(314,271)`
（舞台坐标）的**纯黑矩形**，两帧之间完全不变；黑板下缘还贴着一个小人棋子，
棋子四周也有一圈黑底。

**根因**：那一带的精灵是**带透明底**的，而本模块拿**不透明**的那支去画。
原版有两支 blit：

| 函数 | VA | 实现 | 效果 |
|---|---|---|---|
| `fcn_004563f5` | 0x004563f5 → 0x00455b3a | `rep movsd` | **不透明**：图素里 RGB555 = 0 的背景原样盖上去 ⇒ 黑板 |
| `fcn_00456418` | 0x00456418 → 0x00455c52 | `lodsw / or ax,ax / je` | **抠黑**：0 跳过 |

**（1）左侧面板**（主要那块）：

```asm
00439c3a  mov eax,[0x48c41c] / add eax,0xf0   ; ★ 图 19，不是图 1
00439c5d  push 0x46                            ; y = 70
00439c5f  push 0x18                            ; x = 24
00439c73  call 0x456418                        ; ★ 抠黑
```

图 19 是 186×410 的「记者小姐」立绘，抠黑后落在 (24,70)（它的透明部分露出底图）。
本模块原先在这里画的是**图 1**（290×201 的「存款」气泡）并且走**不透明**，
于是图 1 那 16952 个 0 像素变成了一整块 290×201 的黑板。

**（2）行头像**：`0x00439d35` / `0x0043850d` 两处也都是 `call 0x456418`（抠黑），
而本模块的抠黑表 `MONTHLY_KEYED` 只列了图 6..10、**漏了 47..82** ⇒ 每个棋子
都被盖上黑底（黑板下缘那一圈）。

**（3）同一处的第三个 bug**：头像图号多加了「帧」（见 D-MONTHLY-10）⇒
部分角色 `sprite()` 返回 null、整块不画。

**处置**：三条都按 exe 订正（`MONTHLY_CHUNK.panel = 19` + `monthlyKeyedBlack()`
+ `monthlyRowLayout` 去掉 `+帧`），单测钉住「图号 / 落点 / 抠黑」三件事。
离线合成同一帧复核：黑板消失，先前缺的那一行棋子出现。

## D-MONTHLY-1（**订正**）结算屏那一行头像的落点 —— 查表值是 **y**、x 是常数 600

**先前记的是**「`0x475918` 那段不是 word 表、读不出，只好改用頒獎屏那张
`{60,180,300,420}` 当 x」。**这一轮逐条复核后订正**：表是**静态可读**的，
只是被读**反了**。

**原版**（`loc_00439cd7`，VA 0x00439cd7 起）：

```asm
; ebx = 行号，esi = 在场人数 [0x48c420]
00439cee  mov edi, esi
00439cf0  shl edi, 3                       ; edi = 8 × 人数
00439cf3  mov esi, ebx
00439cf5  movsx esi, word [edi + esi*2 + 0x475918]   ; ★ T[人数][行]
00439cfd  push esi                         ; ← 先压 = **y**（cdecl 从右往左）
00439cfe  push 0x258                       ; ← 后压 = **x** = 600
```

| 人数 | 表行 | 值（= 行头像的 **y**）| @source |
|---|---|---|---|
| 2 | `0x475928` | `{120, 360}` | `0x475918 + 8×2` |
| 3 | `0x475930` | `{100, 240, 380}` | `0x475918 + 8×3` |
| 4 | `0x475938` | `{60, 180, 300, 420}` | `0x475918 + 8×4` |

即：4 人局里原版的 4 个头像落在 **`x = 600`、`y = {60,180,300,420}`**
（竖向叠在画面右侧，行距 120）；本模块把查表值当成了 x、
又给它配了一个 `y = 294`（那是頒獎屏那一步的高度公式），
于是 4 个棋子横着摊在名牌上、还被后画的名牌盖掉。

**处置（本轮已改）**：`monthlyRowLayout(state, i, screen)` 按屏分两套 ——
结算屏 `avatar = (600, MONTHLY_SEAT_Y[行])`、頒獎屏 `avatar = (MONTHLY_SEAT_X[槽],
330 − h + 锚点)`。`MONTHLY_SEAT_X` 与 `MONTHLY_SEAT_Y` 各记各的表
（`0x475930` / `0x475918`），单测钉住「结算屏 x=600 且 y ∈ {60,180,300,420}」
「頒獎屏 x ∈ {60,180,300,420} 且 y=294」。

| 症状 | 处置 |
|---|---|
| 行头像的 x/y 与原版对调 | **已订正**（`monthlyRowLayout` 的 `screen` 参数；单测钉住）|
| 那张表的 `人数 = 1` 槽是别的数据（`0x475920` 读出 `{12339,12336}`）| 1 人局本来就不頒獎，**接受** |

## D-MONTHLY-2（**未解出**）頒獎屏 4 列头像是「叠在竖栏上」还是「各占一栏」

原版 `loc_0043849e`（VA 0x0043849e..0x00438518）那一段，先按**槽 0..3**
画 4 张窄板（图 11..14），再按**同一批槽 0..3** 画 4 张竖栏（图 15..18），
最后按**同一批槽 0..3** 画 4 张头像：

```asm
帧   = [0x475960 + 槽*24 + 槽*2]
图像 = 3×角色 + 47 + 帧
x    = {60,180,300,420}[槽]
y    = 0x14a − h[帧] + y[帧]           ; 0x14a = 330
```

四列 x 跨度 60..420、每张头像 42..66 宽，**互不重叠**；
但 y 都在 294 附近（三帧的 `height/y` 都是 `(72,36)`）。
把这一组常量喂进原版的 12 个头像图逐个核过，**四张确实会互相盖住**。

**处置**：照抄原版，不做改良。若日后拿到一张原版頒獎屏截图，
第一件要核的就是这 4 个头像的 y。

### ★ 2026-09-16 追加：x **不是**常数 `{60,180,300,420}`，而是**按「在榜人数」查表**

原文那一句 `push [0x475930]` 少看了两个下标。完整式子（`loc_0043849e`，
`rich4.asm:16618-16630`，同一支也用在 FLIC 落点上 `:17637`）：

```asm
ebp = byte [0x48c420]                 ; ★ 在榜人数（1..4）
shl ebp, 3                            ; 人数 × 8
名次 = ebx
x = word [ebp + 名次*2 + 0x475930]    ; ★★ 表按 (人数, 名次) 查
y = 0x14a − h[帧] + y[帧]
```

把 `0x475930` 逐行 dump 出来（**另一条独立校验**：同一套映射读道具表
`0x47fee2+5` 得到的 13 个 price 与 `@rich4/data` 的 `TOOLS[].price` 逐个相同）：

| 在榜人数 | 四列 x |
|---|---|
| 1 | `{60, 180, 300, 420}` ← **先前当成常数照抄的就是这一行** |
| 2 | `{407, 490, 0, 0}` |
| 3 | `{324, 407, 490, 0}` |
| 4 | `{324, 407, 490, 573}` |

⇒ **普通四人局（人数 = 4）四列应是 `324/407/490/573`（间距 83），
不是 `60/180/300/420`**。现行 `monthly-screen.ts` 的
`MONTHLY_SEAT_X` 用的是后者 —— 即「1 人在榜」那一行。

**✅ 同日定案并改掉**：`[0x48c420]` 就是**在榜人数**，证据是它的赋值处
（`rich4.asm:19034-19048`）：

```asm
00439caa  for (eax = 0; eax < num_players; eax++) {
            if (player[eax].who_plays == 0) continue     ; 出局跳过
            [0x48c418 + [0x48c420]] = eax                 ; 名次表按玩家号升序填
            [0x48c420]++
          }
```
—— 数的是 `who_plays != 0` 的人数，且名次表就是「在榜玩家按玩家号升序」。
再拿**同形的竖栏表** `0x475960` 做交叉验证：四人在榜那一行是 `{15,16,17,18}`
（四个人四根竖栏 ✓）、三人 `{15,16,17}` ✓、两人 `{16,17}` ✓ ——
行就是人数，没有别的解释。（第 1 行是死数据：本游戏至少 2 人，
与 D-MONTHLY-1 里「1 人槽是别的数据」是同一条。）

⇒ **四人局**：x = `{324,407,490,573}`（间距 83）、竖栏 = `{15,16,17,18}`；
两人局 x = `{407,490}`、竖栏 = `{16,17}`。

`monthly-screen.ts` 已改：新增 `MONTHLY_AWARD_SEAT_X` /
`MONTHLY_AWARD_SEAT_FRAME`（按 `(在榜人数, 名次)` 查），
`monthlyRowLayout(..., 'award')` 两处都查表；
`MONTHLY_AVATAR_FRAME` 补上 18（四人在榜时第 4 列）。旧常数
`MONTHLY_SEAT_X` / `MONTHLY_SEAT_FRAME` **保留** —— 结算屏的 y 表
（`0x475918` 四人行）恰好也是 `{60,180,300,420}`，但**不许**再拿来当頒獎屏的 x。

⚠️ 仍缺：`y` 那一步原版读的是**角色立绘**记录的 `+0x0e`/`+0x12`，
本模块按「帧 → (72,36)」近似（四列同值 ⇒ 都是 294）—— 与 D-MONTHLY-8 同一类近似。

## D-MONTHLY-3（**有意补写**）`存款：` / `利息：` 两个标签

原版这一屏**不重画**这两个标签 —— 串 `0x464e56`（`存款：`）与
`0x464e90`（`利息：`）在结算是作为**参数**传给 `fcn_0044ec30` 的，
也就是「气泡 + 里面那行字」是一整块被贴上去的。

本模块**把两个标签自己写上去**，落点照原版那四条 `draw_text` 的**目标面局部**：
`存款：` 在 `(4,6)`、`利息：` 在 `(4,0x2e)`（@source 0x00439d3d / 0x00439db5）。
理由：原版那两个串是 `draw_text` 的参数、不是烤进图里的，本模块没有 GDI 那一层，
只能自己把这两段画出来，否则那一行只有数字没有标签。

⚠️ **本轮订正**：先前的落点 `(0x2e,0x84)` / `(0x2e,0xe6)` 是**旧读法**（把气泡局部
当行局部），已作废；现行落点见 `MONTHLY_ROW_AT` 与 `MONTHLY_ROW_BLOCK_X`。

| 症状 | 处置 |
|---|---|
| 标签是客户端画的、不是图里的 | **接受**（位置用原版那四个局部偏移）|

## D-MONTHLY-4（**订正**）頒獎屏状态 1 贴的那一小块 —— 是**裁切拷贝**，不是缩放

> ⚠️ **本条的结论又被 D-MONTHLY-8 订正**：源图不是图 1 而是**图 0**，
> 尺寸也不是 70×24 而是 **186×410**。下面这一段保留，只为记录订正的来路。

**先前（包括旧注释与一张草图）记的是**「把区域 `(24,70)-(261,480)` 缩放着
贴图 0」。

**复核后订正**：`loc_00437fff` 走的是 `fcn_0045643d`（VA 0x0045643d，转调
`draw_image_in_rect_ex`），参数序是
`(dst, src, x, y, x_move, y_move, init_copy_width, init_copy_height, use_draw_area)`：

```asm
push 0x19a   ; x_move
push 0xba    ; y_move
push 0x46    ; init_copy_width  = 70
push 0x18    ; init_copy_height = 24
push 0x46    ; y  = 70
push 0x18    ; x  = 24
```

即「把图 1 落在 `(70,24)` 处那块 **70×24** 原样盖到 `(24,70)`」——
`x_move`/`y_move` 才是后两个数，先前把它们当成目的地尺寸，**读反了**。

本模块按订正后的读法实现（`drawMonthlyScreen` 里那段 9 参 `drawImage`），

## D-MONTHLY-7（**机制已解出 · 2026-09-16**）「无人获奖」那句 `別灰心，再加油喔！`

**先前挂的理由是「`fcn_0044ec30` 的第一个参数走的是另一套资源、没核清」。核清了 ——
那个参数根本不是图号，而是「图素记录表的指针」。**

```asm
; ── 呼叫点 VA 0x00438a31（`[0x48c42a] == 9` 的处理器）
00438a31  push 0                       ; arg7 = 描边色 0
00438a33  push 0x101010                ; arg6 = 文字色
00438a38  push 0                       ; arg5 = 文字基线 y 偏移 0
00438a3a  push 0x14                    ; arg4 = 文字基线 x 偏移 20
00438a3c  push 0xa                     ; arg3 = y = 10
00438a3e  push 0xbe                    ; arg2 = x = 190
00438a43  mov eax, [0x48c41c]          ; ★ 图素表基址（= `Panel.mkf` #25）
00438a48  add eax, 0x30                ; ★ **记录表偏移**：(0x30−0xc)/12 = 图 **3**
00438a4b  push eax                     ; arg1 = &图素记录[3]
00438a4c  call 0x44ec30
00438a51  add esp, 0x1c
00438a54  mov eax, 0x464e21            ; `#0108別灰心，再加油喔！`
00438a5a  call 0x44ecb6
```

`fcn_0044ec30`（VA 0x0044ec30）逐条读下来的签名是
**`(图素记录*, x, y, 文字x偏移, 文字y偏移, 文字色, 描边色)`**：

| 存到 | 值 |
|---|---|
| `[0x4762bc]` | arg1（记录指针）|
| `[0x48c624]` / `[0x48c620]` | arg2 / arg3（**锚点前的落点**）|
| `[0x48c618]` / `[0x48c62c]` | arg4 / arg5（**文字在盒心的偏移**）|
| `[0x48c61c]` / `[0x48c628]` | arg6（文字色）/ arg7（≠0 时描边 3 px，否则 2 px）|
| `[0x48c608..0x48c614]` | 盒矩形 = 记录自己的 `w/h` 减去锚点后落在 (x,y) |

`fcn_0044ecb6(串)` 才真的画：把那张图按锚点 blit 到 (x,y)，再用
`create_font(0x14, 文字色, 描边色, 2 或 3, 1)` 把串画在**盒心 + (arg4, arg5)**、
对齐 flag **4**（正中）。

所以这一屏的那只盒子 = **`Panel.mkf` #25 的图 3（239×193 圆气泡）落 (190,10)**，
文字落 **盒心 + (20, 0)**，20 号 `#101010`、描边 2。

**剩下没接的只有「触发时机」**，也已经查清，但本模块的状态机形状不同：

| `[0x48c42a]` | 干什么 | @source |
|---|---|---|
| 2 | 算 `[0x48c42f]`（悲情分最高者，`fcn_00437d1a`）与 `[0x48c430]`（首富，`fcn_00437dfe`）| 0x00438240 |
| — | **动画开**：`[0x48c430] == [0x48c42f]` 或 `[0x48c42f] == 0xff` → 直接跳 **0xf**（收尾）；否则 → 5 | 0x00438254..0x00438275 |

## D-MONTHLY-10（**订正**）行头像的图号 = `3×角色 + 47`，**没有**「帧」

**原版**（两处都是）：

```asm

00439d0d  mov eax, edi / shl eax,2 / sub eax,edi     ; ×3
00439d14  lea edi, [eax + 0x2f]                      ; + 47
00439d23  mov eax,[0x48c41c] / add eax,0xc / add eax,edi   ; &img[3×角色+47]
```

先前的实现写成 `3×角色 + 47 + 帧`，其中「帧」取自 `[0x475960]` 那张表查出的
`15/16/17` —— 那是**頒獎屏竖栏（图 15..18）的图号**（`0xc + 12×值`），
与头像无关。加上它以后图号会落到 **62..98**，而资源 25 只有 **0..82** 张 ⇒
`sprite()` 返回 null ⇒ **有些角色整块不画**（真浏览器实测：4 人局里
「糖糖」那一行没有棋子，其它行也被画成了**别**的角色）。

**同一处**：`y = 330 − h + 锚点y` 里的 `h`/`锚点y` 原版是从**被画的那张头像
自己**读的（`+0x0e`/`+0x12`，VA 0x004384de/e2）。本模块仍用 `(72,36)` 兜着
（`MONTHLY_AVATAR_FRAME`），对 h/锚点不同的角色会差几个像素。

★ **2026-09-16 补：这一条也订正了** —— `monthlyRowLayout` 多收一个
`portrait`（`{height, anchorY}`），绘制那一趟先把立绘取出来再算 y，
于是用的就是**图素自身**的字段。`Panel.mkf` 资源 25 的 47..82（12 角色 × 3 帧）
逐张一查，差别是实打实的：

|---|---|---|---|---|
| 0 | 47..49 | 66×72 | (33,36) | 294 |
| 1 | 50..52 | 66×68 | (33,34) | 296 |
| 2 | 53..55 | 42×68 | (22,31) | 293 |
| 3 | 56..58 | 36×58 | (18,29) | **301** |
| 4 | 59..61 | 48×66 | (24,33) | 297 |

（同一角色那 3 帧的尺寸/锚点相同 —— 这也解释了原版为什么敢用
