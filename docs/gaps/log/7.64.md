### 7.64 ★ 第 83 条（本轮）：**结掉 §7.3 第 15 项** —— 关押的传送/跟班搬家全段差分（48/48），并揭出「回棋盘」那一段

#### (1) 根因不是"忘了三件事"，而是**位置搞错了**

原版把「传送到监狱／医院格 + 跟班搬家」写在 `send_to_prison`/`send_to_hospital`
**函数体内**（`@source 0x0043d601`..`0x0043d674`），所以**每一个**调用点自动获得它。
复刻却把这两件事留给调用点自己做 ⇒ 6 个调用点里只有 2 个接了：

| 调用点 | 改前 | 后果 |
|---|---|---|
| `state/reduce.ts` 魔法屋（`applyMagicRequest`） | ✅ 已接 | — |
| `state/reduce.ts` 飛彈/核彈送医 | ✅ 已接 | — |
| `state/reduce.ts` 炸彈落地住院（`r.hospitalDays`） | ❌ | 伤者还站在雷上 |
| `cards/frame.ts` 陷害卡 / 復仇卡 | ❌ | 受害者不进监狱格 |
| `events/fortune-effects.ts` 命運「坐牢／住院」 | ❌ | 同上 |
| `events/news-effects.ts` 新聞「坐牢／住院」 | ❌ | 同上 |

**修法**：新增 `rules/confinement.ts` 的 `sendToConfinement(players, objects, nodes,
occupancy, kind, index, days, otherOccupancy?)` —— 它就是「`send_to_*` 的完整函数体」：
`confine()`（计数 + 清四项 + 清"另一张"表）→ 首次才 `teleportToGate()`
（nodeId/x/y 原子搬、`lastNodeId=0`、`whoPlays &= 0x0f`）→ `syncEscortNodes()`
（`+0x3f`/`+0x40` 两个跟班物件各自独立地搬）。**6 个调用点全部改走它**，
`applyFrameCard`/`applyFortuneEffect`/`applyNewsEffect` 各自多带 `nodes`/`objects`
并回传 `objects`（缺省时只写计数，兼容既有单元测试）。

「全函数通道 2 差分已跑通」。几条以前不知道/记错的：

- 节点占用位是 **`0x100 << idx`**（槽 0..7 → bit8..15），**只清旧格、不置新格**；
- 尾段 `0x44ba63(idx, days × 2000 × 物價指數)` 是**保险理赔**，且**首次与加刑都走**
  （实测金额 5×2000×pi、2×2000×3、加刑 4×2000×1 全部命中）；

- 节点表 `[0x498e80]` 是**按 nodeId 直接索引**（带 0 号哨兵项），不是 `(nodeId−1)` ——
  测试台一开始照 `(nodeId−1)` 铺就被这条打回来了。

#### (3) ★ 新揭出的残留：**释放后「走回棋盘」的第三段**（未实现）

读 `0x40fc00` 的调用点时才注意到：`0x40d6be`（释放第一段）只立标记、`0x40c05c`
（走路例程）只清账，**都不搬人** —— 真正让刑满者回到棋盘的是**他自己回合的开头**：

```asm
; @source 0x418ebd（回合推进函数）在把 [0x49910c] 推到下一位之后的这一段
00418f07  test byte [player + 0x496b7d], 0x30 / je 0x418f93   ; 没被阻碍 → 正常开局
00418f25  test byte [player + 0x496b7d], 0x10 / je 0x418f80   ; 只有「回棋盘」标记才继续
00418f2e  bl = byte [player + 0x496b83] / and bl, 0xf
00418f37  cmp bl, 0xf / je 0x418f42        ; ★ 关押写的哨兵 ⇒ **不恢复**朝向
00418f3c  byte [player + 0x496b78] = bl    ;    否则把朝向后备写回 +0x10
00418f59  call 0x40f381                    ; ① 神明显灵落点（gods.md §4.3）
00418f78  call 0x448a7e                    ; ② ★ 语义未读通
00418f87  and  byte [player + 0x496b7d], 0xf  ; 清 0x10/0x20
00418f8e  jmp  0x419058                    ; 这一回合到此为止（不掷骰、不走子）
```

复刻现在只做了「清占用表」那一半，**整段回棋盘流程都没做**。
`0x448a7e(player, cell)` 已读到的前置：`who_plays == 0` 返回、`(traffic_method & 0x83) != 3`
返回、`+0x37`（梦游）非 0 返回、`+0x32`（住宿）非 0 返回；随后按 `node[cell+0x20]`
的格值分派 `0x7d0 < v < 0xfa0`（住宅地）那一段；写点是**回合记录表**
`0x498ea0+player*0x34` 的 `+0x02/+0x03` 与全局 `0x46cafb`。
⇒ 它是**规则可见**的（写了回合记录），不能当表现层糊过去。**下一轮的第一件事**。
