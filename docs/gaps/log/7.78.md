### 7.78 ★ 第 97 条（本轮）：**用户口径澄清** + 补上原版三个 `srand` 时机里宿主负责的两个

#### (1) 用户决定（2026-09-19，本轮记录，后续轮次照此执行）

> 「原版预言机有差异问题不大，只要**原则上符合随机**且**回档后重新扔骰子/股票走向会有新的变化**即可；
> 不用浪费太多时间确保复刻版的随机数算法和原版 100% 一样。」
> 「我只要求暂缓**画质升级**和**联网功能**。」

⇒ 两条口径落进本文件：
1. **RNG**：不再追位级一致。这直接收口 §7.3 的 **1.6** 与 **4**（AI 随机流）——
   改为只验两条**可观察原则**：① 局面随种子变化（不固定）；② 读档后重新播种。
   同理，第 95 条登记的 **T-STOCK-1**（`fprem` 差一跳）从"待修"降级为"可接受"，
   通道 3 原版预言机的优先级也随之下降（不再是完成条件的硬门槛）。
2. **范围**：只有 **画质升级**（美术重绘/高清化）与 **联网功能** 暂缓；
   **动效 / 语音 / 音效 / 台词 / UI 屏** 一律**在范围内**，此前把它们笼统写成"表现层暂缓"是**口径错误**，
   已在 §7.3 第 13/18 项与 known-deviations 的说明里改正。

#### (2) ★★ 逮到一个「用户可观察」的真缺口：读档后其实**不重新播种**

`rng/policy.ts` 写着 `SINGLE_PLAYER_POLICY.reseedOn = ['gameStart','afterLoad','turnAdvance']`
（对应原版三处 `srand(GetTickCount())`：`0x40170F` 启动 / `0x402FA1` 读档后 / `0x41D06E` 每回合），
但**全仓没有任何宿主接线**（`needsReseed`/`policyFor` 只被测试引用）⇒ 实际行为：

| 场景 | 之前 | 原版 |
|---|---|---|
| 读**原版**存档 | `importOriginalSave` 给固定占位 `rngState = 1` ⇒ **每次读档后掷骰/股价完全一样** | 重新播种 ⇒ 每次都不一样 |
| 读**重制版** JSON 存档 | 沿用档里的 `rngState` ⇒ 同一档两次读→完全一样 | 同上 |
| 每回合 | 不重播种（整局一条流） | 日推进时重新播种 |

按用户口径（"回档后重新扔骰子会有新变化"）这是**必须补**的。已新增
`packages/client/src/rng-host.ts`：

- `reseedAfterLoad(state, topo, seed = clockSeed())` —— 读档后按策略注入 `{type:'reseed'}`；
- `reduceWithHostRng(state, action, topo, seed)` —— 施加 action，**日推进那一刻**（`day/month/year` 变了）
  再注入一次；联机策略下两者都是**空操作**（`MULTIPLAYER_POLICY.reseedOn = ['gameStart']`）；
- `clockSeed()` = `Date.now() & 0x7fffffff`（对应 `GetTickCount()`）。
- 接线点：`main.ts` 的 `applyAction`、电脑那条直路、`loadState`（三处）。
- 测试：`packages/client/src/rng-host.test.ts` 6 例（单机换种子 / 联机不换 / 同一天内的 action 不换 /
  时钟种子取正 31 位）。

⚠️ 注意一处**容易写错的断言**：联机的 `endTurn` **也会**改 `state.rngState`（那是**规则**在抽随机数：
惡人、行情、新闻），所以只能断言"没被注入宿主种子"，不能断言"没变"。
