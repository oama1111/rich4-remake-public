#### 真正的收获：`0x4967e0` 被规格认错了名字

`ai.md`/`ui.md` 把它叫「**持股数组**（player × `0x54`，**12 档股票**）」，
实际是 **公佈欄挂牌表：4 玩家 × 7 槽 × 12 字节 = 336**。**把槽的字节数 12
误当成了股票档数**。机械证据：

```asm
00427edf  imul eax, dword [0x49910c], 0x54   ; 当前玩家 × 0x54（= 7 × 12）
00427ee6  cmp  byte [eax + 0x496828], 0      ; 0x496828 = 0x4967e0 + 0x48 ⇒ **第 7 槽**
```

⇒ 这一条同时解释了 UI 宿主 `0x427c21` 里那句 `([0x48c2ca]−0x64)/7` 与 `%7`：
**`/7` 是玩家下标、`%7` 是槽号**（每人恰好 7 槽）。也解释了为什么
`0x4284be`（= 公佈欄屏，带「賣價／地點／類型／撤件」）会去读它。
已在三处订正：`ai.md` §6.6、`ui.md`（宿主那句注释）、`save-format.md`（块表里
把「企業表 28 × 12」改对）。remake 侧 `save-writer.ts` 的块注释也一并
从「布局未定名」改成「**已定名**」（块本身仍走 carry —— 两个样本整块全 0，
但**布局不再未决**）。

> 这条与第 47 条（乞丐）同一类：**把它写进规格的过程中，逼出的是规格自己的错**，
> 而不是 remake 的错。PRD 越写越准，是这一阶段该有的样子。
