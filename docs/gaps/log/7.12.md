### 7.12 ★ 第 29 条（本轮）：查稅卡的**嫁祸分支 + `tax2` 重算**（簇 F 剩余之二）

原版流程（`@source 0x0044533e`–`0x004453a4`）：

```asm
0044533e  push 0x13 / push ebx / call 0x4413ad   ; has_card(目标, 19)
0044534e  cmp  dword [esp+0x94], 0x7d0            ; ★ 税额 > 2000 才查嫁祸卡
00445359  jle  0x44536f
00445360  call 0x44476a                           ; 嫁祸卡(target, mode 2)（内部消耗 19）
00445368  cmp  eax,-1 / je 0x44536f               ; 放弃 → 保持原目标
0044536d  mov  ebx, eax                           ; ★ 最终目标
00445380  fild dword [最终目标+0x1c]              ; ★ 按**最终目标**的现金
00445386  fmul qword [0x4653d8]                   ; × 0.2
00445391  fistp dword [esp+0x94]                  ; ★ tax2 = trunc(0.2 × 最终目标现金)
004453a4  call 0x41d2c6                           ; transfer(最终目标, 施卡者, tax2, 0)
```

实现：`applyTaxCard` 新增 `scapegoatPicker` 参数（与第 12 条对 `sleepwalk` 同型），
命中门槛 `SEAPGOAT_TAX_THRESHOLD = 0x7d0`；换目标后**按最终目标重算 `tax2`**；
`registry.ts` 透传 picker。

新增 4 例测试：换目标后**金额重算**（不是沿用原值）、**税额 ≤ 2000 时不查**嫁祸卡、
**放弃转嫁时嫁祸卡照样被消耗**、以及**敌意仍按最初税额算**（`tax/100`，在嫁祸之前）。

> ★ **一条测试写法上的改进值得记**：我最初把期望金额写死（`expect(r.tax).toBe(10_000)`），
> 结果失败 —— 因为我假设的玩家现金与 `makePlayer` 的默认值不一致。
> 改成**从实际玩家值推导**（`const taxNew = Math.trunc(ps[3].cash * 0.2)`）之后，
> 测的就成了「**重算**」这个行为本身，而不是某个具体数字。
> **断言应该钉住行为，而不是钉住我当时算出来的那个数。**
